# nativetools runtime issues found by the eval

These were found while building and verifying the eval sets and in the Sonnet dev runs. The crate is not patched here. A session that cannot pass until an issue is fixed carries `blocked: runtime_issues.md#N`, and `score.py` reports those sessions separately. The numbering must stay stable because the sets refer to it.

**Status after the fix rounds of 2026-09-27:** #1–9, 11, 12 and 14–23 are fixed. #10 and #13 are open. The ref runs pass on both sets (100%), and no session is blocked. The eval absorbed four of the fixes:

- locker notes are sealed in diffs, so gold expects `"sealed"` (test-B-065, test-B-069);
- settle diffs carry a person `balance` → 0, which `score.py` accepts for the person gold settles with;
- world JSON `currency` is set (USD) in every world;
- seed reports `dropped` values, so card, identity and wifi notes and AWS username/url are gone from the worlds.

Repros use the seeded eval vaults (`python3 seed_worlds.py`) and a session such as `nativetools session $EVAL_VAULTS/A/vault --today 2026-10-14T08:40 --me "Priya Raman"`, fed one JSON op per line. A `ref` repro is `python3 run.py --set sets/<set>.jsonl --model ref --only <id>`.

1. [fixed] **Locker `edit` wipes the fields it was not given.** Editing one field of a login clears `username`/`url`/`notes`, and editing `notes` on a wifi or note item changes nothing. Repro: `ref` on dev-A-056 (edit Netflix `notes` → diff shows `url -> None`) and test-B-069. Blocks dev-A-056, test-B-069.
2. [fixed] **Compaction cuts off rows the conversation still refers to.** Fixed per the owner ruling: the previous turn stays whole and older turns compact (checked: a turn-1 result is still addressable in turn 2 and compacted in turn 3; created rows stay addressable). At the start of every turn the previous turn's result rows become unaddressable (`#24 is not shown any more (compacted)`), including rows the model created, so "put X on it" / "open the grateful one" must re-find. Repro: `{"op":"user"}`, `act create kind: list name: Honeymoon`, next `user`, then `act create ... list: #24` → error. Sonnet misses: dev-D-013 t2, part of dev-A-038.
3. [fixed] **`search` misses trashed rows, nicknames and roles, and its hint says to decline.** `search {"text":"bike tire"}` on A (the task "Fix bike tire" is in the trash) → `0 rows ... decline not_found if nothing else fits`. Same for `search "Gabi"` / `"Mamá"` on D (nicknames of Gabriela Reyes / Carmen Reyes) and roles ("Lucía's teacher", "yoga"). Sonnet misses: dev-A-004, A-023, A-025, A-070, D-005, D-006, D-029 (and D-033, D-037 partly).
4. [fixed] **World JSON cannot set the vault default currency.** It is always USD; only group currency is settable. World C (multi-currency) carries non-USD only in groups because of this.
5. [fixed] **`seed` leaves an unchecked-pointed WAL.** World D (~3.8k rows) left ~770 MB of WAL, and `copy` copies it. `seed_worlds.py` runs a checkpoint and VACUUM after seeding.
6. [fixed] **Locker `create` with `type: note` drops `notes`.** Repro: `act create` with `kind: locker item`, `name: Gym locker combo`, `type: note`, `notes: 12-34-56` → the created row has no notes. Repro: `ref` on test-B-065 (blocked).
7. [fixed] **`;` inside an args value is read as a line separator.** `act edit ... args: "description: washer; o-ring"` → `could not read the args line "o-ring"`. The ref calls use commas.
8. [fixed] **`answer` with a `no_link` recovery ends the turn.** An `answer` whose selector hits "X are not linked to Y" ends the turn with no answer, so the model can't retry.
9. [fixed] **`call_text` with two `<tool_call>` blocks runs the last one.** The driver cuts the model text at the first `</tool_call>` to get one-call-per-step semantics.
10. [open] **No CLI op renders the transcript as the model sees it.** The driver rebuilds it from `text`/`compacted` (`lib.Transcript`), which can drift from the runtime's own rendering.
11. [fixed] **Restore is refused for rows trashed more than ~30 days ago, but they still list as trashed with no hint.** A `oldgym` (trashed 2026-09-20) shows in `trashed=true` reads and `act restore` is refused. Gold accepts ask/decline there.
12. [fixed] **`settle_up` returns an empty diff.** The settlement shows only in the text (`settled ... 98.00 USD`). `score.py` matches settle gold on that text.
13. [open] **`undo` can't revert `cancel` or `log`.** `act cancel` on "1:1 with Dana", then in the next turn `act undo` → `not undone: ... the vault has no command that un-cancels an event`.
14. [fixed] **The task kind card doesn't say which end of `priority` 0..9 is high.** "make it top priority" gets 9 from Sonnet, and gold uses 1. Sonnet miss: dev-D-036.
15. [fixed] **Strict selector parsing.** `act` with `kind` plus `rows` is rejected (`act takes rows or a selector, not both`) even when they agree, and `ask options` accepts only `#n`, not labels. These cost steps against the cap of 6.
16. [fixed] **A failed `act create` leaves a phantom row.** `act create kind: task name: book the flights list: #24` (with #24 compacted) returns an error, but the task is inserted anyway. It is invisible to `find`, and it then turns up as an extra `created` row (`n: null`) in the next successful act's diff. Repro: issue 2's steps, then `act create kind: task name: pack bags`. Seen in dev-A-038 t3.
17. [fixed] **The "not linked" hint ignores `within`.** `find kind=photo within=@2 linked_to=<event>` → `photos are not linked to events. Photos whose name mentions "LBI beach week": #57…`, which lists matches from the whole vault instead of from @2. Sonnet answered with those rows (dev-D-016 t2).
18. [fixed] **Open-ended date spans are rejected.** `when={"to":{"date":…}}` gives `a span needs from`, and `when={"from":…}` gives `a span needs to`. "Overdue" and "from now on" need a made-up bound (`2000-01-01`/`2030-12-31`), and Sonnet spent steps on it (dev-D-037 capped).
19. [fixed] **An empty result can only end in `decline not_found`.** Ruling (SPEC §4.2/§8.5): an empty result from conditions alone is a valid answer and ends the turn; recovery and `decline not_found` are only for a name that resolves to nothing or only to trashed rows, or a missing link. Since the #8 fix, `answer` on a selector that matches nothing returns the recovery text `0 tasks match (when: Fri 2026-10-23) ...` and does not end the turn, so "what's due next friday?" can't be answered "nothing" and has to end in `decline not_found` (§8.5). Repro on A: `{"op":"user"}`, then `answer kind=task when={"unit":"week","rel":1,"weekday":5}` gives `ends_turn: false`; `answer rows=@1` gives `@1 was never issued`. Gold follows the ruling: condition-only empty turns expect `rows []` alone. If "nothing matches" should be an answer, `answer` on an empty result needs to end the turn with an empty answer again. Sonnet shows the cost. It answers "nothing" and calls the same `answer` again, and gets `repeated call` → loop (dev-A-004 t4, dev-A-007 t2, dev-A-038 t4 in the 2026-09-27 dev run). A model that follows §8.5 would decline, but the loop is the natural reading of "0 tasks match" with no next step named. At the least, the recovery text could say "nothing matches; decline not_found to end" as the only-trashed hint does.
20. [fixed] **Kind cards don't say that `name` is editable.** A card lists a kind's fields, such as `list: area · links: tasks · verbs: create edit`, but never `name`, except "name only" for albums, notebooks and folders. So "rename Errands to Errands & pickups" gets written to the one text field the card shows: Sonnet ran `act edit rows=#19 args="area: Errands & pickups"` (dev-A-038 t2, in both 2026-09-27 dev runs). Suggested fix: show `name` on every card that has `edit`.
21. [fixed] **`act create` with a `kind` parameter fails with an error that doesn't name the parameter.** `act verb=create kind=note args="kind: note\nbody: …"` gives `create takes args (kind, name, fields), not rows or a selector.` Sonnet reads that as a complaint about `args` and repeats the call until `repeated call` or the step cap (dev-A-076 t1, and dev-A-103 t1 in the first run). Suggested fix: accept a `kind` parameter that equals the args kind, or name it: `drop the kind parameter; kind goes in args`.
22. [fixed] **The #19 fix still treats two condition-only empty results as dead ends.** Under the ruling, an empty result is a valid answer when every name resolved, but `answer` still returns a `recovery: empty` and keeps the turn open in two cases: (a) a selector with `linked_to=#n` (a resolved row, with a link the kinds do have) plus `when`; (b) a `name` that resolves to live rows, narrowed to nothing by `when`. The same query with `where` in place of `linked_to` ends with `answer: {rows: []}`. Repro on B (today 2026-11-28T10:15, me "Kwame Asante"): `answer kind=event linked_to=#21 when={"from":{"unit":"day","rel":0},"to":{"date":"2030-12-31"}}` (#21 = Kojo Mensah from the pre-grounding) gives `0 events match … ends_turn: false`, and `answer kind=event name="Ama piano lesson" when={"unit":"week","rel":1,"weekday":2}` gives `0 events called "Ama piano lesson" with those constraints … ends_turn: false`. Yet `answer kind=event name="Ama piano lesson"` alone returns 20 live rows, so the name resolved. This blocks test-B-086 t1 and test-B-090 t1.
23. [fixed] **Pre-grounding matches the request's verb as a name.** "star it" pre-grounds `#26 photo "Starlight Theatre"` (A, turn after `restore` of "Old gym login"). The only candidate offered is a false one, and Sonnet starred it (dev-A-057 t4) even though the restored row was still on screen. Suggested fix: leave verb words (star, pin, delete, restore, …) out of pre-grounding matching.
24. [fixed] **Renaming a list clears its area.** `schedule.save_project` is an upsert that nulls every column it isn't given, and a rename sent only `name`, so `act edit rows=<list> args="name: Flat 302 chores"` returned `area "home" → none` (authored T02-025). An edit now sends the current name and area along with the changed one.
25. [fixed] **`where` drops a trailing unit word.** `effort > 1 hour` was read as `effort > 1` (minutes) and answered, because the word after a number was taken as a currency code and then ignored on a number field (found while authoring T02-088). The word after a number is now a money field's three-letter currency code or the number field's own unit spelled out (`60 minutes`, `14 days`); anything else is refused with the unit named.
26. [fixed] **Undoing a photo delete leaves it out of its albums.** The vault takes a trashed photo out of its albums and `media.restore_asset` doesn't put it back, so "delete the kitchen pic", then "undo" restored the photo but not its album link (authored T01-017). The delete's inverse now re-adds each album after the restore. A `restore` verb in a later session still can't know the old albums; the album link is gone from the vault at that point.

## 27. A multi-row reveal recorded only the last secret [fixed]

`act reveal rows="$gmail, $lichess"` showed both secrets in the reply, but the effect's `revealed` kept only the last, so the scorer failed "secret of gmail not revealed". The effect now carries every revealed line. Test: `issue_27_a_multi_row_reveal_records_every_secret`.

## 28. An edit or create took a number in the wrong unit [fixed]

`act edit … effort: 1.5 hours` was accepted and stored 2 min (the leading number, rounded). Number arguments now go through `whr::number_arg`: a trailing word must be the field's own unit (`90 minutes`, `14 days`), anything else is refused with the same text `where` uses. Test: `issue_28_an_edit_refuses_a_number_in_the_wrong_unit`.

## 29. A multi-row delete is not all-or-nothing [open]

`act delete rows="$a, $b"` deleted the first row, then refused the second and reported an error; the first delete stayed applied. Found by T11-087. Left as is for now: authors avoid mixed multi-row deletes.

## 30. A notebook cannot take an album's name [open]

`act create kind=notebook name: Family` is refused with "You already have a notebook with that name" when only an album is called Family. Found by T11-072.

## 31. A trashed event still blocks its slot [open]

`crates/vault/src/commands/schedule.rs` `no_busy_conflict` counts events with `deleted_at` set, so creating an event in a slot that a trashed event occupied is refused with "This time conflicts with another event on your calendar." The other event predicates in the same file already add `deleted_at IS NULL`. Vault-side bug, not nativetools; found by T17-034. Authors treat a trashed event's slot as taken.
