# AGENTS.md

Centraid is a personal, local-first superapp: one shell wrapping many first-party apps over a sovereign vault. **The phone is the vault**: the Rust core on the phone is the vault's only writer, and any machine the member controls runs `centraid-gateway` as a blind store for its sealed backup.

## Checks

- `cargo xtask gate --profile <local|pr|nightly|release|mobile-jvm>` is the gate. Run the profile that matches the change before calling it done.
- On a fresh clone run `git config core.hooksPath .githooks` (a Claude session does it at start). Commit subjects read `type(scope): subject (#N)`.
- Fix the code, not the check. Do not loosen a lint, test, budget or allowlist to get green. The budgets that remain are counts and sizes (the copy ratchet, the staging area's byte budget, `library-size.json`, the query-plan allowlist). Wall-clock budgets were removed by the owner's ruling of 2026-11-04 (they flaked on loaded machines and blocked unrelated changes), so no gate step or test asserts on seconds. Keep it that way: bound work by construction and assert on counts (statements, calls, rows), never durations.

## Skills

Guidance lives in [`.claude/skills/`](.claude/skills), eight skills, each a short router. Start from the question:

- `product`: what do we owe the member?
- `design`: what does it look like and say?
- `change`: how does this kind of change travel through the layers?
- `stack`: how do I write this language here?
- `land`: how do I prove it and ship it?
- `assistant`: how does the on-device assistant work, and how do I change it?
- `backup`: how do backup and the gateway work, and how do I change them?
- `orchestrate`: how is multi-session work run? Only for a session that directs other sessions.

## Conventions

- **Docs describe current state.** When a change makes a doc wrong, fix the doc in the same change.
- **Comments only when absolutely necessary.** Write none by default. One stays only for a why the code cannot show (an invariant, a security reason, a workaround, a ruling a reader would otherwise undo). The rule is in the `stack` skill.
- **Mark what is not built.** A path, command or behaviour that does not exist yet is written with "(target)", so a doc written ahead of its code stays honest. Remove the mark in the change that builds it.
- **Delete code a decision makes irrelevant**, in the same change that replaces it. No dead branch, flag or test waits for a later cleanup.
- **Product calls go to the owner.** When a choice is about what the product should be and the `product` skill does not settle it, ask rather than guess.
- **Mockups first.** Every visual or UX change starts in `design/mockups/`: the same PR updates the committed light boards (dark ones, the native files and the sites' sheet are all generated by `cargo xtask design`, never hand-edited) and `design/tokens.toml` when a value changes. Behavioural rules are in the `design` skill's `behaviour.md`.
- **Vocabulary**: a machine running `centraid-gateway` is a _gateway_, not a server or host.
