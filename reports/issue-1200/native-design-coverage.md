# Native design coverage — #1200

This audits the **entire native app**, not only the two directly restyled apps. The accepted Home/People/detail/editor work establishes the paper, typography, glyph, status and room system. Existing rich content layouts remain useful. Shared card-border or text changes alone are not evidence that all nine apps have been redesigned or verified.

Root accepted the second native pattern after reviewing all nine root representatives plus Notes editor, Chat and Backup. Canonical glyph/Notes visibility corrections are applied in light source. Native implementation and matching-build verification are separate work and are not claimed by this audit.

## Coverage decision

Use one app-identity top row across all nine apps: a decorative solid app glyph beside the existing ink title, the existing scope below, and the existing native actions. Reuse the app ID and catalogue glyph already passed to `AppPlace`. A custom Calendar month control carries the mark **in the same row**, without adding a title band. Identity is visible by silhouette and words, not just colour. At existing large-text breakpoints the decorative mark may yield space; the complete title and controls win.

The accepted mark is 32 with the existing icon-chip radius ratio 0.26 (8.32). Reuse the existing `KitTile` default of 32 and canonical `design/icons.toml` app glyph; root confirmed that no new token is needed. Use `AppAccent.fill` under white, not the bright `.tile` variant. Home’s approved invitation block stays on its separate generated size 36 role. Type, palette and card radius 16 stay unchanged.

## Shell and custom exceptions

- **Home:** already accepted open invitations, solid glyphs, actual vault initial/hue/name and separate44 controls. The company mark never replaces active-vault identity. Keep Rust-packed rows, sizes, routes and accessibility summaries.
- **Chat:** the old centered small conversation title does not express the new hierarchy. `Chat.dc.html` now gives the intact assistant mark a leading seat, existing conversation title section20 and vault subtitle meta13. Keep Chats/New-chat visibility, context menu, focus/keyboard behavior, saved-thread state and shell band unchanged. Answer cards use the corresponding app glyph instead of an anonymous colour rail; People cards retain their existing person initials. Source exceptions: iOS `Chat/ChatView.swift` `ChatHeader` and record-card view; Android `screens/chat/ChatScreen.kt` corresponding components. No model, tool, evaluation or assistant feature work.
- **Backup:** source already has a left-aligned state mark/sentence/action and typed conditional sections; it largely fits the accepted system. The old centered board was stale. `Backup.dc.html` now matches that real hierarchy and adds a shell-identity heading. Keep real state colour, all recovery/transfer/pairing rows and existing model conditions. Source exceptions: iOS `BackupViews.swift` root heading; Android `screens/backup/BackupScreens.kt`. **Only the new heading mark is approved for implementation from this board.** Its lower legacy prototype rows/toggles/copy are not authoritative and must not be ported over current `BackupHomeState`. Do not recompute a condition from acknowledgements in the view.
- **Notes editor:** keep its full-screen rich-text canvas and native close/More. Its bar shows the existing noun (`chrome.title`, Note), not Saved. One foot status host above the tool rail chooses the existing refusal/action sentence when present and ordinary autosave feedback otherwise. No second Saved sentence elsewhere. iOS currently has a private adapter with principal-toolbar status and needs direct translation; Android already uses `EditorRoom`'s status interface, so verify the current adapter rather than introducing another host.
- **Settings:** actual source is a pushed page using `PushedPage`, not an app root. Keep native inline title/back and existing grouped choices/sections. Shared editor/card/row/type changes reach it; do not add an app header glyph to a pushed page merely to match stale mockups.
