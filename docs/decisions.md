# Current decisions

This file is the adjudication layer over the repository's append-only evidence: the decisions in force today, grouped by product area, and the deliberate non-goals that still guard the product. A row says what is decided, why, and the issue that settles it. It does not narrate how the answer was reached: history lives in the receipts, the CHANGELOG, the issues and git, and this file is not evidence. Update a row when the answer changes and link the issue that settles the change; delete a row when the thing it ruled on is gone.

Every bold id in the first column is a citable anchor. A row that merged an earlier ruling and its refinements lists every id it stands for, so a citation of any of them still resolves to the one row that states the end state.

## Product positioning

<a id="superseded-decision-pointers"></a>

| Id | Decision |
| --- | --- |
| **X-799-superapp** | Centraid is a personal, local-first superapp: one shell wrapping many first-party apps whose content characters differ widely. The shell, the vault and the apps ship together as one product, and the owner installs Centraid, not apps into Centraid. Retired positioning vocabulary is in [glossary.md](glossary.md); the binding design statement is [DESIGN.md](../DESIGN.md). _Why:_ one product with one trust boundary, not a catalogue. [#799](https://github.com/srikanth235/centraid/issues/799) |
| **X-799-first-party-ui** | Every app UI is first-party code in the release: a native SwiftUI or Compose screen on the phone. The gateway serves data and sealed objects, never UI bytes. _Why:_ there is no served-app plane to secure or version. [#799](https://github.com/srikanth235/centraid/issues/799), [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **R-1020-1** | The shared core is Rust and the mobile shell is Kotlin Multiplatform with native views; there is no desktop shell. Compatibility with earlier-generation artifacts (seat files, pair tickets, npm gateway packages, over-the-air JS updates) is not a constraint, and neither is migration cost; compatibility between v1 releases is (R-1020-4). _Why:_ the choice is structural, not measured: data code stops running on a JS engine at all, and the numbers that hold the work honest are the absolute targets in `tests/journeys.json`, not a comparison against the old stack. [#1020](https://github.com/srikanth235/centraid/issues/1020) |

## Deliberate non-goals

<a id="grants-v2--one-authority-plane-883"></a> <a id="sharing-v1--the-grant-plane-825"></a>

Prohibitions that still guard the product. Each is a decision not to build something, and each stays until an owner ruling removes it.

| Id | Decision |
| --- | --- |
| **NG-799-no-app-builder** | Centraid is not an app builder: there is no authoring surface, no scaffolder pointed at a blank app and no build-and-publish loop. _Why:_ the superapp is one product the owner installs whole. [#799](https://github.com/srikanth235/centraid/issues/799) |
| **NG-799-no-platform** | Centraid is not a platform: there is no third-party, user-built or generated app plane, no code store and no install-from-elsewhere path. The catalogue is the first-party apps this repo ships. _Why:_ every app is reviewed code in the release. [#799](https://github.com/srikanth235/centraid/issues/799) |
| **NG-1029-no-hosted-tier** | v0 has no hosted tier: no hosted adapter, mailbox, account with a signed vault listing or purchases, plan lapse, or S3-compatible byte store. These were deleted, not parked. _Why:_ v0 is a phone backing up to a machine the member controls. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **NG-1029-no-sharing**, **G-view**, **G-revoke** | v0 has no sharing between members or vaults: no grants, audiences, commons, subscriptions or peer transport, and no second deployment of the gateway protocol. The vault schema band for it is deferred, and a photograph leaves only as a copy handed to the operating system. _Why:_ the phone is the sole vault and the gateway a blind store. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **M-nolink** | There are no public or anonymous share links: no unauthenticated read route, no bearer-token document view and no origin willing to project rows to a party the vault cannot name. _Why:_ a URL anyone could open would be a second delivery plane whose audience is whoever has the string. [#880](https://github.com/srikanth235/centraid/issues/880) |
| **NG-1029-no-recognition-plane** | v0 has no recognition plane: no worker, no `enrich.*` commands, no enrichment policy cascade, engine profiles or egress consent rows. The derivation tables have no production writer. _Why:_ the worker and all nine `enrich.*` commands were deleted and the command registry is asserted to hold none. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **NG-816-no-basemap** | No map SDK is linked in either shell and no basemap tile is fetched; a place is drawn only as a zero-egress plot of the member's own coordinates. _Why:_ a tile request's URL is a bounding box and tells a tile server roughly where a member photographs. [#816](https://github.com/srikanth235/centraid/issues/816) |
| **NG-873-locker-no-breach-check** | Locker does no breach checking, and `compromised` stays a flag with no automatic producer. _Why:_ it would mean network egress from the app that holds the most sensitive data. [#873](https://github.com/srikanth235/centraid/issues/873) |
| **NG-873-locker-no-recently-used** | Locker has no recently-used shelf. _Why:_ it would publish reading habits on the one screen where reading is the sensitive act. [#873](https://github.com/srikanth235/centraid/issues/873) |
| **NG-853-second-design-language** | No marketing, internal or engineering-facing surface carries a design language separate from the product's: no palette of its own, no second face, no second type scale. _Why:_ a second design language makes the public face look like a different product. [#853](https://github.com/srikanth235/centraid/issues/853) |
| **NG-883-no-authority-table** | No table of standing grants holds the member's answers about who may do what: nothing grants anything, an app is never a principal, and a policy that configures the member's own machinery is not an authority. _Why:_ the one authority plane was retired with sharing; authority is the vault's command gate. [#883](https://github.com/srikanth235/centraid/issues/883) [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **NG-890-no-pr-devices** | No per-pull-request device farm, no iOS minutes on the merge gate, no device matrix beyond the pinned pair, no coverage floors on mobile screens, and no backfilling deliberate `n/a` cells. Real-device evidence (battery, memory, cold start) is a release-cadence spend decision. _Why:_ a device minute is far dearer than the rendered-tier minute that carries the same claim. [#890](https://github.com/srikanth235/centraid/issues/890) [#915](https://github.com/srikanth235/centraid/issues/915) |
| **NG-1005-ledger-validator** | The law never re-adjudicates the ledger validator: `gates` reports that a knob moved and which way, and whether the move is allowed is `bun run lint:ledgers`'s answer, read from the one direction table both share. _Why:_ two answers to the same question is how the quieter one goes stale. [#1005](https://github.com/srikanth235/centraid/issues/1005) |
| **NG-1005-host-config** | The law never claims the host is configured: it observes, and branch protection and code-owner review are the host's, set by the owner outside the repository. _Why:_ a rule that asserted its own enforcement would be the failure `COSTS.md` was. [#1005](https://github.com/srikanth235/centraid/issues/1005) |
| **R-1029-1**, **NG-1029-no-second-client**, **D-1020-F15**, **R-1020-26** | v0 has no client but the phone: no desktop shell, no browser extension, no paired client, no accept loop, no remote query surface and no second copy of the read plane. A later desktop would be a read-only replica dialled by the vault's key, never reaching `invoke` or `reveal` and never fetching a blob by bare hash. _Why:_ the deferral buys the whole shape of v0 and lets `no-listening-socket` be a structural rule instead of a convention. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **NG-1020-v0-compat** | No code reads, migrates or stays compatible with a pre-v1 artifact (seat files, pair tickets, npm gateway packages, over-the-air JS updates). _Why:_ the earlier generation was a specification, not a migration source. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **NG-1020-cmp-ios** | Compose Multiplatform is not used on iOS; SwiftUI renders iOS and Compose renders Android. _Why:_ CMP on iOS trades a known rendering path for a second runtime to debug on the surface that most needs to be boring. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **NG-1020-s3-blob-store**, **R-1020-19** | The blob store is the local filesystem only; there is no S3-compatible backend. _Why:_ a second storage backend would bring its own failure modes. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **NG-1020-places-app** | Places is never a separate app crate; it stays a facet of Photos. _Why:_ the phrase logic is the load-bearing half and it belongs to Photos. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1025-S7-41** | There is no push wake: no gateway holds a push-service key, and no push proxy exists in v1. `WakeReason` keeps a push slot only because the enum is the payload. A phone in the background backs up in the next window the platform grants. _Why:_ a gateway holding a push credential puts a third party's delivery path inside the machine a member runs themselves, and even a wake-only push tells that party a device has something waiting; correctness comes from the durable ledger and cursor, not timing, so a phone that was away loses nothing. A stateless push proxy is deferred, not refused, and needs its own design for who runs it and what it may learn. [#1025](https://github.com/srikanth235/centraid/issues/1025) [#1080](https://github.com/srikanth235/centraid/issues/1080) |
| **R-1047-P1** | Sharing-era features are not built on the phone: People's vault links, rings, Share and Revoke; Docs' Shared shelf; and no copy says "gateway", "queued for the vault" or "owner". _Why:_ the phone is the vault and the sole writer, so there is no peer to share with or queue for. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **R-ONBOARD-1**, **R-ONBOARD-12**, **R-ONBOARD-2**, **R-ONBOARD-3**, **R-SAMPLE-1** | There is no persistent sample data and no "See an example" preview: a first vault is the member's alone (no second "Sample" vault, no `sample` mark, no removal flow, no example core, no switcher on day one). Onboarding's jobs are to get the member's own data in fast, teach the gestures that are not obvious, and leave nothing to clean up. _Why:_ fake rows delay the member's own, need cleaning up, and in a privacy product contaminate exactly the planes that must be the member's (search, the chat's reads and the backup); a preview is a feature a member visits once and has to be told how to leave, and a look at someone else's full app does not get them closer to their own. Every empty app is a tile that says what to do, and making a vault brings in the photos, contacts, calendar and reminders the phone holds. [#1093](https://github.com/srikanth235/centraid/issues/1093) |
| **NG-1099-no-tally**, **R-1099-19**, **R-1099-33**, **R-1099-34**, **R-1099-35**, **R-1099-21**, **R-1099-37** | v0 has no shared-expense, debt or group-balance product: no Tally app, no People debts or obligations line, no assistant Debt or Group kind and no balance, settle or tally verbs, and no circle search index (every container opens by its own `id`). Money is the only finance app, and its tables hold a member's own imported statements. _Why:_ the whole product was deleted and nothing produces or consumes it. [#1099](https://github.com/srikanth235/centraid/issues/1099) |
| **NG-1047-no-faces** | Photos draws no face surface: no People or face-review screen, no "who is in it" row, no People card in Collections, no person leg in search, and no face tables or commands, until an on-device detection proposal is accepted. _Why:_ the surfaces read tables nothing writes since recognition was deleted, so every one drew an empty promise. [#1029](https://github.com/srikanth235/centraid/issues/1029) |

## The vault model

<a id="replication-offline-and-sharing-1014"></a> <a id="supersessions-closed-by-1029"></a> <a id="the-phone-is-followed-one-way-1127"></a> <a id="the-phone-is-the-vault--v0-1029-ruled-2026-09-21"></a> <a id="the-vault-model-from-first-principles-1135"></a>

The schema, the commands, the journal, retention and the rules every writer shares.

| Id | Decision |
| --- | --- |
| **X-630-migrations** | 1.0 begins when every schema change ships an ordered migration that preserves a real vault. Before 1.0 a schema change may require recreating a vault, but that is never permission to erase one that holds real data, and schema changes land together with their snapshot and restore evidence. _Why:_ a member's vault outlives any build. [#630](https://github.com/srikanth235/centraid/issues/630), [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **AP-principals**, **AP-apps-declare**, **AP-owner-direct**, **AP-one-id-space** | A first-party app is not a principal: it is the owner's own screen running the owner's own code, holds no credential, and cannot be granted or revoked. It declares its reach at build time (the entities and columns its screens read and the commands it invokes), the execution clamp treats that reach as a ceiling that narrows whoever holds it, owner included, and a tripwire fails the build when an app touches an entity it did not declare. An owner device's read of the owner's own vault is owner-direct: it consults no grant, carries `authority_id: None`, and is not receipted. `app` stays a reserved, unwritten principal kind. _Why:_ revoking the owner's own screen is not a thing the owner wants to do, and minimisation is kept at build time with a reviewable diff at zero runtime cost. [#928](https://github.com/srikanth235/centraid/issues/928) |
| **R6** | Every mutable table carries `row_version`, bumped by its `touch_updated_at` trigger. _Why:_ a write names the version it expects and the check compares plain equality against the column. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R8** | Reads paginate by keyset (a stable `(sort_key, pk)` cursor), never `OFFSET`, and the read runtime owns `LIMIT`. The performance gate is measured work at year-3 scale in the journey ledger, not a query-plan snapshot. _Why:_ an outer `LIMIT` does not bound an aggregate or a sort, and plan text changes between SQLite versions. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R12** | A device may hold several vaults, one directory each, and a vault is a world: Agenda's birthdays come from the People in the same vault. _Why:_ a vault switcher is the honest shape, not vault-free views. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R20**, **OQ-9**, **OQ-11**, **OQ-12** | Identity is never taken from a value. A revision is an occurrence, not a content id: two documents with identical bytes have independent histories, restoring is a new revision, and restoring another object's revision is refused; authored edit history is unbounded, with a size-based prune only the owner triggers. Bytes are not an interpretation: media type and charset belong to a representation row, the authored title lives on the wrapper, and a generated caption is a derived row the owner may promote to the title with one action. A provider-local id is scoped to its source, and a cross-source match is a proposed row the owner accepts, never inferred from equal reference strings. A concept's label is not its identity. _Why:_ an identity inferred from a value merges things that only look alike. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R21** | Every writer (domain commands, imports, the assistant) passes through the same domain operations. Simple invariants are CHECKs and partial indexes; aggregate ones are the operations: task completion is one operation (`complete` / `reopen`, never a state-dependent toggle) with a stable series identity, the recurrence occurrence key is one typed value every reader consumes, and temporal meaning (instant, local date, floating local datetime, yearless month-day) is validated at the boundary. An unsupported imported recurrence rule is kept with an explicit support state, never as an executable rule. _Why:_ the same invalid mutation through any writer must be refused by each or transformed identically by each. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R22** | Money keeps its currency: balances are `(party, currency) → amount_minor`, a base-currency overview is an explicit valuation carrying rate, effective time and source with an unavailable state when a rate is absent, and a bare amount is unrenderable as a balance. Deletion is declared by relationship role (owned child, attribution, participation, durable record) beside each reference and tested per role. A machine assertion links to the derivation and input revision that produced it, and a storage ruling is enforced by a reader test that writes through a real command and reads through a real app query. _Why:_ summing across currencies or deleting by guess are silent wrong answers. [#996](https://github.com/srikanth235/centraid/issues/996) |
| **R-1029-5**, **R-1029-4**, **Q-1029-1**, **Q-1029-3**, **T-1029-2** | The schema a new vault founds is one hand-written baseline, `contracts/migrations/001_baseline.sql`, edited in place until the first release that must migrate; from then on the migration ladder is appended to and never edited. `contracts/schema/vault-ddl.sql` is regenerated from a founded vault by `export-ladder-ddl` and diff-checked. _Why:_ a rung edit moves the shipped dictionary and every fixture, and nothing has shipped that needs the longer path. [#1029](https://github.com/srikanth235/centraid/issues/1029), [#1135](https://github.com/srikanth235/centraid/issues/1135) |
| **R-COLL-1**, **R-COLL-2**, **R-COLL-3**, **R-COLL-4** | A container states which kind it is (notebook or album among its kinds), the kind is required with no default and is fixed by the entity key, every writer states it and every reader filters on it. Each app's commands refuse the other's id with a sentence, delete scopes by kind, and sibling order and name uniqueness are per kind. The schema does not constrain which entry types a kind may hold; the commands are the only writers and each refuses the other kind. _Why:_ Notes listed every album as a notebook and Photos every notebook as an album, and a delete on the wrong id removed placements with no undo; a trigger on entries is added when a second entry type is proposed. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **D-1020-D1-2**, **D-1020-D1-13**, **D-1020-R7** | A vault file carries `application_id = 0x43454E31` (`CEN1`) and a `user_version` counting the ladder's own migrations. Migrations are forward-only and run by the core on `open`: a file below the binary is migrated in order with a pre-migration snapshot taken first, a file above it is `DowngradeRefused`, and a migration that fails mid-way leaves the file unmigrated rather than half-migrated (the restore drill runs the real binary against a deliberately failing rung). The baseline migration and its `contracts/` fixture are one file reached by `include_str!`. _Why:_ two copies of one DDL are two answers to one question, and an upgrade that guesses down can lose data. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-D1-5** | The commit pair is the only writable connection, a guard whose ordering cannot be forgotten. `Vault::read` sets `PRAGMA query_only` and `Vault::connection` is `pub(crate)`. _Why:_ it turns "no caller writes through a read" into "SQLite refuses it". [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-D1-3** | Change capture uses one session per replicated table and leaves `table_filter` unused; the bundled SQLite is compiled with the session extension and the preupdate hook. _Why:_ a filter that is silently ignored is a private table's rows reaching every reader, invisible until someone reads a log, while a table never attached produces no changes at all, which a test sees. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-D1-4**, **D-1020-D1-18** | A log row's image keeps the JSON spelling the oracle fixtures were cut in, with number spelling borrowed from `centraid_ontology::jsvalue::js_number_to_string` (a real `1.0` is JSON `1`), and `serde_json`'s `float_roundtrip` feature is on. _Why:_ a differently spelled image makes every row a finding for a difference that is not one, and the default float parser lands one ULP away, so a drifting REAL becomes a quietly wrong latitude or exchange rate. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-D1-8**, **D-1020-D1-17** | `DiskFull` is a typed error classified in the `From` conversions for `rusqlite::Error` and `std::io::Error` (SQLite's full code and `ErrorKind::StorageFull`), never in a helper each call site calls. The snapshot build's disk-full test redirects the build's gzip file write to `/dev/full` through `Fault::GzipTo`, which is privilege-free. _Why:_ a classification a call site can forget is a classification the product renders wrong, and a build cannot exhaust SQLite pages. [#1047](https://github.com/srikanth235/centraid/issues/1047) |
| **D-1020-D1-9**, **D-1020-D1-10** | The paged door's vault-side hook is `Vault::page_raw`, `page::and_row_filters` and `page::apply_field_mask`: the app kit builds the statement text and binds and passes the decision it got from `evaluate_access`; the vault never sees a `PageQuery` and the kit never sees a `Connection`. Device enrolment lives in `crates/vault::devices` (`enrol`, `revoke`, `is_device_enrolled`, `live_devices`). _Why:_ the access decision narrows the answer inside the vault so no caller can forget it. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **R-1020-8** | The vault file is plain SQLite with no SQLCipher. At-rest encryption is the platform's (iOS Data Protection, Android file-based encryption, disk encryption on a gateway machine) plus sealed columns for secrets. _Why:_ SQLCipher costs vendored OpenSSL across every target and a database key held in a running process is no defence against whoever owns the memory. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **R-1020-33** | Civil time is the vault's zone, never the host's. A gateway machine may run UTC, and every scheduled automation still fires at the member's local time. _Why:_ the host's zone is accidentally wrong on rented hardware, and a daily brief that arrives at 07:00 UTC is a defect with no error message. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-X3-2** | Ids are minted as UUIDv7 from the injected clock with a per-open random suffix; no id sequence is persisted. _Why:_ a persisted counter makes every mint a write that must be transactional with the commit that used it, and gives the sequence a schema; injection keeps fixtures and simulation deterministic. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-X3-3** | The owner-facing sentence for a refusal is built from the error code alone (`sentence_for_code` is the only writer); `detail` keeps the predicate for the audit trail, and a sweep asserts no code's sentence is SQL-shaped. _Why:_ a per-layer `sentence` field is one careless `format!` from a member reading SQL. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-X3-4** | The handshake's identity is checked at `open`, against a digest the caller states (`expectedIdentity`); the core refuses a mismatch before a handle exists. _Why:_ checking after `open` leaves a window in which a shell holds a working handle onto a core it would have rejected. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1020-X3-5** | There is one `call` ceiling (50 ms), the same for the Rust side and the JVM binding; no relaxed binding-specific ceiling exists. _Why:_ a binding needing a relaxed ceiling is a binding the product cannot ship. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **X-1020-version-window** | The version window is N = 3; the handshake, `UpgradeRequired` and `DowngradeRefused` live in `crates/ontology` and `crates/core`, with tests at both window ends. _Why:_ a bounded compatibility window keeps old and new cores from silently talking past each other. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **D-1025-S4-1**, **D-1025-S4-7** | One hash names everything Centraid names, and it is BLAKE3: content, intent payloads, the audit chain, backup artefact digests, secrets stored at rest, key fingerprints and capture handles. No column is named after a hash function; hash columns hold BLAKE3 and are plainly named. _Why:_ two hash functions are two answers to "what is this?", and a stage door that computed one while the column was unique on the other gave two names for one document and a dedupe that could never fire; a column named for a function it does not use is a comment that lies and cannot be linted. [#1025](https://github.com/srikanth235/centraid/issues/1025) |
| **D-2** | There is no schema trigger on collection entry kinds: the commands stay the only writers and each refuses the other kind's id. A trigger is added when a third entry kind is proposed for either collection kind. _Why:_ a trigger for two kinds guards nothing the commands do not. [#1047](https://github.com/srikanth235/centraid/issues/1047) |
| **R-1047-D4**, **R-1020-27**, **Q-1047-14** | There is no `online_only` bit on a command, an app action row or the core catalogue, and no `CoreError::OnlineOnly`; `ERROR_CODE_ONLINE_ONLY = 44` is reserved by number and name. Locker's secret-bearing writes are enforced by `assert_sealed_cell` in the command and `seal_command` in the core, never by a flag. _Why:_ the phone is the vault, nothing queues for a gateway, and a flag nothing reads is a claim nobody checks. [#1047](https://github.com/srikanth235/centraid/issues/1047) |
| **R-1047-R1** | Every vault write goes through the commit guard, and no vault command writer resolves a conflict by `REPLACE`: it upserts. _Why:_ SQLite does not report a row a fast-path REPLACE displaced to the update hook and fires no delete trigger, so the manifest's census would disagree with the file (a restore refuses a file whose counts disagree) and a displaced row's entity would be orphaned. [#1047](https://github.com/srikanth235/centraid/issues/1047) |
| **R-1047-X2** | A vault keeps no notices: `notifications_notice` and its indexes are gone, and nothing reads or writes a notice. _Why:_ the planes that raised notices went under #1029 and the inbox that read them is gone. [#1047](https://github.com/srikanth235/centraid/issues/1047) |
| **R-1088-12** | There is no replay ledger: `invoke_key` is the shell's correlation key (the core requires it, the vault never sees it), a command sent twice runs twice, and `Idempotency::Once` means "must not be run twice for one intent", not "the vault stops a second run". ## Backup and the gateway

<a id="backups-from-first-principles-1080"></a> <a id="finding-a-gateway-on-ios-until-a-shell-browses-1080"></a> <a id="the-gateway-v2-and-the-cut-over-1080"></a> <a id="the-native-shells-backup-half-1080"></a> <a id="the-native-shells-library-deleters-1080"></a> <a id="the-phone-core-and-the-cut-over-1080-lane-c"></a> <a id="the-shared-half-of-the-backup-1080"></a> <a id="the-shared-halfs-questions-for-the-owner-1080"></a>

The phone is the vault; a machine running `centraid-gateway` is a blind store for its sealed backup.

| Id | Decision |
| --- | --- |
| **X-1020-no-fallback** | There are no fallback paths for an unsupported protocol or capability: the client shows one update wall, and protocol parsing stays strict and graceful. See [protocol.md](protocol.md). _Why:_ a silent fallback hides which side is stale. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **X-1020-gateway-service** | The gateway runs detached from any app, as its own process. Installing it as an OS service is opt-in and default-off, and the service label is `dev.centraid.gateway`. _Why:_ the member decides what runs on their machine. [#1020](https://github.com/srikanth235/centraid/issues/1020) |
| **X-1029-phone-dials** | The phone dials and accepts no inbound connection, and the gateway verifies that an object's name is the digest of its bytes before it acknowledges the write. The `no-listening-socket` rule keeps the one listener in the workspace to the gateway. _Why:_ a phone with a listening socket is a server by accident. [#1080](https://github.com/srikanth235/centraid/issues/1080), [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **R-1029-2** | Upload is foreground work plus the windows the operating system grants (the charger-time background task on iOS, WorkManager on Android). There is no transfer while the app is suspended and a force-quit stops it until next launch, and member-facing copy never overstates this. _Why:_ it is the same posture as the platform's own cloud backup, and a claim of continuous backup would be false. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **R-1029-3** | Bodies on the gateway wire are JSON and raw bytes for objects; the `.proto` files stay the schema of record for the shapes and keep their `buf breaking` gate. _Why:_ both adapters had shipped JSON, so the finding was ratified rather than reworked. [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **D-1020-D1-7**, **R-1020-29**, **D-1020-R8** | The vault keeps one snapshot use: the pre-migration copy taken before a ladder rung runs, so a failed rung leaves the vault as it was. A backup never copies a sanitised snapshot: it copies the whole vault page for page. _Why:_ a restore from a sanitised copy comes back without what it removed, and the seat plane that needed a bootstrap copy is gone. [#1080](https://github.com/srikanth235/centraid/issues/1080), [#1029](https://github.com/srikanth235/centraid/issues/1029) |
| **R-1029-8** | Every vault-derived path on iOS is excluded from the operating system's backup (the vault file, its WAL, the spool, the thumbnail cache and the other derived paths), and the sweep runs at three moments including the one before the system takes a backup, because exclusion does not inherit to new files. ### Governance as a constitution (#1005)

| Id | Decision |
| --- | --- |
| **R-1005-11**, **R-1005-23** | A rule's door selects when it runs and the pack row sets its severity: `error` blocks, `warn` is a front-page finding, `off` repeals a rule without deleting it. Severity and door are the policy, so moving one, changing a rule without its cases, or adding a rule with no pack row is refused at the hook door unless `CONSTITUTION.md` changes in the same arrival (`amendment-pairing`). _Why:_ porting a blocking directive into a warning weakens policy without editing it, and a cardinal rule enforced by attention is enforced by nobody. [#1005](https://github.com/srikanth235/centraid/issues/1005) |
| **R-1005-13**, **R-1005-19** | The law reads three estates: `law` (the union of every pack's `lawPaths`), `registry` (`receipts/**`, `CHANGELOG.md`, `docs/**`, `QUALITY.md`, `.governance/law/docket.json`) and `territory` (everything else). | **R-1005-18**, **R-1005-26** | The rule catalog is replayed against a real, already-merged change: #1002's squash range is pinned in `.governance/law/fixtures/replay/1002.json` and covers `estate-separation`, `registry-completeness`, `doctrine-citation` (both uncited rulings, by receipt line) and `waiver-docket`. _Why:_ a catalog that has only seen its own fixtures is a catalog of opinions; failing on a change that already merged is what makes "this would have caught it" a fact.
