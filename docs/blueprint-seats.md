# Blueprint seats

Settled **2026-08-05** (Photos v4 design session). How the three client surfaces differ for blueprint apps, which machinery each app class needs, and the north-star product each app mimics. Cite this file instead of re-deriving the split per app; if a decision is wrong in practice, change it here in the same PR that diverges.

**Why north stars at all:** each blueprint deliberately mimics the most popular incumbent in its category so a member switching to Centraid meets no new mental model. Friction is the enemy; novelty is not a goal. When a design question has no answer in the handoff, the north star's behaviour is the default answer.

## The three seats

Form factor (`compact`) says how wide the window is. The **seat** says where bytes live and which way they flow. They are orthogonal: a PWA on a phone is compact but still a viewer; a narrow desktop window is compact but still the custodian's console. Never branch custody logic on `compact`, and never branch layout on seat.

|  | **Mobile (Expo)** | **Desktop (Electron)** | **Web / PWA** |
| --- | --- | --- | --- |
| Seat | **origin** — content is born here (camera, scanner, mic) and cached here | **custodian** — the gateway is a local child process; bytes are effectively local | **viewer** — a replica of meaning; bytes arrive only on request |
| Default byte flow | up (device → gateway) | none — it is the destination | down (gateway → browser, on demand) |
| Danger state | `local-only` — content one accident from gone | gateway disk / backup health | staleness — replica behind the vault |
| Offline means | camera roll + cache fully work; sync resumes later | nearly cannot happen (local gateway) | meaning renders, bytes do not |
| "Free up space" | core feature (evict `backed-up` originals) | rarely meaningful | meaningless |

Code constant: each bundle declares `SEAT: "origin" | "custodian" | "viewer"` as a build-time fact — never a user-agent sniff. See [platform-gating.md](platform-gating.md) for the signal table it joins.

## Two classes of blueprint

| Class | Apps | What the seats must do |
| --- | --- | --- |
| **record-only** | tasks, agenda, people, tally | Payloads are rows. The replica gives every seat offline reads and queued writes for free. No custody states, no upload queue, no download gate. |
| **byte-bearing** | photos, docs; notes and locker via attachments | Needs the custody triple, the backup engine (up), the pin/download engine (down), free-up-space, and the metered gate. |

Every hard per-seat question in the Photos v4 audit was a byte-bearing problem. An agent building a record-only app should not touch any of that machinery.

## Byte custody vocabulary

One triple, system-wide (already shipped in `apps/mobile/src/apps/photos/timeline-model.ts`):

| State | Meaning | Tile slot 4 |
| --- | --- | --- |
| `local-only` | on this device, **not** on the gateway | the custody **mark** — a cloud-slash glyph, from rung S |
| `backed-up` | on the device and the gateway | — (nothing to explain) |
| `remote-only` | gateway only; offloaded from this device | — , except when the gateway is **unreachable**, where the line `on the gateway` explains a tile that cannot paint |

**The triple is a data model; the tile is a binary.** The rule is about ALTITUDE, and it is the part that keeps getting re-litigated, so it is written down rather than left to taste:

- **Per-tile** — the exception only, as a **mark, never a sentence**. `local-only` is the one custody state a member can lose something to, so it is the one that earns a glyph. The two normal states say nothing.
- **Per-shelf** — the population fact, as a count (Backup health's "N on this device only"). This is where an anxious member actually looks, and where the mark is taught.
- **Per-photograph** — the full story, on demand, in the viewer's info sheet.

Slot 4 resolves to **at most one** of a line or a mark (`stateOverlay` returns one value with two shapes, so the exclusion is structural, not a convention). Precedence: `could not decode` → Trash's countdown → `on the gateway` when unreachable → the custody mark. Every case that produces a line is one where custody is not the actionable fact.

Why not a line per tile: it labelled the steady state (`remote-only` is where bytes are _designed_ to live) and the default (in a fresh camera roll every photograph is `local-only`), in prose, under every tile — chrome inside the grid, which §18 forbids. Both Apple Photos and Google Photos independently arrived at the same answer: annotate the exception, never the norm, and never with words. Web already worked this way (`packages/blueprints/apps/photos/media.ts` draws its note only when there are no bytes to paint), so the phone was the surface that had drifted.

Web's `TileMediaState` (`pending | bytes | gateway | failed`) is the **paint pipeline**, not a competing custody model — a viewer seat is never an origin, so `local-only` cannot occur there.

## North stars

| Blueprint | North star | Settled consequences |
| --- | --- | --- |
| **Photos** | Google Photos | Merged mobile timeline (camera roll + vault as one stream, `local-only` marked per tile). Backup is **automatic-with-policy**: one consent moment, then Wi-Fi/charging/roaming policy — never per-photo. Per-item "back up now" survives only as a manual override. Download runs the other way on the same engine: the shelves' Download slot pins and fetches originals ([#883](https://github.com/srikanth235/centraid/issues/883) C6), retiring the phone's `NO_DOWNLOAD_REASON` refusal; on a metered connection it holds for one explicit second tap rather than spending the bytes. |
| **Docs** | Google Drive | Fully feature-rich: folders, sharing, versions. Viewer downloads on demand; mobile gets offline **pins** — real since [#883](https://github.com/srikanth235/centraid/issues/883) C6: a pinned document's bytes are stored durably and `useDocumentText` reads them off disk _before_ it looks at the network, so a pinned doc opens in airplane mode — and the scanner as an origin act; desktop gets bulk import / drag-out. |
| **Notes** | Apple Notes | Folder hierarchy (not labels). Offline-first editing on every seat with background merge; mobile origin acts: quick capture, voice. |
| **Agenda** | Google Calendar | Full replica on all seats; offline read + queued writes; notifications are a mobile-seat act. |
| **Tasks** | Todoist | Same shape as Agenda: tiny payloads, all seats equal, write queue. Todoist alone as of [#834](https://github.com/srikanth235/centraid/issues/834) — one north star per blueprint, and Todoist is the depth bar ([R-northstar](decisions.md#rebuilding-agenda-notes-and-tasks-834)). The backend keeps its Things-shaped vocabulary; the north star names the depth, not the words. |
| **People** | Google Contacts | Full replica; mobile wants OS-contacts import and share-sheet in/out. Every seat draws the v12 screens ([#821](https://github.com/srikanth235/centraid/issues/821)): desktop/web inline, mobile native over replica entity reads. |
| **Locker** | 1Password | Biometric unlock + OS autofill on mobile. **Disabled on the PWA seat for now** — a shared browser is the risky seat; revisit post-v0 with a re-auth-per-open design. |
| **Tally** | Splitwise | Shared expense splitting: multi-party balances ("who owes whom"), naturally at home in a shared/household vault. Record-only, and offline in both directions: its writes queue, and its derived READS run on the device — the phone imports the same `queries/*.ts` modules and the same `tally-balance.ts` / `tally-simplify.ts` fold the web seat uses, over the mounted replica, so "who owes whom" is one derivation on both seats and the gateway read RPCs are gone ([#922](https://github.com/srikanth235/centraid/issues/922) SB-tally / E7; parity held by `tests/integration-mobile/tally-balance-parity.integration.test.ts`). Mobile origin act: receipt photo (byte-bearing only at that edge). |

## Shared engines (build once, per-app never)

1. **One backup engine, one policy.** The upload queue (`apps/mobile/src/apps/photos/photos-backup.ts`) and the Wi-Fi/charging/roaming policy become **frame-owned**. Google's model: one backup setting per account, not per app. Docs' scans and Notes' attachments enqueue into the same engine; consent is asked once.
2. **One pin/download engine.** `apps/mobile/src/kit/fetch-gate/` is it: `ensureOfflineContent` runs local read → metered gate → download → budget pass in that order, and Docs' "available offline" and Photos' "download the original" are the same four steps ([#883](https://github.com/srikanth235/centraid/issues/883) C6). It serves the ORIGIN seat, not only viewers: `gate.ts` is the metered-choice half, `content-store.ts` the durable bytes, `eviction.ts` the law — **a pin is never an eviction candidate**, structurally rather than by a filter at the end, so a store over budget _because of_ pins reports `overBudgetBy` instead of breaking the promise. The budget (`OFFLINE_CONTENT_BUDGET_BYTES`, 256 MiB) is store-wide and governs only the unpinned remainder. The viewer seat still downloads on demand and holds no pins: "Offline means: meaning renders, bytes do not" is that seat's own row.
3. **The reachability contract.** Web: the shell stamps `data-gateway-status` on every inline app root (`InlineAppRoute`); blueprints read it (`libraryReachability`). Mobile: `kit/hooks/replica-query-state.ts`. The §14 offline banner grammar (bordered `--net`, no fill, no icon, outlined Retry) is the one way to say offline.
4. **Origin acts live on the frame; apps register targets.** `Capture.tsx` and `Scan.tsx` already point this way. Camera, scanner, share-sheet-in, notifications, autofill are frame capabilities an app declares — one door for every app.
5. **The refusal grammar** — outcomes to the one status line; disabled controls visible, inert at the handler, and explained inline (never a tooltip).
6. **One search scaffold, per-app entity config.** `packages/blueprints/apps/_shared/search-scaffold.ts` (pure: status union, `groupSearchHits` over a per-app `SearchEntity[]` config, `SearchStateCopy`) + `SearchScaffold.tsx` (the ruled-row / four-state rendering) — issue #712 S1. Photos' `SearchShelf.tsx` and Notes' search route render through it ([#834](https://github.com/srikanth235/centraid/issues/834)), as Tally's search did until its interface was cleared ([#831](https://github.com/srikanth235/centraid/issues/831)); mobile's `search-hits.ts` consumes the pure `groupSearchHits` combinator directly (no UI change). Matching stays app-owned — only "find, then cap, then order" is shared, per this doc's own worked example above: the words differ by seat, and now the states and grouping mechanics do not have to be reinvented per app to say them.
7. **One selection engine, app-owned nouns.** `packages/blueprints/apps/_shared/selection-engine.ts` owns immutable select/toggle/range/prune transitions, the fixed action-slot contract, disabled-handler honesty, and serial failure-isolated batch execution. Web and native import it. Each app keeps the action names, vault commands, copy, and receipts that make those transitions mean something in its domain; Docs bulk-move or Notes bulk-delete must join the engine rather than fork Photos' mechanics.
8. **One pending-write overlay engine.** `packages/blueprints/apps/_shared/pending-overlay.ts` makes every local read `replica ⊕ outbox`. Apps declare action projections and the explicit edit-action → queued-action pairs that may revise them in `pending-projection.ts`; shells own intent identity, status, settlement, retry, and discard. Browser and native consume the same declaration and presentation sanitizer, so no seat may keep a parallel pending array or infer a pending row identity from an arbitrary foreign key.
9. **One action-handler spine.** `packages/blueprints/apps/_shared/action-kit.ts` owns what a bundled action DOES: `runVaultAction(ctx, …)` hands one typed command to `ctx.vault`, passes the outcome back verbatim, and turns a THROWN refusal into the same `{status: "denied", reason, code}` at HTTP 200 that a reached refusal already is — so a surface narrates both with one branch. All 131 handlers dispatch through it ([#883](https://github.com/srikanth235/centraid/issues/883)); what stays app-owned is shaping the member's body into the command's `additionalProperties: false` contract, which is the one thing an action knows on its own. Two lanes in `scripts/lint-engine-conformance.mjs` hold it: **engine K** fails a handler that does not import the kit, carries a `catch` statement of its own, or spells `"denied"` itself, and fails the kit when it stops exporting a verb the handlers call; **engine W** keeps each action's `app.json#writes` a well-formed claim — every name a live vault entity, and never the empty array all 131 once declared.
10. **One concept-scheme vocabulary.** A blueprint cannot ask the vault for a scheme by name; it reads `core.concept_scheme` and matches the URI, so every surface that wanted a star, a folder, a list or a free-form label carried its own copy of the string — twenty declarations across seven files. A typo there is not a crash, it is a silently empty shelf. `packages/blueprints/apps/_shared/concept-scheme-kit.ts` is the one owner ([#883](https://github.com/srikanth235/centraid/issues/883)), and **engine V** fails any `https://centraid.dev/schemes/…` literal spelled anywhere else in the blueprint tree — test fixtures included, since a stale copy in a fixture is how a suite goes on passing against a scheme the vault no longer mints. The native seat keeps its own copies for now: `apps/mobile/src/apps/**` cannot import a `.ts` source module from this package under every build mode, and folding it in is its own change.

## Engine contracts

Settled **2026-08-06** (issue #712 E2). The list above says WHAT is built once; this says what each engine promises, so an agent can consume one without reading its implementation. Every contract names three things: its **verbs** (the only way in), its **reason-string grammar** (what the surface must be able to say when it refuses), and its **structural exclusions** — the cases made unrepresentable rather than filtered at render time, because a rule enforced by a type or an absent registry row cannot be forgotten the way a rule enforced by an `if` can.

One canonical gate per engine is registered in `tests/claims.json#appEngines` and validated by `bun run test:claims`. The existing source-shape gates remain in `scripts/lint-engine-conformance.mjs` (wired into `check:push` as `lint:engine-conformance`), with the single-package halves left beside their contracts: `packages/blueprints/src/placement-registry.test.ts`, `blueprint-seats.test.ts`, the `_shared` engine tests, and `packages/blueprints/src/no-inference-client.test.ts` (the provider-SDK and second-enrichment-client ban, scanning browser, native, and automation trees).

**A — sharing.** **What a member shares is a standing grant** ([#825](https://github.com/srikanth235/centraid/issues/825)). `window.centraid.grants` is the grant plane's bridge — subjects/forParty/forAudience/forSubject/create/revoke over `/centraid/_vault/grants` — and every seat reads it through the one shared kit in `packages/blueprints/apps/_shared/grant-*` (native holds an authed base URL instead of the bridge; nothing else differs). Docs, Photos and People all draw the same `GrantSheet`, and the roster mapping every host supplies it with is one law in `apps/_shared/grant-audiences.ts`, not a per-app copy. The registry decides the verbs: `edit` is drawn only where `GET …/grants/subjects` answers it, and an unreadable registry offers nothing rather than everything. Reason grammar: a refusal's gateway reason is printed verbatim.

`window.centraid.share({ sourceVaultId, containerType, containerId, members })` remains the **container-sharing** verb — container-scoped co-ownership, which is the `edit` fulfillment strategy under a grant: every joined member gets a subscription to the container's shape and the right to send its origin signed intents ([#929](https://github.com/srikanth235/centraid/issues/929)). Tally's group manager was where a member met it directly, and is where the rebuilt interface meets it again ([#831](https://github.com/srikanth235/centraid/issues/831)); the registry row (`tally.group`) and the write command behind it never moved. `packages/blueprints/apps/_shared/placement-registry.ts` is the structural answer to “which container can cross vaults”; `packages/vault/src/share/actable.ts` is its write-command sibling. Structural exclusion remains **Locker × sharing**: `locker.item` is absent from `PlaceableItemType` and from the grant subject registry, so a Locker sharing control is a type error on one side and unofferable on the other. Copy-as-share is gone: “Save to my vault” survives only as the RECEIVER's retain action over an existing projection, which is receiving, not sharing.

**Reading the sharing plane is separate from writing it** (#821, amended by #825): an app may hold `read` on `share.*` to SURFACE links — People draws who is linked, Docs decorates drive rows with `shared_with`. What that read no longer has to carry is the standing-share list itself: People's person screen reads live grants from `?partyId=` and offers `Share` and `Revoke` on the section head, so the #821 withholding of those two verbs is **closed, not still in force** (see [design-divergences.md](design-divergences.md)). Every such read answers `null` on denial and the surface draws nothing, never an empty set.

**B — custody.** `apps/mobile/src/kit/transfer/` (up) and `apps/mobile/src/kit/storage/` (down and out) are the frame's only doors to moving and releasing bytes. Verbs: `answerBackupConsent` / `automaticTransferAllowed` (the one consent moment), `writeTransferPolicy` + `TRANSFER_POLICY_SWITCHES` (the Wi-Fi/charging/roaming record), `readTransferQueue` + `backupVerdict` (what this device is still carrying), `readCustodyStatus` / `foldCustodyStatus` (where the originals are), `freeUpOffer` + `revalidateBackedUp` (releasing them, re-hashed at delete time). Reason grammar: every inert switch carries `inertReason(policy)` — required on the switch's own shape, so a sixth rule cannot arrive without a sentence — and every unreadable source states which source failed rather than folding to zero ("could not be read", "not yet computed"). Structural exclusions: **record-only × custody** (`blueprint-seats.test.ts` for the web tree, the custody check for the mobile one) and **Locker × free-up-space** — a secret has no device original to evict, so it is not in `FREE_UP_APPS` at all.

**C — consent.** `packages/blueprints/apps/_shared/consent-gate.ts` is the shape; `ConsentGate.tsx` in that directory (web) and `apps/mobile/src/kit/components/ConsentGate.tsx` (native) are its two renderers. Verbs: `onRunOnDevice`, `onDecline`, `onChooseNet` — three callbacks and no internal state, so "can a write be issued without an explicit answer" is a question about a caller's props. The tier gate is one rank comparison, `decideEnrichmentGate` in `packages/server/src/automation/fire/enrich-gate.ts`. Reason grammar: `AnswerAvailability` is `{ available, reason? }`, and an unavailable answer renders its reason **beside the control**, never as a tooltip and never as silence; the `--net` panel renders even when its action cannot be taken, because a member who cannot choose egress still has to be told what it would cost. Structural exclusion: **Locker × enrichment**. `domain` is typed `EnrichDomain` (`photos | docs`), so Locker has no value to supply — there is no secret-scanning consent moment to build.

**D — triage.** One verb answers a proposal: `media.answer_face_proposal` (`packages/vault/src/commands/enrich.ts`), with three answers — confirm, reject, dismiss — writing `media_face_region.review_state`. The `media.confirm_face` / `media.reject_face` pair it replaced is **retired, not deprecated beside it**: reject was a DELETE, which is not a state, so the enricher was free to re-propose the same stranger for ever and a review queue could never be finished. The generic session state machine is `packages/blueprints/apps/_shared/triage-session.ts` (`openTriage`, `triageCurrent`, `triageSkip`, `triageAnswer`, `triageRefill`, `triageProgress`), pure and imported verbatim by browser and native seats; its frozen denominator is why the numerator counts up instead of the total sliding around mid-session. Reason grammar: skip records nothing and says so; a queue control that goes inert must say why, since a member stuck at "1 of 54" with a grey control has no next move. Structural exclusion: the outcome vocabulary is per app — the shared module knows neither faces nor duplicate clusters — so a third consumer joins by naming its outcomes, not by widening the engine.

**E — search.** The search scaffold is row 6 above (`apps/_shared/search-scaffold.ts` + `SearchScaffold.tsx`). It has no write verb: its law is a pure configured grouping/cap/order combinator plus a four-state renderer, while matching stays app-owned. Structural exclusion means an app does not consume the scaffold at all; it is never represented by a renderer that silently searches nothing.

**F — enrichment boundary.** Apps enqueue consent-scoped `enrich_request` rows and read model-versioned vault projections. Recognition templates bundle their deterministic model implementation, obtain content with `ctx.vault.content`, and persist through `ctx.vault.invoke` (OCR also has an optional `ctx.delegate` variant). Blueprint/native/template code imports no provider SDK and uses no generic `ctx.infer` / `ctx.enrich` road. Reason grammar is the automation outcome: missing local assets, policy skip, or model failure remains capability-scoped and ledger-visible rather than being relabelled success. Structural exclusion is the closed `EnrichDomain` union and the app's absent consent/control surface.

**G — scope kit + shared containers.** `packages/blueprints/apps/_shared/scope-kit.ts` is how an app reads independently resident vault rows without writing sharing transport. A `ScopeAppDeclaration` still names only `mergeKey`, `mintedIdFamilies`, and the string-tagged `projectionIngest` door. Sharing adds no app-local sync engine: the origin serves a grant-keyed replica shape, each member vault subscribes to it, each seat's ordinary replica cursor observes that vault, and `mergeScopePages` reads it like any other scope. The per-shape `(shape, audience vault)` cursor belongs to vault core, not to the blueprint. Photos remains the byte-bearing proof; Tasks is the record-only proof again through its own `scope-fanout.ts`, restored with its rebuilt interface ([#834](https://github.com/srikanth235/centraid/issues/834)). Tally is the multi-writer proof: every `read+write` group member sends signed intents to the container's one origin, which executes them as its single writer, then every seat computes balances locally from identical expense/split rows — no balance projection crosses the wire.

**H — pending-write overlay.** Verbs: `projectPendingWrite` converts an app action declaration into row mutations; `decoratePendingMutation` folds the durable intent's live status into those rows; `settlePendingOverlay` and `expirePendingOverlay` are the pure visible-row transitions; `retryPendingWrite` and `discardPendingWrite` are the only terminal persistence controls. Status grammar is shared: `queued` says “Waiting for a connection”; `sending` stays quiet; `parked` names the approval reason and the seat it waits on (`owner`, `origin` or `gateway`) with the label from the link; `denied`, `conflict`, and `failed` retain the reason and expose edit/retry/discard; conflict copy includes expected and actual versions; `expired`/`cancelled` remain explicitly dismissible — a shape removal settles that shape's queued intents `expired` with “no longer shared with you”. `executed` alone removes the overlay in favor of canonical rows. A synthetic-add revision is recognized only when the app declaration pairs the incoming edit action with the original queued action and projects that synthetic row identity; a canonical-row revision matches the exact app, action, shape, entity, and row projected by the incoming edit. Unrelated pending foreign keys are ordinary input. Replacement is exclusive per original intent in one runtime and under Web Locks across browser tabs; a second tap reuses the already-durable successor rather than minting another write. Inline query decoration preserves the source row's exact pending provenance across ordinary object spreads; an explicit field-only projection matches the row's own leading identity field and never merges every matching foreign-key marker. Structural exclusions must be declared with a reason: Locker add/edit secrets set `onlineOnly` and both the inline and served bridges bypass the replica session entirely, while its non-secret item actions project metadata-only row patches; Photos upload bytes use custody; actions whose payload cannot identify a row say so rather than performing an extra app-owned read. Origin-side status may enrich the reason and the waited-on seat online but never creates a second row source. `scripts/lint-engine-conformance.mjs` rejects the removed hand-owned stores, common renamed variants, vocabulary-free hook collections fed from replica write results, inline optimistic mutations, and any app reach-past into intent/overlay engine internals. Its demonstrated-red fixtures cover semantic write-result dataflow and the architectural boundary; `packages/blueprints/apps/_shared/pending-overlay.test.ts` pins the runtime projection and settlement laws.

## App admission contract

An app does not sit in the shell because a folder exists under `packages/blueprints/apps/`. It sits there because it satisfies six named claims, each of which some gate refuses to let it go quiet about. This section is the SHELL half of admission — what must be true and registered for an app to be mounted at all. The EVIDENCE half — which layer (`U`, `C`, or `E`) is the cheapest one that falsifies a given scenario claim — is [TESTING.md's app admission contract](../TESTING.md#app-admission-contract), and the two are read together: this one says what an app owes, that one says at which tier the owing is paid.

1. **A valid manifest, including the `seats` and `states` blocks.** `packages/server/src/engine/registry/manifest.ts` is the one validator, and the [designed-states](#designed-states) partition is closed there: a manifest that omits a canonical state, claims one on both sides, or lists one twice is rejected rather than projected with a hole. `packages/blueprints/src/app-manifests.test.ts` parses every bundled manifest under that real validator.
2. **Engine conformance.** Each shared engine has one canonical gate registered in `tests/claims.json#appEngines`, and the source-shape half is `scripts/lint-engine-conformance.mjs` (`lint:engine-conformance`, in `check:push`). An app joins an engine by passing its cell; a combination the seat doctrine makes impossible is a `skip` with a reason and an [engine-contracts](#engine-contracts) citation, never a blank.
3. **Every designed state owned or tracked.** `tests/claims.json#appStates` (grid D of the test-health report) mirrors the app's own `app.json#states` partition, cell for cell. Each cell is `owned` (naming the proof), `gap` (naming an open tracking issue), `excluded` (only where the manifest excludes the state), or `held` (naming the ruling that cleared the interface the state would live in — Tally's seven cells cite [#831](https://github.com/srikanth235/centraid/issues/831)). A missing cell is a validation error, so "we forgot" cannot render as "not applicable".
4. **Every seat owned, tracked, or refused.** `tests/claims.json#appSeats` (grid B) owes a cell per app per seat on the same terms. A seat the manifest turns off — Locker's `disabledOn: ["viewer"]` — is a `skip` whose reason is the refusal itself, and the refusal is what the journey there proves (`apps/web/tests/e2e/locker-seat.spec.ts`).
5. **A pending projection for every action.** Every app declares one in `pending-projection.ts` and registers it from `app-inline.tsx`; `packages/blueprints/apps/_shared/pending-overlay.test.ts` asserts the declaration covers exactly the manifest's action list, with every structural exclusion carrying a reason, and contract [H](#engine-contracts) is what refuses an app-owned optimistic store in its place.
6. **Placement declared, or structurally absent.** An app that can place rows into another vault names its entities in `packages/blueprints/apps/_shared/placement-registry.ts`; an app that cannot is absent from `PlaceableItemType` altogether, which is why Locker sharing is a type error rather than a hidden control. `packages/blueprints/src/placement-registry.test.ts` holds the registry against the vault's own `ShareableItemType`.

`scripts/test-report/validate-app-axes.mjs` is what enforces claims 3 and 4 as totals: the app axis of each grid must equal the apps on disk, every owner path must exist, every gap must cite an open issue, and every skip or hold must cite a followable document anchor or registered issue. The grids are the contract's ledger — read them there rather than restating their contents here. History: [#839](https://github.com/srikanth235/centraid/issues/839).

## One computation

A product-law computation lives exactly once: **in the vault as a model-versioned projection when it is derivable server-side, otherwise in `packages/blueprints/apps/_shared` as a pure module imported by every seat**. Browser and native components are adapters over that result; they do not maintain seat-local versions of the arithmetic.

Pure app-delta arithmetic follows the [app admission contract](../TESTING.md#app-admission-contract): put a `*-model.ts` beside the view and exercise it at the U layer. When the same concept spans seats, promote the pure law to `_shared` instead of copying the model. Photos' face crop, confirmed-photograph people counts, triage session, and selection transitions are the reference hoists; its Memories rail reads the gateway-built `media.memory` / `media.memory_member` projection rather than deriving another rail client-side.

`packages/blueprints/src/one-computation.test.ts` is the mechanical guard. It scans ten lanes — the eight paired blueprint apps, plus `packages/client/src` against mobile's `kit`+`lib` (the **kit** lane) and against the rest of `apps/mobile/src/apps` (the **screens** lane), so every mobile source directory is paired exactly once. Two baselines, both tighten-only: a new runtime export-name collision fails, an identical body under two names fails, and removing an old collision must shrink the baseline in the same change. It also asserts that the shared crop/count modules are imported by both seats.

Analytics is the second reference hoist, next to Photos: the run-rollup arithmetic — columns, axis marks, spend and source facts, the four breakdowns, the CSV — lives once in `packages/design/src/blocks/insights.ts`, and each seat lends only its number words (`InsightWords`) and maps the result onto its own row shapes.

## Enrichment doctrine

Settled **2026-08-06** (issue #712 C5), amended **2026-08-08** by #725 for the #724 reference service. Product code reaches model work only through host-owned seams:

1. **`ctx.delegate`** through the ACP harness registry (`packages/server/src/engine`) — a harness turn, dispatcher-gated per call for provider egress (#567).
2. **The device work-lease lane** (`enrich_request.required_capability` + `packages/vault/src/enrich/leases.ts`) — non-model device work such as poster and PDF-text extraction, bytes never leaving the member's own devices.
3. **Deterministic recognition automations** — bundled handlers own and run their ML implementation, read content through `ctx.vault.content`, and persist typed results through `ctx.vault.invoke`; the automation engine owns schedule, policy, cursor, ledger, and retry. Model assets may be local to the automation runtime.

No blueprint app, native seat, or automation imports a provider SDK, calls a model service, or uses a generic `ctx.infer` / `ctx.enrich` primitive (`packages/blueprints/src/no-inference-client.test.ts` is the conformance check). Apps express intent as rows and consume vault projections; deterministic templates are self-contained, while OCR's optional delegate step uses the existing ACP and egress-consent rails.

**The trust-domain boundary.** A member's trust domain is their own devices _and_ their own gateway — the gateway is not, by itself, egress. What IS egress is a harness that talks to a **third-party provider**; every harness shipped today happens to be one, which is a fact about the roster, not a definition. The door stays open for a gateway-hosted local-inference harness (a custom `acp` kind fronting a model with no network egress) whose model turns would be legitimately inside the trust domain — the deciding fact is "does this harness egress to a provider", a property of the harness, never of which machine issued the call.

**One axis, three points.** `off | device | gateway` (`packages/server/src/automation/fire/enrich-gate.ts`), ordered by how far work may run — `off` (nothing), `device` (the member's phone/laptop, plus deterministic gateway work), `gateway` (the member's own gateway may additionally do whatever it is already wired to). There is no fourth `provider` tier: provider egress is enforced per call at the dispatcher (#567) and per capability at the consent gate (decision S9), independently of this tier. An enricher declares the **lane** it needs (`manifest.enrich.lane: "device" | "gateway"`); the gate is one rank comparison, `rank(lane) <= rank(tier)`. Every enrich domain (`ENRICH_DOMAINS`: `photos`, `docs`) declares its enrichers' lanes the same way — none of them invent their own transport.

**The policy cascade (#807).** That per-domain tier is the vault-default layer of a scoped cascade — vault → domain → collection → item (`enrich_policy_rule`). Each level states, per capability, up to three things: `enabled`, the engine `profile`, and the `trigger` (`on-ingest | on-view | on-demand`); `null` is inherit, and the fold is most-specific-wins **per field**. The tier's `off | device | gateway` migrate into that vault layer as **egress-class ceilings** (`off | on-device | gateway`) that no deeper level can raise — a rule may pick a cheaper engine, never one that reaches further than the vault allows, and the gate refuses a profile whose computed egress exceeds the ceiling. There is still ONE gate: `decideEnrichmentGate` grew the resolver (`automation/fire/enrich-resolve.ts`, re-exported through `enrich-gate.ts`), and no reader of `enrich_policy_rule` answers "may this run" anywhere else. An unreadable policy is a refusal, never a default.

**The ceiling is stored, not chosen (#815).** Settings → Enrichment offers no per-domain tier control: enrichment work runs on the gateway, and where it runs is not a member's choice, so it is not surfaced as one. Everything above still holds server-side — the vault layer still carries a ceiling and the gate still refuses under it — so a capability a stored ceiling stops states that at its own row, in ceiling words (`ENRICH_CEILING_WORDS`). A member's remaining enrichment choices are per capability: on or off, and for the two delegate-capable capabilities, which engine reads it.

## Worked example: search is not one behaviour

Photos search resolves differently per seat, and the copy has to follow:

| Seat | How it resolves | What the surface says | Offline |
| --- | --- | --- | --- |
| viewer (web/PWA) | live gateway FTS5 (`ctx.vault.search`), no replica in the path | `N results · searched the live library` | cannot search — the `--net` unreachable panel is the honest answer |
| origin (mobile) | the on-device replica's eager metadata | `N results · searched the whole replica on this device` | searches fine; may be behind the vault |

Neither is a deviation from the handoff — the handoff was written for one seat. The rule "a surface never teaches a different fact about the same control" governs **facts**, not strings: where the underlying truth differs by seat, the words must differ with it, and where it does not, the words are shared verbatim. Web additionally matches free-form tags (`core.tag_item`), which the mobile replica does not carry, so `things` appears in one client's copy and not the other's for the same reason.

## Per-app seat profile (machine-readable)

Each blueprint's `app.json` grows a `seats` block so coding agents get the split without reading this prose:

```json
"seats": {
  "byteBearing": true,
  "originActs": ["camera"],
  "disabledOn": [],
  "northStar": "google-photos"
}
```

Locker declares `"disabledOn": ["viewer"]`. Record-only apps declare `"byteBearing": false` and should fail review if they import custody machinery.

### Designed states

Beside `seats`, each UI blueprint's `app.json` carries a `states` block naming which honest states the design calls for:

```json
"states": {
  "designed": ["dayone", "pending", "offline", "stale", "conflict", "parked", "denied"],
  "excluded": []
}
```

The seven ids are the canonical designed states (`CANONICAL_DESIGNED_STATES` in `packages/server/src/engine/registry/manifest.ts`), and the two sides are a **closed partition**: `packages/server/src/engine/registry/manifest.ts` rejects a manifest that omits a canonical state, claims one on both sides, or lists one twice, so an app can never be silent about a state. `designed` is what the design calls for; `excluded` is what the design makes structurally unrepresentable, and each entry costs a `reason` plus a `citation` (both non-empty) — the same evidence discipline as the [engine contracts](#engine-contracts). "Nobody has built it yet" is a gap, not an exclusion. The block is optional, so the UI-less automation manifests keep validating without one.

`packages/blueprints/src/app-states.test.ts` pins the partition app by app, `scripts/build-manifest.mjs` folds the block into the gallery `manifest.json` so the shell needs one fetch, and `tests/claims.json#appStates` **mirrors** it: the app × designed-state grid (grid D of the test-health report) must declare exactly the manifest's partition, and `bun run test:claims` fails when a grid cell and its manifest disagree in either direction. History: [#839](https://github.com/srikanth235/centraid/issues/839).
