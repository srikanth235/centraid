Five directions out of restraint

Alternative design-system directions for a local-first personal superapp — and an argument for which one to build first.

The problem with the baseline

The current system's personality comes from restraint. Restraint is a discipline, not a position — it produces a product that is never wrong and never memorable, and it leaves the hardest superapp question unanswered. If the shell is near-monochrome and each app is allowed to lead with its content, what is actually constant between a photo grid and a doc? Right now the answer is "a teal accent and a border colour," which is a brand, not an identity.

Each direction below commits to a different identity carrier — the one thing that stays the same when everything else is allowed to change:

A · Vellum
Substrate. Every app is printed on the same paper.
B · Atelier
Silence. No app may introduce a hue; chrome dims to nothing.
C · Bench
Structure. One permanent frame; colour becomes data.
D · Hearth
Temperature and shape. Rooms in one warm house.
E · Ambient
Grammar. Platform materials; identity lives in behaviour.

All five inherit the invariants unchanged: one product grammar across surfaces, semantic tokens with per-surface renderers, light and dark, WCAG AA, text scaling, reduced motion. Every hex below is a proposal for the role layer, not a hard-coded value.

A

Vellum

A bound personal archive. Ink and paper carry the identity; chrome carries nothing.

iA Writer · Things 3 · Bear · Muji / Field Notes stationery

Shell vs app
The shell is an index, not a springboard: a typographic table of contents — app name, ink mark, last-touched line, set in a ruled list. Apps are chapters and may diverge in layout almost freely, because the substrate is the constant: identical paper hex, identical 1px rule, identical ink ramp. App hues stop being brand colours and become inks — low-chroma, used in the chapter rule and the app's mark, never in a control.
Colour
Light — paper #FCFAF6 / #F6F2EA / #EFE9DE, rule #DED6C7, ink #16130E / #2E2A22 / #5C5648 / #8A8172.
Dark is not an inversion — "night desk": #14120F / #1C1A16 / #24211C, rule #35312A, ink #EFEAE0 / #C9C2B4 / #9A9284.
Accent (one): ink-blue #2F4B8F, dark #7E9BE0. Destructive: marginalia red #A8402C.

Typography
A deliberate three-way split, which is how one system serves reading and scanning at once. Docs body: Source Serif 4 (Charter, Georgia) 19px/1.65, measure capped at 68ch. UI: Public Sans (-apple-system, Segoe UI) 15px/1.45, labels 11.5px at .06em. Numerics: IBM Plex Mono tabular 13px for every date, time, file size and count — Calendar's grid is built on it, which is what makes dense scanning work without borders.
Shape & depth
Radius 3px, everywhere, forever. 1px hairline rules do all the work borders and shadows normally split. Zero box-shadows. Elevation is paper stacking: a raised sheet is one step lighter with a 1px rule and a 2px offset; a modal is a sheet over a 40% ink scrim. Spacing 4/8/12/20/32; list rows 34px desktop, 48px mobile.
Motion
Sparse and flat-footed. 160–200ms, cubic-bezier(.32,.08,.24,1), no bounce, no parallax, no scale on hover. Signature: the index row expands into the page — shared bounds, 220ms, the row's rule becoming the app's header rule. Going back reverses it exactly, so the shell feels like a place you never left.
Per surface
Desktop: two columns — a bound "spine" sidebar (paper-2, one rule, no fill states except a 2px ink bar) and the sheet. PWA: pixel-identical; there is nothing platform-specific to lose. Mobile: full-bleed lists, sheets that slide up with a 1px top rule and no blur, no elevation shadow — the direction with the smallest desktop/mobile delta of the five, and the only one where React Native costs essentially nothing.
Stress test
Photos grid
The hard one. Warm paper casts every thumbnail. Fix: Photos claims a chroma-free mat surface (#F2F0EC light / #1A1A1A dark) with 2px gutters — paper recedes into a passe-partout. Solves it, but requires a new token role, which is the seed of my recommendation below.
Docs
Best case of any direction. Serif at 19/1.65 on #FCFAF6 at 68ch is simply a good page. Editing chrome lives in the left margin as marginalia rather than a toolbar.
Mobile home
A list, not a grid: seven ruled rows, ink mark, name, one recency line. Calmer than any springboard — and measurably slower to hit a target than a 3×3 grid. Worth testing before committing.
Trade-offs
  • Dark mode must be hand-authored, not derived — a paper metaphor inverts badly. Budget ~34 values and real design time, not a token flip.
  • Warm substrate vs colour-accurate media: the mat surface is mandatory, not optional.
  • Austerity risk. Reads "literary" to some users, "unfinished" to others; no visual reward anywhere.
  • Cheapest of the five to build and maintain: no blur, no shadow system, no gradient, no per-app colour matrix. Strongest fit for a small team.
B

Atelier

Chrome is a museum wall: achromatic, dimmable, and gone the moment content appears.

Apple Photos / TV · Lightroom · Arc's low-chrome browsing

Shell vs app
Identity is the absence of colour plus one exact geometry. The shell is a dark achromatic scaffold that dissolves on entry into edge-anchored overlays; apps get near-total layout freedom and one hard prohibition — no app may introduce a hue. App identity hues survive only in the springboard, as a monochrome glyph plus a 3px accent bar under the tile. The discipline is enforceable by lint: any chromatic value outside the springboard is a bug.
Colour
Dark-primary — #08080A / #101013 / #17171B, lines rgba(255,255,255,.08), text #F2F2F3 / #A1A1A6 / #6E6E73.
Light ("daylight gallery") — #FFFFFF / #F7F7F8 / #F0F0F1, lines rgba(0,0,0,.08), text #0A0A0B / #5A5A5F.
One functional blue #2E6BFF (dark #6C9BFF) for links and focus. No other chroma in the entire system.

Typography
One family, worked hard: Neue Haas Grotesk Display (Helvetica Neue, Helvetica, Arial) — 36px/1.08 display at −.02em, 15/1.5 body, 13/1.4 dense, and 11px uppercase at .08em for every section label. Docs cannot survive on this alone, so it gets an explicit Reading surface: a 68ch sheet at #FBFBFC that stays light even in dark mode, with Source Serif 4 optional per-document. That exception is the direction's honest weak point, not a footnote.
Shape & depth
10px on floating panes, 0px on anything full-bleed — the contrast between the two is the depth model. Material: backdrop-blur(24px) over a 60% scrim for toolbars and inspectors; shadow 0 8px 24px rgba(0,0,0,.5) dark, 0 2px 8px rgba(0,0,0,.10) light. Content gutters 2–4px so grids read as one plane.
Motion
The most motion of the five, and the most controlled. 240ms cubic-bezier(.16,1,.3,1). Signature: chrome fades out over the first 120ms, then the tile's content zooms to full-bleed from its own bounds — you never see a new screen arrive, only the thing you touched growing. Reduced-motion swaps the zoom for a 100ms opacity cut.
Per surface
Desktop: full-bleed canvas, floating inspector, no permanent sidebar (⌘K and a hover-revealed rail instead). PWA: the fidelity gap — backdrop-filter is inconsistent and expensive in a web view, so translucency degrades to flat 92%-opacity scrims. Two materials for one role. Mobile: native territory; system materials, gesture dismissal, sheets — but Android blur is a real frame-cost decision, not a style choice.
Stress test
Photos grid
Decisive win, and no other direction is close. 2px gutters on #08080A, chrome auto-hiding on scroll, colour accuracy uncompromised.
Docs
Worst case. Long-form reading on a gallery wall is fatiguing within minutes; the light reading sheet fixes legibility but visibly contradicts the theme — a white rectangle floating in a dark room.
Mobile home
A dark grid of live content previews — last photo, a doc's first line, tomorrow's first event. Genuinely beautiful, and it obliges every app, present and future, to ship a preview provider. That is a permanent platform tax on "more apps arriving over time."
Trade-offs
  • Translucency vs AA is the top risk: contrast becomes content-dependent, so every overlay needs a guaranteed-opacity floor.
  • React Native blur on Android is costly and inconsistent; expect a flat fallback and therefore two visual truths.
  • The Docs exception weakens the thesis in exactly the app people spend the most minutes in.
  • Coldest of the five. For a product holding someone's family photos and relationships, "cinematic" can read as "corporate media."
C

Bench

Instruments on a shared workbench: structure is visible, colour is data, the keyboard is the primary surface.

Linear · Superhuman · Braun functionalism

Shell vs app
The exact inverse of A and B: the shell is strong, permanent and non-negotiable — a 44px left rail and a command bar that are byte-identical in every app. Apps get very little layout freedom; in exchange they get colour. Each app owns a hue that drives its rail state, selection fill and focus ring, so you always know where you are without reading. This deliberately breaks the baseline's rule that identity hues never touch actions — here that rule is the whole idea.
Colour
Cool graphite. Light — #FFFFFF / #F4F6F8 / #E8ECF0, line #D3DAE1, text #0B0E12 / #4A545F / #77828E.
Dark — #0E1013 / #16191E / #1E2229, line #2A2F37, text #E6EBF0 / #9AA5B1 / #6B7683.
App hues at oklch L≈.58 C≈.13, each with a 12% wash and a hover step — 7 × 3 × 2 modes.

Typography
One superfamily, three cuts — the cheapest way to hold density and reading in one system. IBM Plex Sans 14/1.45 for UI (fallback -apple-system, Segoe UI); IBM Plex Mono, tabular, for every time, size, count and ID; IBM Plex Serif 18/1.7 for Docs body only. 4px grid; rows 28px comfortable / 24px compact; spacing 8/12/16/24.
Shape & depth
Radius 4px. Borders always present, shadow almost never — 0 4px 12px rgba(9,12,16,.14) for popovers and nothing else. Depth is expressed by border weight and background step, which is what keeps it identical in RN. A user-level density switch is a first-class token, not a setting bolted on later.
Motion
The least motion of the five, on purpose. 120ms cubic-bezier(.2,0,.4,1) for state; app switching is an 80ms crossfade with zero translation — changing app should feel like changing channel, not travelling. Reduced-motion is nearly a no-op, which is a genuine accessibility asset.
Per surface
Desktop: home turf — rail, command bar, keyboard grammar shared across apps. PWA: identical, shortcuts included. Mobile: the weak surface. A seven-app rail collapses to four tabs plus More, 28px rows must relax to 44px targets, and the shell's permanence — the thing carrying the identity — is the first thing lost.
Stress test
Photos grid
Worst case. A magenta-tinted frame argues with every photograph. A "chrome off" full-bleed viewer rescues the single-photo view, but the grid still sits inside coloured furniture.
Docs
Strong for structured documents — serif body in a tight frame, outline rail, keyboard everything. Slightly clinical for personal prose; a journal entry shouldn't look like a ticket.
Mobile home
A compact grid of hue chips with counts. Scans in under a second and looks like a control panel — the least personal home screen of the five, in the app that holds the most personal things.
Trade-offs
  • 42+ colour tokens with AA proofs in both modes — and a new set every time an app ships. That is a permanent tax on the "more apps over time" promise.
  • Colour-blind users lose the primary wayfinding channel; a redundant shape or letter mark is mandatory, not nice-to-have.
  • 28px rows and 200% text scaling are in direct conflict; the density switch must be forced to comfortable above ~130%.
  • Cheapest motion and the most RN-faithful rendering of the five — borders and background steps port exactly.
D

Hearth

A warm house with many rooms: soft materials, generous space, and a different light in each room.

Hey · Craft · Things 3 · Airbnb DLS

Shell vs app
Identity is carried by temperature and shape — not colour, not type. Every app inherits the same radius language, the same warm neutral base and the same generous rhythm; each then gets a 6% surface wash in its own hue, so a room feels different on entry without ever being loud. The shell is a warm springboard of large soft tiles. Divergence is capped: an app may change its wash and its content layout, never its radii, shadows or spacing.
Colour
Light — #FDFBF9 / #F6F1EC / #EFE8E1, line #E3DAD1, text #241F1C / #6B615A / #9B9188.
Dark ("lamplight") — #17140F / #1E1A16 / #26221C, line #35302A, text #F3EDE5 / #B3A99D / #857B70.
One action accent: terracotta #B85C3C, dark #E08055. App washes at 6%: Docs #EEF0F6, Photos #F7EFEA, Cal #F1F4EE, People #F6EEF2, Tasks #EFF3EF, Files #EEF1F3, Chat #F7F1E8.

Typography
UI: Work Sans 15/1.5 (Avenir Next, -apple-system) with tabular figures switched on globally — there is no mono in this system, because mono reads as "technical" and the whole point is that it doesn't. Docs: Newsreader (Iowan Old Style, Georgia) 19/1.7 at 66ch. Section headers 13px/600 at .01em, sentence case, never uppercase. Calendar leans on weight and space rather than rules for structure — which is exactly where it strains.
Shape & depth
Radius 14 cards / 10 controls / 999 pills. Shadows are warm and doubled: 0 1px 2px rgba(60,40,25,.05) plus 0 10px 24px rgba(60,40,25,.06) — never grey, never black. Padding 20–24px; rows 44–52px; section gaps 32px. Borders appear only where a shadow can't (inputs, dividers).
Motion
Generous but never playful: 260ms, cubic-bezier(.34,1.06,.64,1) with overshoot capped at 4% and used only on sheets. Signature: the springboard tile expands with a corner-radius morph, 14px → 0, as it fills the screen. Press states scale to .985 over 90ms — the only scale-on-touch in any of the five.
Per surface
Mobile: home turf — springboard, sheets, thumb-reach, native-feeling. Desktop: the risk — without a density downshift (rows 36, radius 10, padding 16) it looks like a phone app blown up to 1600px. That downshift must be a token tier, not a per-screen fix. PWA: follows desktop above 900px, mobile below.
Stress test
Photos grid
The warm wash casts thumbnails, though less severely than Vellum's paper. Photos switches to a neutral #F4F2F1 viewer surface and 14px-radius thumbnails; the rounded corners on photographs are a taste call you will argue about for a month.
Docs
The most comfortable long-form of the five. Newsreader at 19/1.7 on #FDFBF9 with 24px gutters is genuinely pleasant to sit in for an hour.
Mobile home
Best case. Seven washed tiles with a recency line each — personal, calm, immediately legible, and the only springboard here that a non-technical person would call friendly.
Trade-offs
  • Density. Calendar's month view loses roughly a quarter of its visible rows to padding and radius; a "compact" tier for Calendar and Files is unavoidable and partially breaks the promise of one rhythm.
  • Warm dark mode goes muddy fast — the warmth must desaturate as lightness drops or #26221C reads as dirty brown.
  • Soft-consumer tone can undercut credibility in People (CRM) and Files.
  • Shadow-heavy on Android RN, where elevation is not a soft warm shadow; expect a flat-with-hairline fallback and a visible fidelity gap.
E

Ambient

Centraid is a grammar, not a skin: platform materials everywhere, one constant serif, one constant motion signature.

Apple's own app suite · Fantastical · Material You

Shell vs app
The shell is whatever the OS says a shell is: a vibrancy sidebar on macOS, a tab bar and sheets on iOS, Material 3 navigation on Android. Identity survives in exactly four invariants — the information hierarchy, the wordmark, the Docs serif, and a 200ms "unfold". App hues resolve into the platform's own accent machinery; on Android they surrender to dynamic colour entirely. This is the only direction where the answer to "what is constant" is behaviour.
Colour
Neutrals are the OS's, not ours. Centraid contributes one constant: mark ink #17322C (dark #7FBFAC).
Accent defers — macOS user accent, iOS #007AFF, Android dynamic colour, PWA fallback #17322C.
Clamp required: any platform-supplied accent is snapped to ≥4.5:1 against its own surface before use.
Typography
System stacks for UI — SF, Segoe UI Variable, Roboto — at each platform's own default sizes, because matching them is the point. The single constant across all three surfaces is the Docs serif: Literata (Charter, Georgia) 18–19/1.65. It is the one thing a screenshot from any device shares.
Shape, depth, motion
Platform values, not ours: 6px macOS, 10–12px iOS, 12–16px Material 3; platform elevation, platform curves. The only shared motion is the unfold — 200ms, the app's mark scaling into its header — implemented three times with three easings that happen to feel the same.
Per surface
Maximal divergence by design. This only works because the semantic-token layer already exists: roles stay identical and each renderer maps them to platform primitives. It is the strongest argument for the architecture you already have — and the direction most likely to expose any role that was secretly a value.
Stress test
Photos grid
Excellent and nearly free on every platform — you inherit a solved problem.
Docs
Consistent where it counts: the serif and the measure are identical everywhere. The surrounding chrome is not, so two screenshots don't obviously come from the same product.
Mobile home
Three different first impressions — an iOS grid, a dynamic-colour Material grid, a desktop sidebar. Each is comfortable; none is Centraid.
Trade-offs
  • Lowest distinctiveness by a wide margin. Centraid becomes memorable only through behaviour, which is a slow way to build a brand.
  • Three renderers drift fastest; QA surface roughly triples, and every OS release is a maintenance event.
  • Android dynamic colour can produce combinations nobody approved — a brand and AA risk unless clamped, and clamping partly defeats it.
  • In exchange: the highest native comfort, the lowest user friction, and the cheapest path to staying current as platforms move.

Recommendation

Prototype Vellum, with exactly one role borrowed from Atelier. It is the only direction whose thesis is about what Centraid holds — a personal archive — rather than about a UI genre. It is the cheapest to build and the kindest to a small team: no blur, no shadow system, no gradients, no per-app colour matrix, and a React Native rendering that costs essentially nothing. Its two real weaknesses are a warm cast on media and a hand-built dark mode, and only the first needs a system change.

The borrowed role is surface.gallery — a chroma-free surface any media-forward view may claim: the Photos grid and viewer, Files thumbnails, the image viewer inside Docs. Paper for reading, mat for looking. One token pair per mode, not a second theme.

Do not derive dark mode. Author "night desk" by hand — nine neutrals, seven re-tuned inks, one accent, roughly 34 values — and treat any attempt to invert the paper ramp as a bug.

Smallest proving slice — behind theme=vellum
  1. Shell home, desktop. The index. Proves that a typographic launcher can replace a springboard.
  2. Photos grid + one photo open. Proves surface.gallery and whether mat-next-to-paper reads as intentional or as a rendering bug.
  3. Docs read + edit at 68ch. Proves the serif/sans/mono split and marginalia-instead-of-toolbar.
  4. Mobile springboard + one app entry. Proves the index-as-list on 375px and the 220ms expand under React Native.

Light and dark for items 2 and 3 only. Nothing else — no Calendar, no People, no settings.

What would kill it. If the paper substrate tests as "nostalgic" rather than "personal"; if the index-as-list springboard is measurably slower to first tap than a grid; if the mat surface reads as a defect. All three are answerable inside the slice, in about two weeks.

Fallback. If Vellum fails on warmth or austerity, go to Bench for its shell strength — but only with the 42-token colour matrix budgeted and a non-colour wayfinding channel designed in from day one. Atelier is not a whole-product direction; it is a very good Photos app that would have to be argued into being a Docs app.
