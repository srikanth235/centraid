# `centraid-assist` — the on-device chat plane

Centraid is visual-first, and so is its chat: an answer is **one short line and result cards** — real rows (a task, a photograph, a ledger line, a person) that the app's own tile draws and taps through to. The model writes calls over eight flat tools; the runtime reads the vault, composes the line and draws the rows as cards; the apps draw the data. The model is a small language model that runs **on the phone** (llama.cpp, in [`crates/assist-llama`](../assist-llama/src/lib.rs), over a GGUF file the shell downloaded), and a write it proposes parks behind a confirm card until the member taps it.

This crate is the plane, and none of the engine or the vault. The vault side is [`crates/core`](../core/README.md)'s `assist` module (`Request::Assist`, `assist.proto`); the engine side is a [`Model`](src/model.rs) implementation.

| Module | What it owns |
| --- | --- |
| [`native`](src/native.rs) | The native tool runtime, moved here from `crates/nativetools` (#1088, R-1088-4): eight flat tools over a vault, one metadata table they are all generated from, the date-expression evaluator, observations, the system prompt and the `Session` that runs a call. The fine-tuning loop and the phone run this one runtime; `crates/nativetools` keeps its binary, the world seeder and the export. `native::transcript` renders a session as the one text the model is trained, scored and prompted on (`render.py` is its Python client), and `native::step::decode_step` writes one assistant message through any [`model::Model`] (the think guard, the call rendered from the think, one call per message; no grammar). It holds no vault and no path: every read and write goes through its [`Door`](src/native/door.rs) trait (paged table reads, typed commands, ids, the clock), which the harness implements over a vault file and the core implements over the phone's vault. It never writes SQL. A Locker item is a row like any other, and a sealed value is a channel the runtime keeps closed in the harness exactly as on the phone (#1135): its cells are a presence bit, a `reveal` or a secret to set ends the turn in a member action the member completes in Locker (`member`), and a secret the member typed is sealed by the door when its card is confirmed. Money is on in every session (#1099, R-1099-8). `Flags::writes` is the write policy: `Run` (the harness: the vault runs every step) or `Park` (the phone, [`park`](src/native/park.rs)): the steps of a turn's writes are applied to an in-memory patched copy of the world and the turn ends in one `PendingWrite` that `Session::confirm` runs through the door under a key per step and `Session::dismiss` (or any new message) drops (R-1088-2, R-1088-6, R-1088-10). Events are read in the person's own zone through `Door::events`, which is Agenda's `occurrences` (R-1088-8). |
| [`native_turn`](src/native_turn/mod.rs) | The native turn loop (#1088): `NativePlane` drives a `native::Session` the way the fine-tuning driver does (`user`, render the log, `decode_step`, `call_text`, up to `STEP_CAP` steps, a cancel checked between steps), with an `Activity` event per looking step. Every question about the vault takes this loop; a turn with an attachment takes the attached path instead (R-1088-9). A turn ends in the chat's existing `Card` (the one kind to app and entity table, [`cards`](src/native_turn/cards.rs): thirteen kinds into the seven apps, row routes for the kinds the shell opens and the app's home for the rest) and in a line the runtime composes from the final effect out of `copy/chat.json` ([`words`](src/native_turn/words.rs), the `SAID_` keys; a count, a value, the ask's question, a decline reason): no second generation (R-1088-10), except one: a turn that ends in a decline `out_of_scope` is answered with a few words from ONE free generation (`Plane::chat`: no tools, no grammar, 256 tokens, told it has read nothing and can send, call and change nothing), and falls back to the sentence when that fails, is stopped or says nothing. The words are the turn's answer, so a reopened thread shows them. [`log`](src/native_turn/log.rs) is the conversation the model reads, rendered with `native::transcript`. A `NativeChat` is one chat's session in memory; the caller opens a fresh one for a reopened thread, a retry or a failed turn, and between kept turns the session's clock follows the request (`Session::set_clock`: the person's now and zone, the world read again). The session runs `Writes::Park` (R-1088-2): a write is planned against a patched world and the turn ends in one pending write that has touched nothing, said as "Proposed: …" and sunk as `Event::Pending(PendingCard)`, which the core puts on the wire (`AssistPending`, on the stream and on the answer); `NativeChat::confirm` runs its steps through the door, one key per step, and `dismiss` or a new message drops it. The card the member reads is built from the runtime's structured facts, not from the text the model was shown: each parked call keeps a `RowChange` per row (kind, title, the fields that moved old to new, the links gained or lost), and [`pending`](src/native_turn/pending.rs) says it in the words of `copy/chat.json` (`SAID_STEP_*`): one line per row, `destructive` for a delete, removal, cancel or settle. `crates/nativetools/tests/park_card.rs` holds every mapped write's line to the row it changes. A reveal never parks: it ends the turn in a member action card the member completes in Locker; a secret the member typed parks masked and the door seals it on confirm (`Confirmed::Locked` when Locker is shut, the card staying). |

## What a turn is

1. **Steps.** The model writes one message at a time — a think, then one call — and the runtime runs it (`find`, `search`, `open`, `compute`, `act`, `answer`, `ask`, `decline`), up to `STEP_CAP` messages, a stop checked between them.
2. **Cards and a line.** The turn ends in the rows it found, drawn as cards (the first six), and a line composed from the final effect out of the chat's copy. A write ends in a pending card instead, and nothing is written until the tap.
3. **A free reply** for a decline `out_of_scope`, in place of the canned sentence.

A turn with an attachment skips all of it: one streamed answer over the photograph or the document ([`attach`](src/attach.rs)).

## What stops this crate doing more

| Not allowed | What stops it |
| --- | --- |
| SQL, in any form | `sql-confinement` scans this crate; the runtime reaches a vault only through a `Door` |
| A chat scoped to Locker | `App::SCOPES` and `roster::scopes` leave it out; `app::tests::locker_is_a_card_domain_and_no_scope` |
| A sealed value in a prompt, a tool result, an event, the stored thread, the journal or the index | `World::load_in` reads each sealed cell as `<cell> IS NOT NULL` (a presence bit) and nothing else, `plan_reveal` ends a reveal in a member action that names the offer and never a value, and a secret the member typed is `«sealed»` in the log and the stored question once its card is parked (`crates/core/tests/assist_channel.rs`, which plants a marker in every sealed cell, a sealed custom field and a passkey key and searches every one of those places; `crates/nativetools/tests/locker_parity.rs`) |
| A sealed value reached through a command or a page | The chat's door runs as the owner device and the vault withholds nothing from it (#1135): the door seals a typed secret in `run_keyed` before the vault sees it and serves no sealed column but as a presence bit, and `page::withholds_sealed_value` refuses a page that names a sealed column but as its presence bit (`crates/core/tests/assist_door.rs`, `crates/vault/tests/locker_plaintext_gate.rs`) |
| A write on the phone before the member's tap | `Flags::writes` = `Park`: no step reaches the door until `Session::confirm`, which refuses a stale card (`crates/nativetools/tests/park_confirm.rs`); the patch is held to the vault by `tests/park.rs` and `experiments/toolchat/native/authored/park_oracle.py`; the core's door refuses a bare `run` |
| A claimed action in the free reply | the free reply's system turn says it cannot send, call or change anything, and `prompt::tests::the_free_reply_is_told_it_can_act_on_nothing` pins it; it reads no vault, so it can state no fact about one |
| A persisted transcript | a chat's session is memory; there is no table and no file (R-1088-10) |
