# `centraid-assist` — the on-device chat plane

Centraid is visual-first, and so is its chat: an answer is **one short line and result cards** — real rows (a task, a photograph, a ledger line, a person) that the app's own tile draws and taps through to. The model writes calls over eight flat tools; the runtime reads the vault, composes the line and draws the rows as cards; the apps draw the data. The model is a small language model that runs **on the phone** (llama.cpp, in [`crates/assist-llama`](../assist-llama/src/lib.rs), over a GGUF file the shell downloaded), and a write it proposes parks behind a confirm card until the member taps it.

This crate is the plane, and none of the engine or the vault. The vault side is [`crates/core`](../core/README.md)'s `assist` module (`Request::Assist`, `assist.proto`); the engine side is a [`Model`](src/model.rs) implementation.

| Module | What it owns |
| --- | --- |
| [`native`](src/native.rs) | The native tool runtime, moved here from `crates/nativetools` (#1088, R-1088-4): eight flat tools over a vault, one metadata table they are all generated from, the date-expression evaluator, observations, the system prompt and the `Session` that runs a call. The fine-tuning loop and the phone run this one runtime; `crates/nativetools` keeps its binary, the world seeder and the export. `native::transcript` renders a session as the one text the model is trained, scored and prompted on (`render.py` is its Python client), and `native::step::decode_step` writes one assistant message through any [`model::Model`] (the think guard, the call rendered from the think, one call per message; no grammar). It holds no vault and no path: every read and write goes through its [`Door`](src/native/door.rs) trait (paged table reads, typed commands, ids, the clock, sealed cells), which the harness implements over a vault file and the core implements over the phone's vault. It never writes SQL. `Flags::locker` is the Locker policy: on for the harness, off on the phone, where no Locker table or sealed column is read and a call that names a Locker kind or `reveal` ends in `decline sealed_egress` (R-1088-3). `Flags::writes` is the write policy: `Run` (the harness: the vault runs every step) or `Park` (the phone, [`park`](src/native/park.rs)): the steps of a turn's writes are applied to an in-memory patched copy of the world and the turn ends in one `PendingWrite` that `Session::confirm` runs through the door under a key per step and `Session::dismiss` (or any new message) drops (R-1088-2, R-1088-6, R-1088-10). Events are read in the person's own zone through `Door::events`, which is Agenda's `occurrences` (R-1088-8). |
| [`native_turn`](src/native_turn/mod.rs) | The native turn loop (#1088): `NativePlane` drives a `native::Session` the way the fine-tuning driver does (`user`, render the log, `decode_step`, `call_text`, up to `STEP_CAP` steps, a cancel checked between steps), with an `Activity` event per looking step. Every question about the vault takes this loop; a turn with an attachment would take the attached path instead (R-1088-9), but the shipped build takes no attachment (R-1088-19). A turn ends in the chat's existing `Card` (the one kind to app and entity table, [`cards`](src/native_turn/cards.rs): thirteen kinds into the seven apps, row routes for the kinds the shell opens and the app's home for the rest) and in a line the runtime composes from the final effect out of `copy/chat.json` ([`words`](src/native_turn/words.rs), the `SAID_` keys; a count, a value, the ask's question, a decline reason): no second generation (R-1088-10), a decline `out_of_scope` included: it is the canned sentence, because the shipped model writes tool calls for plain prose and a free reply would show that (R-1088-19). [`log`](src/native_turn/log.rs) is the conversation the model reads, rendered with `native::transcript`. A `NativeChat` is one chat's session in memory; the caller opens a fresh one for a reopened thread, a retry or a failed turn, and between kept turns the session's clock follows the request (`Session::set_clock`: the person's now and zone, the world read again). The session runs `Writes::Park` (R-1088-2): a write is planned against a patched world and the turn ends in one pending write that has touched nothing, said as "Proposed: …" and sunk as `Event::Pending(PendingCard)`, which the core puts on the wire (`AssistPending`, on the stream and on the answer); `NativeChat::confirm` runs its steps through the door, one key per step, and `dismiss` or a new message drops it. The card the member reads is built from the runtime's structured facts, not from the text the model was shown: each parked call keeps a `RowChange` per row (kind, title, the fields that moved old to new, the links gained or lost), and [`pending`](src/native_turn/pending.rs) says it in the words of `copy/chat.json` (`SAID_STEP_*`): one line per row, `destructive` for a delete, removal, cancel or settle. `crates/nativetools/tests/park_card.rs` holds every mapped write's line to the row it changes. A Locker call never parks: the session declines it `sealed_egress`. |

## What a turn is

1. **Steps.** The model writes one message at a time — a think, then one call — and the runtime runs it (`find`, `search`, `open`, `compute`, `act`, `answer`, `ask`, `decline`), up to `STEP_CAP` messages, a stop checked between them.
2. **Cards and a line.** The turn ends in the rows it found, drawn as cards (the first six), and a line composed from the final effect out of the chat's copy. A write ends in a pending card instead, and nothing is written until the tap.

There is no free reply: a decline `out_of_scope` is the canned sentence. A turn with an attachment would skip all of it, one streamed answer over the photograph or the document ([`attach`](src/attach.rs)); the shipped build refuses it (R-1088-19) and a later model (S3) brings both back.

## What stops this crate doing more

| Not allowed | What stops it |
| --- | --- |
| SQL, in any form | `sql-confinement` scans this crate; the runtime reaches a vault only through a `Door` |
| Locker in a prompt, a tool list or a scope | `App` has no such variant; `app::tests::locker_is_in_no_scope` |
| Locker on the phone surface | `native::Flags::locker` off: `World::load_with` skips the Locker table and its sealed columns, and `Session::locker_off_decline` ends any call naming a Locker kind or `reveal` in `declined: sealed_egress` (`crates/nativetools/tests/locker_off.rs`) |
| A write on the phone before the member's tap | `Flags::writes` = `Park`: no step reaches the door until `Session::confirm`, which refuses a stale card (`crates/nativetools/tests/park_confirm.rs`); the patch is held to the vault by `tests/park.rs` and `experiments/toolchat/native/authored/park_oracle.py`; the core's door refuses a bare `run` |
| Words the model writes to the member | only the question of an `ask` is shown: the line is composed by the runtime from the final effect (R-1088-10), and a decline `out_of_scope` is the canned sentence (R-1088-19, `crates/core/tests/assist_native.rs`), so no reply can claim an action or state a fact about the vault |
| A persisted transcript | a chat's session is memory; there is no table and no file (R-1088-10) |
