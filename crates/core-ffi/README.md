# `centraid-core-ffi`

Five symbols and a contract ([#1020](https://github.com/srikanth235/centraid/issues/1020) wave 2, lane D2, ruling D-1020-D2-3).

```c
int32_t centraid_open      (const uint8_t *config, size_t len, Handle **out);
int32_t centraid_call      (Handle *h, const uint8_t *req, size_t len,
                            uint8_t **out_buf, size_t *out_len);
int32_t centraid_next_event(Handle *h, uint32_t timeout_ms,
                            uint8_t **out_buf, size_t *out_len);
void    centraid_free      (uint8_t *buf, size_t len);
int32_t centraid_close     (Handle *h);
```

**Read [`CONTRACT.md`](CONTRACT.md) before calling any of these.** It is normative, it has ten clauses, and **each clause has a test** in `tests/contract.rs` named after the clause. A shell's memory safety depends on claims that are not visible in the signatures above.

## Why five

Every symbol is a thing three shells must wrap, three build systems must see, and compatibility must hold for. A per-verb ABI would be forty symbols that change whenever a verb does; one `call` over encoded bytes moves that churn into the protobuf schema, where `buf breaking` already governs it.

## Why bytes and not structs

Every payload is a protobuf-encoded `centraid.core.v1.Envelope`. A C struct would need a stable layout per message, per platform, per compiler — and a shell that got the padding wrong would read garbage rather than fail to link. Bytes have one layout.

The `open` configuration is the exception: UTF-8 JSON, because it is read once at startup by a human-written call site and being able to log it verbatim is worth more than the encoding.

## The header

`include/centraid.h` is **committed** and generated by cbindgen. A Swift or Kotlin build that generated it would need cbindgen and a Rust toolchain on every developer's machine, and the header is the one artifact a shell author reads. `tests/symbols.rs` asserts that regenerating it is a no-op.

```sh
CENTRAID_WRITE_HEADER=1 cargo build -p centraid-core-ffi
```

## Tests

| File | What it proves |
| --- | --- |
| `tests/contract.rs` | one test per `CONTRACT.md` clause, through the C entry points |
| `tests/symbols.rs` | exactly five exported symbols in the built `cdylib`; the names resolve through `dlopen`; the committed header is current |
| `tests/marshal_miri.rs` | the unsafe surface under miri |
| `tests/spike.rs` | the C harness, and the event path's throughput |

```sh
cargo test -p centraid-core-ffi
nm -D --defined-only <target>/debug/libcentraid_core_ffi.so | grep ' T centraid_' | wc -l   # 5
```

Two different questions about "five", both asked: the xtask rule `abi-five-symbols` counts the **declarations** in this crate's source, and `tests/symbols.rs` counts what the linker **exported**. A symbol can be declared and not exported, or exported by a dependency, and only the artifact settles it.

## Miri

```sh
RUSTUP_TOOLCHAIN=nightly cargo miri test -p centraid-core-ffi --test marshal_miri
```

Miri cannot run this crate's other tests: they open a vault, SQLite is a C library, and miri does not execute foreign code. So **the unsafe surface is confined to `src/marshal.rs`** — that confinement exists for this test. What miri covers: the slice reconstruction, the out-pointer writes, the `Vec` → raw → `Vec` round trip `centraid_free` inverts, the null-pointer refusals, the empty-buffer corner, and a thousand round trips against miri's leak check.

## The binding spike, host half (D-1020-D2-7)

`spike/spike.c` is a C harness; `spike/jna/` is a JVM harness using JNA (not the Foreign Function & Memory API — FFM is final in JDK 22 and Android's minimum is nowhere near it, so an Android shell will use JNA or JNI for years, and measuring the binding the product will ship is the point of a spike).

```sh
cargo test -p centraid-core-ffi --test spike -- --nocapture

cargo run -p centraid-core-ffi --bin spike-fixture -- /tmp/spike
cd spike/jna && CENTRAID_LIB_DIR=<target>/debug \
  CENTRAID_VAULT=/tmp/spike/spike-vault.db \
  CENTRAID_REQUEST=/tmp/spike/request.bin gradle -q run
```

The spike fixes the ABI's **shape** before three shells are written against it. The numbers are `ci-linux-x64-4c` numbers and a floor; the device half (cinterop on iOS, JNA on Android, the Swift wrapper) is wave 3 lane E's and an owner hand-off. The measured numbers are in the receipt.
