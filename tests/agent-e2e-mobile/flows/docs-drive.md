# docs-drive

**Goal:** prove the phone's Docs seat end to end against the real seeded drive — the All shelf counts the vault's own documents, a row opens the reading surface, a band tap from that pushed route returns to the stack's home with a different shelf named rather than pushing a second copy of it, and (on Android) **a document still opens with the gateway out of reach**.

**Setup:** `ctx.ensureDemo("docs")` runs before pairing so the initial replica clone already holds the deterministic drive (`packages/blueprints/apps/docs/seed.js`: two folders, three documents, one of them starred, tagged, and carrying a second version). The flow then pairs via `ctx.configureGateway()`, which reuses the nightly paired profile when the suite runner sets `MAESTRO_REUSE_PAIRED_STATE=1`.

**Steps:** open Docs from Home's launcher tile, observe the All shelf's own standing status sentence and two seeded titles, open the packing list, observe the reading surface's back control and its changed-byline, then tap **Folders** in the band FROM the pushed reading route and observe the Folders shelf's own status and a seeded folder.

**Expectations:**

1. **The All shelf counts the seeded drive.** `allStatus()` (`apps/mobile/src/apps/docs/docs-copy.ts:17`) is published by this shelf alone; a zero there means the drive read never reached the replica.
2. **The rows are the vault's rows.** `Tahoe packing list` and `Renters insurance policy (sample)` are `DocRow`'s accessible names (`DocRow.tsx:69`), taken straight from the seeded titles.
3. **A row opens the reading surface.** `docs-breadcrumb`, whose label names its destination (`Back to All` — `DocsShelfHeader.tsx:34` with `DocumentRead.tsx:69`'s `backTo="All"`), is rendered only by `DocsShelfHeader`, which no shelf on `DocsHome` draws — so it cannot pass on the shelf that was tapped from.
4. **The band pops, it does not push.** Tapping `docs-band-folders` from the pushed reading route lands on `DocsHome`'s Folders shelf (`DocsScreen.tsx`'s `popTo`), proved by `foldersStatus()` (`docs-copy.ts:22`) plus the seeded `Travel` folder (`DocsFoldersView.tsx:139`) — and by `docs-breadcrumb` being **gone**. That negative is asserted on the handle rather than on the words: an `assertNotVisible` on copy passes forever the day the copy is re-worded, which is precisely what `scripts/lint-mobile-testids.mjs` exists to keep out (it holds the other end of the contract, so the id cannot quietly stop naming anything). The copy negative is kept beside it.
5. **Android only — a document whose bytes are already here still opens offline** ([#890](https://github.com/srikanth235/centraid/issues/890) W4). Airplane mode on, force-stop, relaunch, reopen Docs: the All shelf still counts the drive (titles, folders, filing and stars are replica reads and owe the gateway nothing), the caption swaps to `CAPTION_OFFLINE` (`view-copy.ts:82` — a caption still promising "on this gateway" while it is unreachable would be the one untrue sentence on screen), `docs-row-first` opens, and the reading surface draws its byline. The row never takes the `will not open` mark that `rowStateMark()` gives a row whose bytes are elsewhere. Restored in a `finally`.

**On "pin a document, then open it offline."** There is no pin to take on this corpus, and that is the seat working rather than the seat missing something: every document `packages/blueprints/apps/docs/seed.js` writes carries its bytes as an inline `data:` URI (#296), so `useDocumentOfflinePin` (`offline-pin.ts:129`) refuses the toggle and states `This document's text travels in the replica, so it already opens offline.` instead of offering a control that would copy bytes to where they already are. The pin half of the claim is therefore that sentence — asserted online, on the reading surface — and the offline half is what the sentence promises, checked above. A live pin/unpin journey needs a seeded document with gateway-side bytes, which is a fixture change, not a flow change.

**Verdict:** PASS only if all five hold. A full All shelf above a `0 folders …` line, a `Folders` tap that leaves the pushed header on screen, or a document that will not open with the radio off, is a real defect and must fail here.

**Deliberately not asserted:** the packing list's second-version body line (`Tire chains …`). The reading view renders the whole markdown body as ONE multi-line text node, and Maestro anchors a text selector to the whole node with a Java regex whose `.` does not cross newlines — a `.*Tire chains.*` selector would be red for a reason unrelated to its claim. Proving that the replica carries the CURRENT version's bytes needs either a single-line surface or an on-disk read; it is recorded as an open gap rather than cemented as a fragile selector.
