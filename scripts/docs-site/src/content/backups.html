Chapter 4 · backups

A backup is real when the gateway acknowledges it.

Your phone is the vault and the only writer. It seals backup data before sending it directly to a gateway you control. Recovery uses your recovery key and a reachable gateway.

§01 · what is backed up

Records first. Original bytes may wait.

The phone reports what each gateway acknowledged. Records acknowledged with all their content hashes confirmed can be reported as backed up. If records were acknowledged while files still wait, the Backup screen says so with the count and reason; that is not a complete backup.

Original photos and videos are separate from vault records. Their transfer follows your backup rule: Wi-Fi by default, optional cellular transfer for photos, and video originals never cross a metered link. A manual backup sends records over a metered link, not heavy originals.

§02 · connect a gateway

Pair directly from Backup.

Run centraid-gateway serve --data-dir DIR on a machine you control, then scan its fresh QR in the phone's Backup screen and compare the safety number. The gateway stores sealed data and cannot read it. You can pair more than one gateway.

The phone works offline. Backup runs in the foreground and in background windows the operating system grants. Force-quitting stops background work until the next launch. A gateway outage does not stop local use.

§03 · recovery key

Keep the 24 words safe.

Your recovery key is its 24 words. They derive the keys needed to open your vault backups. Depending on the platform and settings, the operating system may also keep an encrypted seed in its secure key store. That can help a replacement phone on the same OS account; it is optional custody, not a substitute for keeping the words safe.

There is no recovery-kit JSON, provider API key, or hosted recovery service.

§04 · restore

Restore checked records to a new phone.

Install a compatible Centraid phone build and choose Restore my vaults and enter your recovery key's 24 words unless the phone can use a seed already held in its secure key store. Choose a reachable gateway. If the original pairing QR has expired or been used, ask the gateway operator to print a fresh pairing code with centraid-gateway pair --data-dir DIR.

The phone checks backup records before it claims the next writer position. A successful restore recovers the checked vault and previews. An original file acknowledged by the gateway can be fetched from that gateway later; an original that never reached a gateway may be unavailable after the source phone is lost. If the restore cannot establish that it has the newest backup, it asks before claiming anything.

A takeover invalidates the old phone's gateway tokens. An offline old phone learns about takeover only when it next contacts a gateway, so remote revocation is not immediate while it is offline.

§05 · check and retention

A check reports what it read.

Check my backup restores records from each reachable gateway into a scratch copy, verifies files by name and opens a bounded sample. The screen distinguishes a backup that opens, one with a problem, and one that was not checked. It needs free space for the vault size plus one tenth and 64 MiB.

The phone keeps seven daily, four weekly and six monthly snapshots, where those periods contain snapshots; the newest is always retained. Deletion starts only after no kept backup needs the file. Once the phone asks the gateway to delete it, the gateway holds that copy for at least seven days before purging it. If the gateway is paused or offline, it may keep the copy longer. Copies on backup devices go when old backups age out; there is no exact deletion deadline to promise.

For implementation details, see the repository's backup phone rules and gateway README.

§06 · limits

Connectivity changes backup, not your vault.

Only a reachable gateway can acknowledge a backup. Phone background work depends on the operating system; a stopped or force-quit app cannot promise continuous transfer. If a phone is replaced, the restored phone becomes the writer after checks and a successful claim. A former phone may still have local data, but its next gateway contact reports that it was superseded.

Keep the gateway's data directory backed up as an operator would any important machine data. The directory contains the gateway identity and sealed objects; it does not contain the keys that open the vault.
