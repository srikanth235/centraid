§01 · Thesis & system map

One life. One model. Apps become projections.

Your life is currently modeled by whoever shipped the app: your heart rate belongs to a watch vendor, your invoices to an accounting SaaS, your relationships to a contacts silo. Centraid inverts the ownership. A single, person-owned, self-hostable ontology holds the canonical record — identity, place, time, money, content, activity, relationship, classification — and every familiar app becomes a thin projection over it. A personal agent operates across the whole model through one typed, consent-governed surface.

The product is the substrate, not the apps. Familiar interfaces lower adoption cost; one shared model removes the silos; the access and agent planes make it sovereign and agent-ready. Read it top-down as a user, bottom-up as an architect: surfaces render projections; projections read extensions; extensions never fork identity — they hold a foreign key into the spine. Nothing crosses a layer without passing the access plane, and agents only touch the model through the command surface.

§03 · Detailed schema

The logical model, generated from data

Ten schemas — the canonical core, seven life domains, and the two planes (access, agent) — rendered from a single JavaScript array of table definitions generated from the shipping DDL and held equal to it by a test (packages/vault/src/schema/ontology-doc.test.ts). Every column shows its logical type, constraints, foreign-key target, and the standard it conforms to. This is the artifact a team would implement. In a running vault the same model is explorable live, over the real rows: Operations → Vault Atlas renders it as Kinds (a per-pack census), Relations (the reference graph centred on core.party) and Browse (a consent-gated, journalled table editor).

Machinery bands — named, not described

Eight more bands ride the same file but hold plumbing, not life data: the gateway names them so a member can see what exists, and never fabricates a description for them (issue #883, ruling O-label). Their DDL lives beside the packs in packages/vault/src/schema/. The audit and ledger bands are declared by their modules rather than by the entity registry, because their physical names do not follow <band>_<table> — that band list is the same one the export and the replica exclude by.

Physical target — local-first SQLite

STRICT tables throughout; primary keys are TEXT UUIDv7 (time-ordered, offline-mintable); money is never floating point — fixed-scale integers (amount_minor INTEGER + ISO 4217 currency); all timestamps are TEXT ISO-8601 UTC with named IANA zones stored separately; structured columns use json1 with CHECK(json_valid(…)). Append-only by TRIGGER, not by convention: every table of the audit band refuses UPDATE and DELETE in the engine, so an append-only claim cannot be quietly broken by a caller with a connection. Mutable rows keep one created_at / updated_at shape — NOT NULL with a default, touched by trigger — declared per entity rather than adopted table by table (#916, ruling R8). SQLite has no row-level security, so access is enforced in the gateway: every query and every typed command is evaluated against access.grant_scope before it touches a connection, and every allow/deny emits an access.receipt. Bytes behind content_uri replicate via ordinary blob tooling — they are rented; the rows here are owned.

Physical layout — ONE file, three bands. Everything is vault.db (#916): the model, the append-only audit band (access.provenance, access.receipt, agent.command_invocation / invocation_check / evidence / explanation) and the ledger band that holds conversation transcripts and automation state. The second file was a size argument, and it cost correctness: a receipt written in another file is not atomic with the mutation it describes, so a crash between the two left the model changed and the evidence missing — and every pointer across the seam had to be a gateway promise instead of a foreign key. One file means one ACID transaction for provenance, core rows and domain rows; it means core.entity_revision.invocation_id is a real key; and the size argument is answered where it belongs, by retention: each band declares its own window (audit 365 days, ledger 90) in one place, and an archival pass proves custody before it prunes. The bands are excluded from the portable export, the device replica and the support bundle by band, not by table list, so the evidence stays local without anyone maintaining a second list. Because every table is schema-qualified and only the gateway holds connections, a later per-domain split (one file per schema via ATTACH) remains a mechanical migration held in reserve — justified only by a concrete trigger such as a separate encryption key for a pack, media metadata dominating backup time, or multi-device sync conflict reduction. An app that needs real tables of its own declares them as an ext band inside the same vault.db (ext.<app_id>.*, issue #286 — the per-app appext_<app_id>.db file is retired): its tables may hold FKs into the canon, the canon never references them, and uninstall is revoke grant + retain-then-purge the band.

Since #883 — the #916 close of v0. The model above is what a full re-review left standing, and the changes were structural rather than cosmetic. One supertype: every entity row is also a core.entity row, so a pointer pair is a composite foreign key the engine enforces and cascades — the poly-ref registry, its sweep and the class of dangling-pointer bug it managed are gone, and nine projections that are parts of an entity rather than entities keep only their parent key. Dormant domains left: health, finance, the observation spine, the learn loop (agent.correction / judgment), registered app views, export jobs and availability rules had DDL and typed commands but no producer and no consumer, so O-domains’ own test was applied evenly; social.thread and message stayed, because they have writers. One version scheme: the file (PRAGMA user_version) and the command contract carry the version; the per-row ontology_version stamp two tables happened to have is gone. Lifecycle is declared: each entity says append-only, mutable, trash or machinery, and a test — not a habit — holds the timestamps and the trash pair to it. The consent plane became the access plane, its scopes now naming one dotted entity instead of four encodings of “which entity”. Money states its currency on the group, the expense and the settlement; recurrence exceptions key on the series’ wall clock instead of a resolved UTC instant, and both a template’s splits and an exception’s attendees are rows instead of JSON. The version is 1.0, and the ladder is one rung: the schema modules carry the shipping shape, and a pre-1.0 vault is recreated rather than migrated.

Stance — the runtime store stays outside the graph. Conversation transcripts and automation run summaries live in the ledger band of vault.db (formerly a standalone transcripts.db, then a second file), deliberately not in the model (issue #280: the vault directory is the sovereign unit; the runtime store is operational state). Sharing a file is not joining the graph: the band is excluded from the export and the replica, and no canonical row references it. They are activity-shaped, so the pull to join them will grow — the decision of record is: they stay out until an agent query genuinely needs them, and the door in is a thin core.activity projection, never soft TEXT joins from canonical rows. That band is now bounded (#438): idle turn-ranges digest into conversation_digest, seal into the vault blob CAS indexed by conversation_archive, and the raw turns prune only once custody is proven — reopening a conversation lazily rehydrates from the archive, and Insights read the digests either way. Bounding the runtime store is orthogonal to keeping it out of the graph; both hold.

Stance — version brokering waits for v1. A command contract stamps ontology_version (now 1.0) and the gateway enforces EQUALITY, not R07's compatibility windows: pre-release there is no data to migrate and no third-party contract to keep rendering, so a mismatch means a stale registration. Rows carry no stamp at all (#916, ruling ONT-04) — a version two tables out of seventy happened to carry was a vestige, not a scheme. The windows return when v1 ships; until then the ladder itself is one rung — schema modules carry their final shape and a dev vault is recreated, not migrated.

The gateway contract — everything SQLite cannot enforce, in one auditable choke point (elaborated in §10)

SQLite has no row-level security, no stored procedures and no server, so the gateway is the sole holder of connections — locally and hosted — and every request passes one pipeline: identity → consent → contract → execution → evidence. Identity: every caller authenticates as a row (access.app.signing_key, access.agent, access.device); no credential, no path to data. Access: an active access.grant must exist, its grant_scope rows must cover the entity and verb, row filters and field masks are applied, declared purpose is checked against access.policy, and command risk against the app’s risk_ceiling — any step may deny, and a deny is a receipted outcome, not an exception. Contract: writes are never rows, only typed commands — payloads validated against JSON-Schema, preconditions evaluated as real queries and recorded as agent.invocation_check rows before anything mutates, postconditions verified after. Execution: the gateway owns write ordering, the ACID boundary — the invocation, the rows and the receipt commit together, in one file — idempotent replay off UUIDv7 keys and external_id uniqueness, and what declarative constraints still cannot express: Σ-invariants, membership rules and lifecycle refusals. Entity pointers are no longer on that list; since #916 they are composite foreign keys the engine enforces. Evidence: every read and every command, allowed or denied, emits an access.receipt; every write stamps access.provenance; outcomes hang agent.evidence and agent.explanation — unskippable because there is no other door.

Standing duties (not request-shaped): parking high-risk invocations and routing owner confirmations (the pause between draft and send is gateway state); the revocation cascade — sessions killed, projections scrubbed, the app’s ext band retained then purged, instantly; lifecycle sweeps (purge_at deletions, retention policy, share and grant expiry), each row in its own transaction so one refused purge cannot wedge the pass; the archival pass that holds the audit and ledger bands to their declared retention windows and proves custody before it prunes; ingest discipline at the vault border (dedupe on external_id, per-row provenance, handle→identity resolution); ontology version equality per command contract (R07’s compatibility windows return at v1); and file custody — attachments, WAL checkpoints and shipping, backups, blob custody and the sealed-column reseal sweep. Polymorphic-ref cleanup is no longer a duty: the core.entity supertype made every pointer pair a composite foreign key, so the engine cascades what the sweep used to chase.

What the gateway must not do: no domain logic (state machines and command implementations are domain-owned; the gateway hosts and checks them), no reasoning (planning and judgment belong to the agent; the gateway checks declared conditions, it does not form intentions), no rendering (projections are app-side), no byte custody (content_uri targets are brokered, not stored). The trade is explicit: engine enforcement is exchanged for a single testable choke point — so a gateway bug is a sovereignty bug, which is exactly why it stays a thin, mostly declarative interpreter over the consent and capability tables, with the model, not the code, as the source of truth about what is allowed. The corollary #916 made explicit: raw SQL outside the vault package is linted against a reasoned allow-list (bun run lint:vault-sql), because a second door is exactly as bad as no door.

§04 · Modeling principles

Five commitments the model never breaks

Everything in §03 is a consequence of these five decisions.

P1

Shared where meaning is stable, local where behavior differs

“A person,” “a place,” “money moved,” “something was measured” — these mean the same thing in every app, so they live once, in the core, carrying identity and history. What differs per domain is behavior: a photo’s capture context, an expense’s split method, a task’s recurrence anchor. Domains add thin typed extensions — a media.asset holds a FK to the content_item it is — and never fork identity into a parallel copy.

P2

Own the meaning, rent the bytes

The durable asset is the graph: rows, relationships, provenance, classifications. Pixels, PDFs and audio sit behind content_uri with a sha256 integrity hash — storable on any disk, NAS or object store, and re-homeable without touching a single relationship. Losing a blob store loses bytes you can re-fetch; losing the model would lose the meaning. So the model is what you own.

P3

Consent travels with the data

Sovereignty is a plane, not a settings page. Apps hold scoped, expiring grants (purpose-bound per W3C DPV, expressed as ODRL-style rules); shares and retention are policy rows; every access decision leaves a Kantara-style receipt chained to W3C PROV provenance, in an audit band the engine holds append-only. A grant is evaluated on every read and action — consent is data the data carries.

P4

Agents act through commands, never tables

The agent plane exposes one uniform surface — discover, query, reason, act, verify, explain — where every action is a typed command (an MCP tool) with declared pre- and postconditions. Agents never hold a write handle to a table: they invoke agent.commands that are access-checked, executed transactionally, provenance-stamped and receipted. The correction-into-judgment loop this principle once promised had commands and no caller, so it left the model rather than sit in it as dormant DDL (#916).

P5

Entity-scoped meaning joins, surface-scoped state rides

An owner judgment about an entity — starred, a memo, a relationship — means the same thing in every app that renders the entity, so it lives in the universal joins (core.tag, knowledge.annotation, core.link), keyed to the canonical row. State that only means something inside one surface — pinned-to-top, sort order, a cover image — rides the domain’s own rows. A flag never mints a column, a row or a table — not even a mirror of one: Gmail stars ≠ Drive stars ≠ Photos favorites is a fragmentation artifact of separate databases, not a design to copy. Reference products are evidence, not authority.

§10 · The gateway

One door. Every request. No exceptions.

SQLite has no row-level security, no stored procedures and no server — so everything an enterprise database would enforce about who may do what lives in exactly one place. The gateway is the sole holder of connections, locally and hosted: apps, agents, workflows and generated views never see a file handle. Every request — human tap, agent plan, cron trigger — walks the same five-stage pipeline. Click a stage to inspect what it checks, which tables it consults, and what a denial looks like.

Standing duties — the work between requests

Not everything the gateway does is request-shaped. Eight duties run on schedules, triggers, or lifecycle events — each one still writes receipts and provenance like any caller would.

Two duties this page once listed are gone rather than dormant (#916): the view service, because no app ever registered a view, and polymorphic-ref cleanup, because the entity supertype turned every pointer pair into a foreign key the engine cascades.

Retention & archival

Holds the two append-heavy bands to the windows they declare — audit 365 days, ledger 90 — by sealing what leaves into the blob CAS, proving custody, and only then pruning the live rows. One window per band, declared in one place, so “the vault stays small” is a mechanism rather than a hope.

Confirmation routing

Parks any invocation above the caller's risk_ceiling, surfaces the confirmation to the owner, then resumes or expires it. The pause between draft and send is gateway state.

Revocation cascade

Revoking a grant is instant and total: sessions killed, materialized views invalidated, the app’s ext.<app_id>.* band retained then purged (issue #286). The §11 success test — projections go dark, model and receipts remain — is this cascade.

Lifecycle sweeps

Executes purge_at deletions and lapses shares, authorities and grants at expires_at. Each row is its own transaction with a named skip in the receipt, so one purge the engine refuses cannot wedge every later pass — the shape the #916 review found and fixed.

Ingest customs

The border post: import batches dedupe on external_id, stamp per-row provenance, and resolve raw handles to identities via party_identifier — OFX, ICS, vCard and IMAP all enter the same way.

Export & portability

Owns the lossless round-trip: any scope of the model and its bytes out as verifiable files, and back in with identities intact — the test that gates every new domain.

Version brokering

The ontology versions explicitly (R07), in two places and no others: the file (PRAGMA user_version) and the command contract. Pre-v1 the gateway enforces equality — a contract on another ontology_version is refused as a stale registration; negotiated compatibility windows return when v1 ships.

File custody

One SQLite file and its WAL: checkpointing, backup coordination, backup and WAL shipping, blob custody, and the sealed-column reseal sweep — which is also what makes a portable export safe to import, since import re-seals under the target’s own key and never installs a foreign one (#630).

The negative space — what the gateway must never become

The trade is explicit: engine enforcement exchanged for a single testable choke point. A gateway bug is a sovereignty bug — which is exactly why it stays a thin, mostly declarative interpreter over the access and capability tables. Four things are permanently out of scope:

No domain logic — state machines and command implementations are domain-owned; the gateway hosts and checks them No reasoning — planning and judgment belong to the agent; the gateway checks declared conditions, it does not form intentions No rendering — projections are app-side; the gateway serves rows and outcomes, never pixels No byte custody — content_uri targets are brokered, not stored; meaning is owned here, bytes are rented elsewhere

§11 · Implementation rules

Ten hard rules, then a first boundary

The stance in §01 survives contact with engineering only if these are enforced in code review, not aspiration.

IDs are immutable and meaningless

UUIDv7 TEXT keys, minted once, never recycled, carrying no semantics. Merges keep both rows and record a core.link of relation same-as with provenance — history is never rewritten.

Extend, don’t fork

A domain adds columns by holding a UNIQUE NOT NULL FK to the core row it specializes (media.asset.content_id, people.profile.party_id). Creating a second “person”, “event” or “transaction” table is a rejected review. Locker is the one written exemption: an owner-only secret anchors nothing in the core by design, and the exemption is in its DDL header rather than in anyone’s memory.

Relationships are typed and temporal

All cross-entity meaning goes through core.link: a SKOS-governed relation concept, valid_from/valid_to, who asserted it, and provenance. No boolean junction tables that forget when and why.

Writes are typed commands

Apps and agents mutate state only via registered agent.commands with JSON-Schema inputs, declared pre/postconditions and idempotency class. Raw UPDATE is for migrations, run by the owner, and it too leaves provenance.

Durable facts vs rebuildable projections

Observations, transactions, messages, provenance: durable, append-mostly, exported. Feeds, dashboards, search indexes, “smart albums”: projections that can be deleted and regenerated. Never let a projection become the only home of a fact.

Consent travels with the data

Every read path and every command execution evaluates access.grant_scope (purpose, verbs, row filter, field mask, expiry) in the gateway and emits an access.receipt. A share or export carries its policy with it — and a portable export carries no key in the clear, so the bundle opens only what its holder was given (#630).

Version the ontology explicitly

The ontology versions in exactly two places: the FILE (PRAGMA user_version) and the command CONTRACT (agent.command.ontology_version). An agent refuses a command whose schema version it does not recognize rather than guess. A per-ROW stamp is explicitly not the scheme (#916, ONT-04): a version column two tables out of seventy carried could never be checked, so it recorded nothing and constrained nothing.

Lifecycle is declared, not adopted

Every entity declares what it is — append-only, mutable, trash or machinery — and a test holds the schema to the declaration: mutable means a touched updated_at in one shape, trash means the deleted_at / purge_at pair with its guard, append-only means the engine refuses UPDATE. Conventions applied as tables are touched drift by construction; this rule replaced the correction-into-judgment loop that had commands, DDL and no caller (#916).

One judgment, one mechanism

Entity-scoped meaning goes through a universal join; surface-scoped state rides the domain row. Starred is a flags-scheme core.tag on the canonical entity; an owner memo is a knowledge.annotation; employment is a core.link. A favorite boolean on a domain table is a rejected review — it silently discards who judged and when, and re-imports the app-silo fragmentation the vault exists to dissolve. There is no registered exception any more: media.asset.favorite, the single-writer mirror this page once carried, was deleted in #916 — a mirror is two truths, and the replica shape it existed for reads the tag. Photos’ star anchors on media.asset and Docs’ on core.document: the same mechanism on each app’s own entity, not the shared bytes underneath.

Every app rides the paved road

Centraid is a superapp, not a platform: every app is first-party code shipped in the release (issue #799 retired the generated/served plane). The paved road stays exactly as strict anyway, because trusting your own code is how a model rots: a manifest becomes a grant (explicit risk_ceiling), reads go through scoped queries the gateway clamps to the grant, writes go through existing typed commands, and custom data lives in core.tag / core.concept / core.link or a declared per-app ext band inside the vault (issue #286) that may point into the canonical model but is never referenced by it. Uninstall = revoke grant + retain-then-purge the band; projections stay disposable and the model stays everything.

The domain admission checklist (issue #310 C6)

Locker and Tally shipped whole apps before anyone noticed the universal mechanisms had not come along — a second tag table, a private junction, an unindexed domain. New domains keep landing; drift is a process failure, not a modeling one. A PR that adds a vault domain answers all seven in review — and the eighth, since #916: is every entity row also a core.entity row, with every pointer pair a composite foreign key, or is it a projection that says so in the registry?

1 anchor — does every entity extend or reference a core row (R02), or carry a written exemption?  2 relations — do cross-entity joins ride core.link / an existing mechanism, not a new junction (R03)?  3 flags — stars and booleans through core.tag flags (R09)?  4 memos — owner remarks through knowledge.annotation?  5 search — an FTS spec for its text (sealed columns structurally barred)?  6 registry — entity in tables.ts with its label, lifecycle and revision policy declared, commands registered, scopes declared?  7 doc — §03 regenerated and this document updated in the same PR?

Recommended first boundary

Ship the spine where the pain is cheapest and the loop is fastest: core.party + core.event + the schedule domain, wrapped in the full access plane. Contacts and calendar exercise identity, time, typed links (attendee), one real state machine (RSVP), imports with provenance (vCard, RFC 5545 ICS), and two honest agent commands — schedule.propose_event and schedule.reschedule_event — each consent-checked and receipted end to end.

Success test: revoke the calendar app’s grant and watch every projection go dark while the model, history and receipts remain yours. Then add the second domain — and do not add a third until export→reimport round-trips losslessly. This page once recommended expanding straight to a four-domain foundation release. That was the advice the implementation took, and it is the advice #916 had to undo: two of those domains shipped DDL and typed commands with no surface and no consumer, and dormant DDL is not a head start — it is a claim the model makes and cannot keep. Add the next domain when a surface is ready to read it.

§12 · Inside the runtime

A second plane, not a second silo

Centraid’s app host (@centraid/server + @centraid/server/engine) once gave every app a private data.sqlite — full SQL, zero sharing. Issue #286 deleted that silo: app-declared tables now live as a registered ext band inside vault.db (ext.<app_id>.*), diffed on publish, retained-and-purged on uninstall. A handler reaches everything through ctx.vault — canonical entities under consent scopes, its own ext tables under its band — and every call walks §10’s five-stage pipeline on the host side of the process boundary.

The seam — a second RPC channel beside db

Centraid handlers run in a worker thread that holds no file handle: every db call round-trips as a message to the host, which owns the SQLite connection (app-engine/src/handlers/handler-runner.ts host-side, app-engine/src/worker/runner.ts worker-side). ctx.vault is the same move aimed at the canon: the worker posts {type:'vault'} messages with read / invoke / query / describe payloads; the host resolves the running app to its Credential, calls the process-held vault gateway (vault/src/gateway/gateway.ts), and replies with allowed rows or a receipted denial. Consent is enforced on the host side of the boundary — the correct side, because the worker gives crash isolation and a controlled surface, not a security sandbox.

No keys in the worker — credentials resolve host-side; the handler surface carries capability, never secret No second wire — ctx.vault rides the existing worker RPC; no new protocol, no new port No FK across bands — a declared ext.* table may point into the canon; the canon never points back (R09, band-shaped since #286) No unreceipted path — every ctx.vault call ends in an access.receipt, allow or deny No consent shortcut — a first-party app’s call is a §10 pipeline walk like any other caller’s

Who is who — the concept mapping

Each vault-plane concept lands on a Centraid structure that already exists. Nothing here invents a parallel mechanism; the integration is mostly wiring.

access.app ← registry entry

An app that goes live (registry.ensureUploaded) is enrolled via enrollApp as an access.app row. origin admits one value, installed, since that has been the only door since #799 (#916). App deletion runs the revocation cascade: projections dark, parked invocations dropped, the ext band retained then purged.

signing key ← identityDb

The minted signingKey persists host-side in the gateway’s identity store, keyed by app id. It never crosses into the worker; the host attaches it when proxying a ctx.vault call.

access.agent ← chat & automation runners

The conversation runner and automation fires act as an enrolled access.agent riding an owner device (session binding). Risk ceiling medium; high parks for owner confirmation — the send-message pause, verbatim.

owner device ← the host itself

bootstrapVault mints the first device on first boot, idempotently. The desktop user’s direct actions — confirmations, grants, revocations — ride it with riskCeiling='owner'.

vault.db ← GatewayPaths.vaultDir

A caller-derived path slot beside appsDir, identityDb and analyticsDb. Opened by buildGateway(), WAL mode, closed on stop(). ONE file since #916 — model, audit band and ledger band — so the vault stays a single thing the owner can copy out and a receipt is atomic with its mutation.

agent.command ← app.json action

Both are JSON-Schema-validated typed writes. A declared action may delegate to a vault command; the vault then adds consent, pre/postconditions, provenance and receipts on top of Ajv input validation.

ext band ← declared ext.* tables

R10’s per-app extension surface is no longer a separate file: issue #286 moved app tables INTO vault.db as a declared, registered band. Ext tables may FK the canon (and each other within one app); the canon never references them; uninstall = revoke grant + retain-then-purge the band.

standing duties ← in-process scheduler

Centraid’s gateway already runs a minute-boundary cron scheduler. sweep() joins its tick; checkpoint()/backup() join the lifecycle; revocation is wired to app deletion.

Six phases, each independently shippable

Sequenced so the risky parts — the handler primitive and the consent UX — land only after the vault is simply present and app identities exist. Every phase carries its own tests.

Host holds one vault

Add vaultDir to GatewayPaths; buildGateway() opens the file, bootstraps the owner idempotently, registers the packs, exposes the vault gateway on BuiltGateway, closes it on stop(). Tests: builds with a vault, bootstraps once, survives restart.

Apps become access.app rows

App-live enrolls the app and persists its signing key host-side; deregistration calls revokeGrant and the cascade follows. Tests: registration mints a credential; deletion goes dark.

ctx.vault in the handler surface

Worker proxy mirroring db: read / invoke / query / describe. The host resolves app → Credential and calls Gateway.read/invoke; a deny returns a shaped handler error carrying the receipt id. Tests: a handler proposes an event into the canon; an ungranted read is a receipted deny.

Grants, owner-approved

app.json declares requested scopes; the owner approves and the host calls createGrant. Deny-by-default until then — installation is not consent. Tests: pre-grant denied, post-grant allowed, owner reads unaffected.

Manifest surface

A vault block in app.json (requested scopes + command delegation) and handlers that call ctx.vault.* — declared handlers stay the agent’s primary surface, and the automation compiler emits that same shape for a cloned automation.

Duties on the gateway clock

sweep() joins the scheduler tick; checkpoint/backup join start/stop lifecycle; parked confirmations surface through the existing confirmation UI instead of a bespoke one.

Decided and built

Consent model: manifest-declared scopes with explicit owner approval. An app's app.json vault block is a request, never a grant; the owner approves it over POST /centraid/_vault/apps/<id>/grants, and until then every call is a receipted deny.

Data planes: one file, one canon, one band per app. The per-app data.sqlite is deleted (issue #286); app extension tables ride inside vault.db as the declared ext band, and the shipped blueprints declare zero of them — pure projections. The canon stays the consent-gated shared plane; the band boundary, not a separate file, is the silo line now.

All six phases are implemented and tested: the vault plane mounts off GatewayPaths.vaultDir (gateway/src/serve/vault-plane.ts), live apps enroll and uninstalls cascade, ctx.vault rides the worker RPC (app-engine/src/worker/runner.ts), owner routes serve grants and parked confirmations, the automation compiler teaches cloned handlers this same surface (there is no user-facing build-an-app flow — #799 retired that plane, and the compiler survives because it is what turns an automation into a plan), and the sweep clock runs on the gateway lifecycle.

And the §01 projection band ships as blueprints. Eight product surfaces are first-class templates in packages/blueprints/apps — docs, photos, notes, people, locker, tally, agenda, tasks — each a pure projection: zero private tables, every row from ctx.vault, every mutation a typed command, consent denial and the parked pause rendered as first-class UI states. Revoke a grant and the projection goes dark; the model, history and receipts remain. The same eight are documented from the user's side in the Apps chapter.
