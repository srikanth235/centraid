Nine relations join them

An edge is a directed link between two records. The vault checks that each relation connects allowed kinds.

  • containsalbum → photo, list → person — ordered membership; a note, document, task or event has its holder as a column instead
  • taggedanything → tag or flag — a word put on a thing: also a star, a pin, an archive
  • aboutnote, task or event → anything — a note about Maya, a journal entry, a task about Mum, an anniversary; also document → person, and Locker item → account, place or person
  • linksitem → item — a link set by hand between any two items (a person, place, event, task, note, document, photo, account, transaction or workout), or a note’s [[wikilink]] with its anchor in the text; a Locker item may start a link and is never the end of one
  • attachedanything → document or photo — a file brought to a thing
  • attendeeevent → person — a guest, with their answer on the edge
  • withactivity, transaction or Locker item → person — who a call or a visit was with, who a payment was with
  • relatedperson → person — labelled by a relation concept
  • depictsphoto → person — who is in a photograph, tagged by hand (no face detection)

Principles

How the model stays coherent

One identity, then kind-specific fields

Every record has one row in entity. A kind table stores only that kind’s fields; concepts and containers use shared tables.

Links are typed and directed

The edge table records the relation and its two ends. Allowed kind pairs are checked by the vault.

Files are separate from records

Blob bytes are addressed by hash. Records refer to those bytes; derived previews are rebuildable.

Imports preserve member edits

Followed sources update fields they last supplied. A member’s edit to a field is kept when that field has changed locally.

Checks

What the tests hold in place

One host per kind

The code’s kind list, each kind’s storage group, and the generated kind constants agree.

Trash and identity live on the entity

Deletion and purge state belong to the shared entity row, including for Locker items.

Every byte reference is declared

Columns that hold blob hashes are foreign keys, so collection can find all references from the schema.

Relations allow only defined pairs

Every relation and source-kind/target-kind pair is checked against the code’s relation shapes.

Search matches a rebuild

Incremental current and earlier-version indexes must match what rebuilding the index writes.

The schema page matches the migration

Counts, kinds, relations and every generated table definition are checked against the vault source.
