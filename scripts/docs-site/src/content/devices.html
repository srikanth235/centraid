Chapter 3 · devices

The phone is the vault. The gateway keeps its backup.

Centraid has one writer: the Rust core on your phone. A gateway is a machine you control that stores sealed backup data. It cannot read the vault, serve as another app client, or reach into the phone.

§01 · topology

One phone, one writer.

The phone holds the live vault and its keys. Apps and edits go through its Rust core. A gateway holds encrypted records and objects acknowledged from the phone; it is not a second vault you can work in.

The phone initiates every connection. No relay or listening phone is involved. If the gateway is unreachable, the phone continues to work locally and backup waits.

§02 · reachability

Direct HTTPS to a reachable gateway.

The phone uses addresses in the gateway's pairing QR and pins the certificate fingerprint carried in that QR. A port forward may carry HTTPS through to the gateway, but do not terminate TLS at a proxy: the phone must see the pinned gateway certificate.

On a local network, the gateway advertises its service unless started with --no-mdns. For remote access, configure routing and firewall rules so the phone can reach the bound address. The QR's address must be reachable from the phone's network.

§03 · pairing

Use a fresh QR and compare the safety number.

Start centraid-gateway serve --data-dir DIR on a machine you control. On first run it creates the gateway identity and prints its pin and a pairing QR. To pair another phone or retry with a fresh secret, run centraid-gateway pair --data-dir DIR beside the running gateway. Pairing codes are single-use and expire after a day.

In the phone's Backup screen, scan the fresh QR. The phone connects directly over HTTPS and checks the certificate pin. After pairing, compare every group of the safety number shown on the phone with the number printed by the gateway. Stop if they differ.

Pair each additional gateway separately. Each stores its own sealed backup.

§04 · connection

The phone calls out.

The gateway accepts direct HTTPS requests from the phone. It does not relay traffic, list vaults, or initiate connections to a phone. Local network discovery can help the phone find an address, but does not replace pairing or certificate pinning.

§05 · restore and takeover

A restored phone becomes the writer.

Restore checks the recovered records before claiming a new writer position. A successful takeover invalidates the older phone's gateway tokens. The old phone learns it was superseded only when it contacts a gateway; while offline, it cannot learn about that change. Revocation is not immediate on an offline phone.

The gateway keeps sealed snapshots and objects according to current retention rules. It does not keep a live replica or offer a remote shell.

§06 · operator setup

Run the gateway on a machine you control.

gateway terminal
# bind on all interfaces when remote clients need to reach it
$ centraid-gateway serve --data-dir ~/centraid-gateway --bind 0.0.0.0:8443
# create a fresh pairing QR while serve is running
$ centraid-gateway pair --data-dir ~/centraid-gateway
$ centraid-gateway pairings --data-dir ~/centraid-gateway
$ centraid-gateway health --data-dir ~/centraid-gateway

Build the binary from the repository with cargo build --release -p centraid-gateway. --data-dir selects the gateway's complete data directory; --bind selects its listening address and defaults to 0.0.0.0:8443. These flags also accept CENTRAID_GATEWAY_DATA_DIR and CENTRAID_GATEWAY_BIND. Keep the data directory and gateway identity safe: copying the directory copies the gateway.

install --dry-run previews a supported user service unit on Linux or LaunchAgent on macOS. install writes it but does not enable or start it. The repository gateway README documents the container setup and its network requirements.

§07 · desktop

There is no desktop app.

A gateway is a blind backup store, not a shell or client that opens and edits your vault.

§08 · web

There is no web vault.

Centraid's live vault and apps run on the phone. The gateway exposes only its backup protocol.

§09 · phone builds

Native iOS and Android shells.

The iOS app uses SwiftUI and the Android app uses Jetpack Compose over the Rust core. Source-build instructions for this pre-release are maintained in mobile/README.md.
