Devices · topology

The phone is the vault. The gateway keeps its backup.

The Rust core on your phone is the vault's only writer. A gateway is a machine you control that stores sealed backup data. It cannot open the copy or act as another Centraid app.

The phone calls out

On the phone

Apps read and change the live vault through its Rust core.

On the gateway

Encrypted records and objects arrive from the phone; the gateway cannot read them.

One phone, one writer

The phone holds the live vault and its keys. A gateway holds only sealed data acknowledged from the phone; it is not a second vault to work in. Pairing more than one gateway makes a separate backup at each.

Reach a gateway directly

The phone connects over HTTPS to an address in the gateway's pairing QR and pins the certificate fingerprint in that QR. A port forward may carry the connection to the gateway, but a proxy must not terminate TLS: the phone must see the pinned gateway certificate.

On a local network, the gateway advertises an address unless it starts with --no-mdns. Remote access needs routing and firewall rules that make the QR address reachable from the phone.

Pair with a fresh QR and compare the safety number

Run centraid-gateway serve --data-dir DIR on a machine you control. First run creates the gateway identity and prints a pairing QR and safety number. To issue a new QR, run centraid-gateway pair --data-dir DIR beside the running gateway. Codes are single-use and expire after a day.

Scan the fresh QR in the phone's Backup screen, then compare every group of the safety number with the number printed by the gateway. Stop if they differ. The phone connects directly over HTTPS and checks the certificate pin.

What the gateway does not do

The gateway accepts HTTPS requests from the phone. It does not relay traffic, list vaults, initiate phone connections, or serve as a remote shell. Local discovery can help find its address; it does not replace QR pairing or certificate pinning.

Restore and move the writer

A restore checks the recovered records before claiming a new writer position. A verified takeover invalidates the old phone's token at that gateway. An old phone learns only when it contacts a gateway. A verified moved mark fences ordinary member write actions; the backup pass can continue to gateways that have not moved. Only when all paired gateways have moved does the whole backup door refuse writes.

The gateway keeps sealed snapshots and objects under the retention rules. It does not hold a live replica of the phone's vault.

Run and maintain the gateway

Build the binary with cargo build --release -p centraid-gateway. --data-dir selects the complete gateway data directory; --bind selects its listening address and defaults to 0.0.0.0:8443. The environment variables are CENTRAID_GATEWAY_DATA_DIR and CENTRAID_GATEWAY_BIND. Copying the directory copies the gateway identity and sealed objects, so protect it like important machine data.

install --dry-run previews a supported Linux user service or macOS LaunchAgent. install writes the unit but does not enable or start it. See the gateway README for container and network setup.

Is there a desktop app?

No. The gateway stores a sealed backup; it does not open or edit your vault.

Is there a web vault?

No. The live vault and apps run on the phone. The gateway exposes only its backup protocol.

Build the phone apps

The iOS shell uses SwiftUI and Android uses Jetpack Compose over the Rust core. Source-build instructions for this pre-release are in mobile/README.md.
