Understand it · how it works

One phone vault. Apps that share its records.

Centraid has one live vault: it lives on your phone, and the Rust core on the phone is its only writer. SwiftUI and Android's native shell draw the same built-in apps over that core. A backup device runs centraid-gateway and stores sealed backup data; it cannot read your records or answer app queries.

Begin with the phone setup, or read the foundations behind the vault and its recovery.

The shape of the system

Three parts, one owner.

part 1

The phone vault

The phone holds live SQLite records. Original files may be on the phone, in its OS library, or only on a backup device. The shared model connects events, people, places, documents, payments, photos, health entries, and Locker metadata. Only the phone's Rust core writes durable data.

part 2

Built-in apps

Home opens Calendar, Reminders, People, Notes, Docs, Photos, Money, Health, and Locker. These are first-party screens in the release, not separately installed apps. Each app reads and acts through typed operations in the phone core.

Hometyped actions shared history

part 3

Backup device

Pair the phone with a gateway you control using a fresh pairing code and compare the safety number. Direct HTTPS carries sealed backup data. The gateway is a blind store, not another Centraid client or a writer.

The shared record model

One set of connected records.

The apps use one ontology: a shared description of the things the vault stores and how they relate. A person can connect to an event, note, payment, or photo without copying that record into another app. App screens and the assistant use typed reads and actions exposed by the phone core; an action changes the vault only after the member chooses it.

Imported and followed records keep their source information. A record written directly in Centraid has no imported-source row. Restore recovers records first; original files acknowledged by a backup device can be fetched from it without the source phone. Originals never backed up may need to be imported again from the OS library or may be unavailable if that phone is lost. Records and file availability are reported separately.
