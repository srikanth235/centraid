# `contracts/` — the language-neutral fixtures

v1 is three languages ([#1020](https://github.com/srikanth235/centraid/issues/1020)). A fixture that lives inside one of them is a fixture the other two cannot be held to, so every fact both trees must agree about lives here, as data, in a form a Rust test and a TypeScript test can each read without a bridge.

**The rule.** Every fixture under `contracts/` passes in Rust, and **while the v0 tree exists, the TypeScript oracle passes the same files.** "The same files" is a claim about bytes, not about intent: the golden corpus is committed twice, once under `packages/vault/tests/golden/` where v0's suite reads it and once here, and `crates/ontology/tests/fixtures.rs` asserts the copies of **each** corpus are byte-identical for as long as the v0 path exists. When wave 6 deletes the v0 tree, that assertion has nothing left to compare and says so; this directory is what survives.

**Nothing here is hand-written.** Each subdirectory is generated from a source that is still v0's, and the generator is named beside it. A fixture whose regeneration step is undocumented is a fixture that will be edited by hand.

| `protocol/framing-golden.json` | The wire's byte-level facts: `frameBase64 = base64(u32BE(len) ‖ body)` for seven named `centraid.core.v1.Envelope` vectors, the three v1 ALPNs with their bytes, the framing caps (`maxFrameBytes` 262144, `chunkBytes` 65536) and the version window. | `apps/tally/` | Tally's parity fixtures: `rows.json` (every row of every table the eight queries read), `queries.json` (`{query, input, output}` for all eight at fixed inputs), `balances.json` (the balance engine's cases, inputs to pairwise/simplified), `scenarios.json` (the two ontology scenarios that touch tally). Every identifier is canonicalised to first-appearance order and every host-clock instant to `<host-clock>`. | `CENTRAID_WRITE_CONTRACTS=1 node node_modules/vitest/vitest.mjs run --config vitest.quality.config.ts tests/quality/tally-parity.contract.test.ts`, then `bun run format`. | `tools/` | The generators that are not Rust binaries. | — |

The rest of the tree named in the issue — `applier/`, `migrations/`, `restore/`, `journeys/` — arrives with the waves that need it: the applier fixtures in wave 2 lane D, the remaining seven apps' parity fixtures in wave 4, the migration fixtures with the forward-only ladder in `crates/vault`, the restore drills with wave 2 lane R. This file is the index; a lane that adds a subdirectory adds its row.

## Why the registries are transcribed rather than re-typed

`packages/vault/src/schema` is the **source** of the model until wave 6. Re-typing "which tables never leave the gateway" in Rust would create a second answer, and two answers to one question drift silently — which is the failure `private-tables.ts` was itself written to prevent inside v0. So `export-v0-registries.ts` transcribes and interprets nothing, and `crates/ontology/src/registries.rs` embeds the result with `include_str!` so a shipped binary carries the registry it was built with and never looks for a repository path at runtime.

When a v0 registry changes, regenerate the fixture **in the same slice** as the change. `bun contracts/tools/export-v0-registries.ts` is deliberately invoked by path rather than through a `bun run` script: it is v1 tooling that happens to be written in TypeScript, not part of v0's package scripts, and v0's own gates stop running on PRs from wave 1.

## The version window is two numbers, and both are exported

`schema/v0-registries.json` carries **both ends** of the `PRAGMA user_version` window v1 accepts (#1020, **D-1020-A1**):

- `userVersion` — what the #929 **checkpoint** corpus was frozen at, read from the manifest beside it.
- `ladderUserVersion` — what a **freshly founded v0 vault** reaches today, the length of v0's migration ladder.

They are both here, rather than one here and one in the manifest, because `crates/ontology` embeds this file and nothing else: `Vault::open` has to know the window without reading a repository path at runtime. A file above the ladder head is refused as a downgrade, one below the corpus as needing a forward migration this crate does not have.

The expected version was briefly a hard-coded `7` in Rust, which quietly made v1 understand only the checkpoint fixture and refuse a vault v0's own code had founded. A number a lane has to remember is a number that goes stale, so it is transcribed with everything else.
