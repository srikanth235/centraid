# Backup design decisions for #1191 (lane B)

Hand-written decisions for [#1191](https://github.com/srikanth235/centraid/issues/1191), lane B (rows B1 to B15). Lane B builds from this file without making a design choice. Each decision gives the rule, the exact shape, the reason, the code it replaces and the row that builds it. Where two options were defensible, the rejected one gets a line. Nothing here is built yet; when a row lands, the backup skill and the gateway README describe the result and this file is deleted at Lock (L2).

Line references are by name, not number. "Protocol 3" means every route moves from `/v2/` to `/v3/` and `GET /v3/info` answers `protocol: 3`. There is no dual serving.

Common encoding, used by every signed record below (the claim's scheme in `rules/claim.rs` today): Ed25519, verified strictly, by the vault identity key; the preimage is a list of fields, each `u32be(length) ‖ bytes`; integers are `u64be`; a name or hash is 32 raw bytes; an absent optional name is a zero-length field.

## E1. The key and the context strings

**Rule.** The vault identity key (the vault id) signs every head, delete, undo, claim and pairing. It is the key claims use today, so no key is added and the gateway already holds its public half. Each kind of record has its own context string, the first field of its preimage, so a signature over one is never valid as another.

| Record | Context (field 1, ASCII) |
| --- | --- |
| claim and read grant | `centraid-gateway-claim-v3` |
| head | `centraid-gateway-head-v3` |
| delete | `centraid-gateway-delete-v3` |
| undo | `centraid-gateway-undo-v3` |
| pairing by secret | `centraid-gateway-pair-v3` |

Every preimage's second and third fields are `gateway_id` (16 bytes) and `vault_id` (32 bytes), so a record made for one gateway or vault is void at another. All five use `v3` because the claim's preimage gains a nonce (E5) and the contexts move together with the protocol.

**Why.** One key, one scheme, one builder: `rules::signing` holds every `*_preimage` and `sign_*`/`verify_*` pair, and the phone calls the same functions. The vault's symmetric keys (root, backup) cannot sign for a party that holds no key, so they are not candidates.

**Rejected.** A separate head-signing key derived from the seed (a second leaf to derive, store and rotate, for no isolation: the seed holds both).

**Replaces.** `claim_preimage`, `CLAIM_CONTEXT`, `sign_claim`, `sign_read`, `verify_claim` in `rules/claim.rs` (the module's v2 vector test is rewritten as v3 vectors in `contracts/crypto/gateway-signing-vectors.json`, generated by the Rust test, read by the phone's test). **Built by** B2 (head), B4 (claim), B5 (delete, undo), B6 (pair).

## E2. What a signed head binds

**Rule.** A head is a record the phone signs and the gateway stores and serves as signed. Preimage, in order:

```text
u32be(24) ‖ "centraid-gateway-head-v3"
u32be(16) ‖ gateway_id
u32be(32) ‖ vault_id
u32be(8)  ‖ u64be(epoch)         the writer epoch the phone holds there
u32be(8)  ‖ u64be(generation)    E3
u32be(8)  ‖ u64be(writes)        the vault's write counter in the snapshot (Manifest.writes)
u32be(8)  ‖ u64be(taken_at_ms)   Manifest.taken_at_ms, so a token holder cannot move it
u32be(32) ‖ manifest_name        the root manifest object's name
u32be(32) ‖ prev                 the head's name this one replaces, or u32be(0) for none
```

Wire: `PUT /v3/v/{vault}/head` body `{name, prev, taken_at_ms, generation, writes, signature}`; the epoch is the token's, not sent. `HeadView` answers `{name, prev, taken_at_ms, epoch, claim, generation, writes, set_at_ms, signature}`, where `claim` is the vault's standing claim (the shape `MOVED` carries, null before any claim) and **no unsigned writer epoch travels**: the phone takes its epoch as the greater of the verified head's and the verified claim's (`Client::head_state(vault, gateway)`, typed `ClientError::Unverified`). `GET head` serves the stored record unchanged, and the phone verifies the signature (and `gateway_id`, `vault_id`) before it believes any field (E4, B8).

**Gateway tables** (state.db, ladder rung 1). `head(vault PK, name, prev, taken_at_ms, epoch, generation, writes, set_at_ms, signature)`; `snapshot(vault, name, taken_at_ms, registered_at_ms, epoch, generation, writes, prev, signature, held_at_ms, purge_after_ms, PRIMARY KEY (vault, name)) WITHOUT ROWID`, one row per signed head ever accepted that is still kept, each a copy of the record. Keys run head → snapshot → object: `head (vault, name)` references `snapshot (vault, name)`, which references `object (vault, name)`; a manifest object that a snapshot row names cannot be tombstoned except through a held delete (E6) and a head's manifest cannot be at all (`HEAD_IN_USE`, kept).

**Why.** With a signature, a token holder alone can no longer set a head (gap 2): the worst a token can do is replay a head the phone really signed, and E3 refuses that. `writes` lets a restore order two heads from different gateways even when generations were reset.

**Rejected.** Signing only `(manifest_name, generation)` (leaves the epoch and vault out, so a record is portable between vaults and eras).

**Replaces.** `HeadRecord`, `SetHead`, `HeadView`, `Engine::set_head`, the `head` and `snapshot` tables in `server/sql/schema.sql`, `store::Head`. **Built by** B2.

## E3. The ordering rule and its refusal

**Rule.** The gateway keeps, per vault, the current `(epoch, generation, writes)` of the last accepted signed record (head, delete or undo; one counter, `generation`, shared by all three). It accepts a new one only if:

1. its signature verifies (else `UNAUTHORIZED`);
2. the token's writer epoch equals the vault's writer epoch (else `MOVED`, E4);
3. `generation > current.generation` and `generation - current.generation <= MAX_GENERATION_JUMP`, where **`MAX_GENERATION_JUMP = 256`**;
4. for a head, `writes >= current.writes` (a vault's counter never falls inside one epoch);
5. for a head, `prev` is the standing head's name (the existing compare-and-set; `HEAD_CONFLICT` as today).

A **claim** (E5) resets the counters: after a claim `generation = 0`, `writes = 0`, and the first record of the new epoch needs `1 <= generation <= MAX_GENERATION_JUMP`. A retry of the head that already stands (same name, same signature bytes) answers the stored record and does not consult 3 or 4, so a lost answer is not a conflict. A delete or undo retry re-signs at the next generation (deleting a deleted name is idempotent).

**The bound.** The phone signs `generation = last + 1` and sends it; gaps come only from signed requests whose answer was lost. 256 lost-answer requests between two contacts does not happen in an hour-long pass cadence; the bound exists so that one signed record at `u64::MAX` (a bug, or a compromised token holder replaying a forged-looking field) cannot lock the real phone out for ever, because the ordering rule never lets the counter fall.

**Answer.** New closed code `OUT_OF_ORDER`, status 409, companions `epoch`, `generation`, `writes` (the standing record's). The phone reads it as "this gateway holds something newer or different": it re-reads the head, takes `generation = max(local, standing) + 1`, re-signs, and tries once more; a second `OUT_OF_ORDER` stops that gateway's pass with reach `refused_other`.

**Why.** Gap 2: an old signed head replayed by a token holder fails rule 3; an old snapshot cannot be re-pointed. **Rejected.** Ordering by `taken_at_ms` (a phone clock; a gateway cannot trust it, and it falls legitimately after a vault restore).

**Replaces.** `Engine::set_head`'s check, `Refusal`/`Code` in `rules/code.rs` (new `OutOfOrder`), `phone/link.rs` `store_error` mapping, `store::Refusal`. **Built by** B2.

## E4. "Moved": the signed claim, and what the phone believes

**Rule.** The gateway keeps, per vault, the last claim it accepted: `claim(vault PK, epoch, head_seen, nonce, signature, claimed_at_ms)`. Every refusal that today says `MOVED` carries it: `MOVED` 409 `{epoch, claim: {epoch, head_seen, nonce, signature}}`. A token revoked by a claim also answers `MOVED` (E5), on every route, reads included.

**The phone's rule.** The phone believes a `MOVED` only if the carried claim (a) verifies by its own vault identity key against this gateway's id and the nonce in the claim, and (b) has `claim.epoch` strictly above the epoch its `gateway` row holds. Then, and only then, it records `reach = 'moved'`, `moved_epoch = claim.epoch` on **that gateway's row only**, and the pass to **that gateway only** stops. There is no vault-wide freeze flag. The pass to every other gateway goes on, each until it says `MOVED` with its own verified claim, because each gateway arbitrates its own writer epoch and a claim the new phone has not yet made there changes nothing there. The status line says another phone has taken over as soon as any row is `moved`. A `MOVED` whose claim is missing, does not verify, or is not above the epoch held is treated as that gateway refusing for another reason (`reach = 'refused_other'`): it stops the pass to that gateway only and writes nothing else.

**Why.** Gap 1: today one gateway answering a higher unsigned epoch freezes the phone for every gateway until the ledger is deleted. The vault key signs the claim, so only a holder of the 24 words can produce a believable one; a gateway cannot forge, and a genuine old claim is not above the phone's epoch.

**Rejected.** A vault-wide freeze on the first verified claim: one gateway, or a thief who reached only one gateway, would then stop the backup to all the others.

**Replaces.** `CoreError::VaultMoved` raising in `phone/drain.rs` (the `epoch > reached.destination.epoch` check on `head_and_epoch`, the `Stop::Moved` arm, the `set_moved` call), `super::moved(&ledger)`, `Ledger::set_moved`/`moved`, `heard_of`/`refused_by` gain `OUT_OF_ORDER`, `FROZEN`, `BUSY` and `CLOCK_AHEAD` arms that map to a reach value per gateway. **Built by** B3, with B4 on the gateway side.

## E5. Takeover: revoke everything older, tombstone, nonce

**Rule.** A claim at `writer_epoch + 1`, signed (E1) and passing the head check as today, does in one transaction:

1. deletes every `token` row of the vault, every kind, reads included;
2. writes one `revoked_token(token_hash PK, vault, epoch, revoked_at_ms)` row per deleted token;
3. clears every held delete of the vault (`tombstoned_at_ms`, `purge_after_ms` set to NULL on objects and snapshots; E6), so a thief's deletes are undone by the takeover that follows them and the new phone's retention re-issues what it wants;
4. stores the claim (E4), resets the counters (E3), sets `writer_epoch`;
5. mints the claimant's token.

**Tombstone (decision 29).** A takeover always keeps the superseded writer's tombstone: past `MAX_REVOKED_PER_VAULT` rows the trim drops read-grant tombstones first, then the oldest writers. A `revoked_token` row holds only the token's BLAKE3, the vault, the token's epoch and when. For `REVOKED_TOKEN_KEEP_MS = 365 days` (gateway clock, in the hourly sweep) and at most `MAX_REVOKED_PER_VAULT = 64` rows per vault (oldest pruned first), a request bearing a revoked token on any authenticated route answers `MOVED` with the vault's latest claim (E4), so the old phone hears "moved" and can verify it. After the tombstone is pruned the same token answers `UNAUTHORIZED`, which the phone already reads as "pair again". A token the phone or operator revoked on purpose (`POST revoke`, `pairings revoke`) leaves no tombstone and answers `UNAUTHORIZED`: no claim backs it.

**Nonce (decision 27).** `POST /v3/nonce` (no auth, no body) answers `{nonce: 80 hex, ttl_ms: 300000}` and **writes nothing**. The nonce is 40 bytes: 16 random, `u64be(issued_at_ms)`, and a 16-byte BLAKE3 MAC keyed by a gateway-local `nonce.key` over `"centraid-gateway-nonce-v1" ‖ gateway_id ‖ random ‖ issued_at_ms`. The rules receive the random bytes and `now_ms` as arguments. A nonce is good for `NONCE_TTL_MS = 300_000` and is signed into the claim, read-grant and pairing preimages (the last field of each). A request is judged nonce (MAC, gateway, age), then credential, then signature, and **only a request whose signature verifies records the nonce as spent** (`nonce_spent`); a forged, expired, foreign or wrong-key request writes nothing, so a stranger cannot fill the table. An unknown, expired or spent nonce answers `UNAUTHORIZED`, the same as a bad signature, so there is no oracle. At `MAX_LIVE_NONCES = 4096` spent rows still inside their five minutes a pair request answers new closed code `BUSY` (503, companion `retry_after_ms: 60000`); expired rows are pruned by the hourly sweep. The nonce route never names a vault.

**Why.** Gap 3: a superseded token holder keeps reading everything. Gap 8: a read grant or claim signed once could be replayed after a revoke. **Rejected.** A timestamp in the signature instead of a nonce (needs a phone clock the gateway believes). A permanent tombstone table (unbounded).

**Replaces.** `pair_by_claim`, `grant_read`, `mint`, `authorize` (revoked-token branch), `remove_token` callers, `Engine::pair`'s signature handling in `rules/engine.rs`; adds `server/sql/nonce_*.sql`, `revoked_token_*.sql`. **Built by** B4.

## E6. Held deletes, undo and the operator's three verbs

**What is signed.** A delete and an undo each carry `{names, generation, signature}` (E3 counter). Preimage of a delete: `u32be(26) ‖ "centraid-gateway-delete-v3" ‖ gateway_id ‖ vault_id ‖ u64be(epoch) ‖ u64be(generation) ‖ names_digest`, where `names_digest = blake3(u32be(count) ‖ name₁ ‖ … ‖ nameₙ)` over the names sorted ascending and de-duplicated, 32 bytes. The undo preimage is the same with `centraid-gateway-undo-v3`. An unsigned delete is `UNAUTHORIZED`. Head changes are signed by E2.

**Held, not gone.** An accepted delete sets `held_at_ms = now_ms` and `purge_after_ms = now_ms + GRACE_MS` (7 days) on each name's object, and on any snapshot row whose manifest is among them. Nothing is removed until the purge sweep passes `purge_after_ms`. The README's rules stay: a held name is not held for `exists` (so a `PUT` of it with the digest the gateway recorded lifts the hold, and a file that still verifies is kept as it is; **a `PUT` with another digest is `NAME_TAKEN`** carrying the recorded digest and `state: live|held|damaged`, decision 28, so a token without the vault key cannot overwrite a held snapshot), the live listing leaves it out, and `GET` and `fetch` still serve its bytes until the purge.

**How the seven days is measured (decision 26).** By the gateway machine's clock: the adapter passes `now_ms` and the rules write the absolute `purge_after_ms`; the rules have no clock. **A hold counts only time the gateway was watching:** when the gap since the last purge sweep exceeds `PURGE_GAP_INTERVALS = 3` sweep intervals, every hold moves out by the whole gap, in one transaction before anything is purged (`Engine::account_for_gap`, the same operation as `unfreeze`). A gateway that slept for a month and one whose clock jumped a year give each hold all the time it had left; a clock that steps back purges nothing and shortens nothing.

**A damaged name (decision 30).** A delete signed by the vault key that names an object the gateway marked damaged removes its row and file at once, with no hold (the bytes are bad; an undo would restore nothing), and reports it in the answer's `freed` apart from `deleted`. A token alone cannot. The head's manifest, and a damaged manifest a kept snapshot row still names, are not freed this way. `NAME_TAKEN` is an acknowledgement only when the recorded digest is the phone's own (`Put::acknowledged`); with another digest the phone is told whether the name is live, held or damaged and never counts the file as stored. Accepted residual: a stolen writer token without the vault key can occupy a name the phone has not yet written, delaying that one file until a signed delete's hold ends.

**What "listed" returns.** `GET /v3/v/{vault}/held?after=<name>&limit=<n>` (seek-paged by name, at most `LIST_LIMIT`) answers `[{name, size, digest, kind: "object" | "snapshot", held_at_ms, purge_after_ms}]`. `GET /v3/v/{vault}/snapshots` keeps a held snapshot in its list with `held_at_ms` and `purge_after_ms` set, so a restore can still choose it (its bytes are still served).

**Undo.** Signed undo by the phone (`POST /v3/v/{vault}/undo`, `{names | null}`, null meaning every hold) and the operator's `undo` verb both clear `held_at_ms` and `purge_after_ms` on the named objects and snapshot rows, or on all of the vault's; the objects are live again for `exists`, the listings and `fetch`. Undo never moves the head and never reverses a takeover (a takeover clears holds itself, E5). **The phone lists its held deletes and offers Undo for its own** (a screen in B16, "delete pending and undo"): it reads `GET held`, shows the count and the date each goes, and Undo sends the signed undo for the names it deleted.

**Operator verbs** (CLI on the gateway machine, `centraid-gateway vault <id8> <verb> --data-dir DIR`, `id8` the first 8 hex that `pairings` prints; refused when it names more than one vault). The operator is local and unsigned; the CLI reads and writes `state.db` through the same `Engine` so the rules stay the only decision-maker.

| Verb | What it does to state |
| --- | --- |
| `freeze` | sets `vault.frozen_at_ms = now`. While frozen, every state-changing route (`PUT` object, `bundle`, head, delete, undo, claim, pairing by secret, `revoke` excepted) answers `FROZEN` and the purge sweep skips the vault. Reads (`head`, `snapshots`, `held`, `exists`, `objects`, `GET`, `fetch`), `nonce` and read grants still answer, so the member can read the backup from another phone. |
| `unfreeze` | clears `frozen_at_ms` and adds the time it was frozen (`now - frozen_at_ms`) to every `purge_after_ms` of the vault, so freezing does not burn the week. |
| `undo` | the undo above, for every hold of the vault, no signature (the operator has the last word). Works while frozen. |
| `purge-now` | needs `--yes` and an unfrozen vault; sets `purge_after_ms = now` on every hold of the vault and runs the purge sweep once, printing counts. |
| `delete-vault` | see E14. |

`FROZEN` is a new closed code, status 423, companion `since_ms`. The phone records `reach = 'frozen'` on that gateway's row and says the gateway is paused by whoever runs it; it stops that gateway's pass, never the others, and asks again next pass. There is **no delay on a takeover** (decision 1): a claim is never held.

**Why.** Gap 4: today a token holder deletes every part and the snapshots vanish from the listing; here a delete needs the vault key, waits a week, stays listed and the person at the machine can stop it. **Rejected.** A phone-visible "held" countdown timer (a clock the product does not need; the phone shows the date).

**Replaces.** `Engine::delete`, `Tombstone`, `GRACE_MS`, the `object` columns `tombstoned_at_ms`/`purge_after_ms` (renamed `held_at_ms`/`purge_after_ms`), `Engine::purge`, the `remove_snapshot` call in delete, `store::Deleted`, `TOMBSTONE_GRACE_MS` (restated, now generated at L1), `crates/gateway/src/main.rs` CLI. **Built by** B5.

## E7. Pairing by secret proves the vault key

**Rule.** `POST /v3/pair` with kind `secret` carries `{vault_id, label, secret, nonce, signature}`. The signature is over `u32be(24) ‖ "centraid-gateway-pair-v3" ‖ gateway_id ‖ vault_id ‖ blake3(secret) ‖ nonce`. The gateway checks the nonce (E5), the secret as today, then the signature, in that order and answers `UNAUTHORIZED` for any failure, spending nothing. `VAULT_KNOWN` and the rest stay.

**What it stops, and what it does not.** It stops someone who has the QR (or a vault id, which is a public key) from admitting a vault id they do not hold the key of, so a stranger cannot squat the member's vault address on this gateway and make the member's own pairing `VAULT_KNOWN`. It does **not** stop a photographer who pairs their own vault with the secret first; that spends the member's code. The member then runs `pair` again, and the gateway prints the safety number of every pairing as it lands (existing), so the unexpected pairing is visible at the console. See "For the owner".

**Why.** Gap 7. **Replaces.** `pair_by_secret` and `PairRequest`'s secret shape. **Built by** B6.

## E8. The sealed gateway directory

**Rule.** The directory is an ordinary sealed file, written like any other, whose name is derived from the vault's keys and its own content:

```text
directory plaintext = JSON { "v": 1, "gateways": [ { "gateway_id": hex16, "addrs": [..], "pin": hex32, "label": text } ] }   at most 16 entries, sorted by gateway_id
directory name      = name(keys, PlaintextHash(BLAKE3(directory plaintext)), 0)   the sealed-name function of naming.rs
```

The name is a keyed hash under `K_name` (so it is unique to this vault and unguessable), and the object sits in the vault's own namespace at each gateway like any part. It is **immutable**: a change to the set of gateways writes a new directory under a new name. The root manifest (E9) carries `directory: <name>`, so the directory is read through the head like everything else. It holds addresses, certificate pins and labels, **never a token**.

**Rewritten** when the member pairs a gateway, forgets one, or when a gateway's addresses, pin or label change; each marks the `gateway` rows `directory_dirty` and owes a snapshot (which re-uses every unchanged range name, so it costs one manifest, one tree leaf and the directory). The old directory object is dropped by normal collection (E9, B10) once no kept snapshot names it.

**Restore uses it.** A restoring phone derives the vault's keys, asks each gateway address it has (the one scanned or typed, then each from the directory it learns) for a read grant (E5, with nonce), reads each reachable head, verifies its signature (E2), and picks the greatest `(epoch, generation)` (ties broken by `writes`). It fetches that head's manifest and directory, claims at every gateway the directory lists that answers (the claim names the head it checked, as today), and reports every listed gateway it could not reach.

**One gateway.** If the directory lists one gateway, cannot be read, or lists more gateways than answered, the restore does not claim silently: it shows the newest backup's date and the gateway's label and asks. Sentence (for the copy check, row B16): "The newest backup I can find is from {date}, on {label}. I can't tell whether a newer one exists on a gateway I can't reach. Restore this one?" The phone claims only after the member says yes.

**Does not link vaults.** The object is sealed under keys of one vault and named under that vault's `K_name`; a gateway holding several vaults of one member sees unrelated ciphertext under unrelated vault ids and unrelated names (product principle 2). The directory lists no other vault's id.

**Rejected.** (a) A fixed-name mutable directory: gateways are write-once by name and digest, so a rewrite would be `NAME_TAKEN`. (b) A versioned name `name(tag, n)` probed `n = 0,1,2…`: unbounded probing and holes after collection.

**Replaces.** `phone/restore.rs` gateway discovery (`GAP`/`probe` over index only, the single-gateway trust in head choice), `pair.rs` has no directory; adds `backup/directory.rs`. **Built by** B8 (with the manifest field from B9).

## E9. Manifest version 4

**Rule.** `MANIFEST_VERSION = 4`. A v3 manifest is refused with the dev-vault sentence (E13). The manifest is a two-level tree so a 1 GB vault does not make a 2.4 MB JSON and a changed page rewrites one leaf, not the whole listing.

```text
root manifest (sealed JSON, named by name(keys, BLAKE3(json), 0) as today)
  v: 4, vault_id, taken_at_ms, page_size, db_len, db_hash, user_version, writes, written_at_ms, app,
  census,                                   as v3
  directory: <name>                         E8
  ranges_tree: [ { first: u32, count: u32, name, d: hex32 } ... ]   leaves of the page ranges, in order
  blobs_tree:  [ { first: u32, count: u32, name, d: hex32 } ... ]   leaves of the blob parts, in order

leaf (sealed JSON, one object, name derived from its own plaintext hash)
  ranges leaf: [ { i, name, len, d: [hex32] } ]        d: one digest per sealed chunk of the part (below)
  blobs leaf:  [ { h: hex32 plaintext hash, len, parts: [ { i, name, d: [hex32] | null } ] } ]
```

**Fan-out.** At most `LEAF_ENTRIES = 1024` entries per leaf and at most `ROOT_LEAVES = 4096` leaves per tree (4 million ranges, a 256 GB vault); more is refused with the existing "too large to back up" wait reason. Leaf `d` in the root is the BLAKE3 of the leaf's sealed bytes **as acknowledged**; unlike a part, a leaf is sealed once and the same bytes go to every gateway (it sits in the outbox like a part).

**Which digest.** The digest recorded for a part is the BLAKE3 of the **plaintext of each sealed chunk as it opens** (the bytes under the tag; compressed bytes when the part is compressed), one digest per 4 MiB chunk, so a range part (one chunk) has exactly one and a large original has up to sixteen per part. It is **not** a digest of the ciphertext. Reasons: (1) sealing is salted and every chunk has a random nonce (`sealed.rs`), so the same name sealed twice has two different ciphertext digests, and the manifest is shared by every gateway; a plaintext digest is a function of the name alone. (2) A sampled chunk can only be checked against a chunk digest (E10); a whole-part digest would need the whole part. (3) The gateway's own digest (ciphertext, kept per object) stays what it is: the transport check and the scrub's reference, with nothing recorded about it in the manifest. The sealer returns each chunk's digest as a by-product of the pass that already hashes the file (a change in `crates/media/src/sealed.rs`'s `PartSealer`, row B9). A blob part whose bytes have not arrived yet (`d: null`) names the part for collection (E9 below) and gets its digests in the next snapshot, which the arrival of the bytes owes (E11).

**A damaged or missing kept manifest stops collection.** Collection (B10) needs every kept snapshot's root and every leaf at that gateway. A kept snapshot whose root or leaf cannot be fetched, opened, or whose name does not derive from its bytes stops collection **for that gateway**, deletes nothing there, and the Backup screen says one old backup cannot be read. Nothing is counted across passes and nothing gives the snapshot up: it leaves the kept set only when retention drops it, so the stop is bounded by the retention horizon. An unreadable newest head is not repaired: the "head not whole" rule already makes a new snapshot due at once.

**Exact collection (B10).** The live set is **the union, over every kept snapshot, of its root, its leaves, its ranges' names, its blob parts' names and its directory, plus the names the vault itself implies now (`content_names`, the open snapshot), plus the names in the outbox**. Retention is as today (7 daily, 4 weekly, 6 monthly). A listed object in none of them is garbage and is deleted by a signed delete (held seven days by the gateway). The per-name "first seen unlive" record, `first_unlive` handling in `retention.rs` (`collectable`, `collectable_among`) and its future-dated-snapshot special case are deleted: a name is either in the union or it is a grave, and a grave goes at once.

**Why.** Decision 3 and B10: a digest per part makes read-back measurable and the tree keeps manifests small. **Rejected.** BLAKE3 of the ciphertext (non-unique across gateways, above). One flat `ranges` list (v3; its size grows with the vault).

**Replaces.** `Manifest`, `RangeRef`, `MANIFEST_VERSION`, `Manifest::validate`, `snapshot::describe`, `retention::live_names`, `retention::collectable*`, `retention::garbage` callers, `restore::fetch_and_assemble`'s flat range loop. **Built by** B9 (format) and B10 (collection).

## E10. Read-back sampling

**Rule.** Each pass samples, per gateway reached, `SAMPLE_CHUNKS = 64` sealed chunks drawn at random from the newest head snapshot's parts, stopping early at `SAMPLE_BYTES = 64 MiB` of ciphertext read; on a metered link it samples `8` chunks of at most 1 MiB. A *chunk* is one sealed chunk of a part (a range part is one chunk of 64 KiB plus framing; an original's chunk is at most 4 MiB plus 44 bytes of framing and tag). The phone reads exactly that chunk with the gateway's existing single `Range` read (`GET /v3/v/{vault}/o/{name}`, 206), plus the 30-byte header for the salt, opens it (the tag authenticates it under the part's key) and compares BLAKE3 of the opened bytes with the digest the tree lists (E9). A chunk that is gone, that will not open or whose digest differs puts its part back in the outbox for that gateway (the stored copy is the damaged one: the phone signs a delete of the name and re-sends the part at once; the re-send is a `PUT` of a held name, which stores the new bytes and clears the hold, E6).

**The draw (no clock).** Population: the newest head snapshot's chunks numbered `0..N-1` in tree order (ranges leaves, then blobs leaves, skipping `d: null`). The draw for sample `k` of this pass is

```text
sample_key = blake3::derive_key("centraid backup v2 sample", K_backup)      32 bytes
r(k)       = u64 from the first 8 bytes of blake3::keyed_hash(sample_key, u64be(counter) ‖ u64be(k)), big-endian
index(k)   = r(k) mod N        (skip an index already drawn this pass; try k+1)
```

`counter` is the gateway row's `sample_counter`, incremented in the same transaction that records the pass's result. Tests pin the draw by pinning `counter`, `N` and the keys; the gateway cannot predict a draw (it lacks `K_backup`), and no clock enters it. Modulo bias is under 2⁻³² for any `N` below 2³² and is ignored.

**The sentence a member reads** (template; the words go through the copy check in B16): "Each time I check, I read {s} of the {n} stored pieces, chosen at random. Every piece is read about once in {n/s} checks." With `s` the sample size actually read last pass and `n` the population. A check that read fewer than `SAMPLE_CHUNKS` because the link was metered or the budget ran out states the smaller `s`. The line never says "verified" or "backed up"; it says what was read and what opened.

**Needs the gateway** a ranged read. The single-range `GET` already exists (`rules/range.rs`, README table), so B13 needs no new route; B7's "ranged read" row is satisfied by what is there (see the report).

**Why.** Gap 6: four whole parts out of 100,000 reads about 0.004%; 64 chunks of 4 MiB or less read more bytes and cover parts that matter. **Rejected.** A wall-clock budget ("check for a minute"), and sampling whole parts (an original is up to 64 MiB).

**Replaces.** `verify::read_back_large`, `SAMPLE_MAX_BYTES`, `Ledger::oldest_verified_large`, `confirmed.verified_ms`, the "3 random parts" read-back in `phone/drain.rs`, `check.rs`'s `pick_sample` (its `SAMPLE_FILES` etc. stay for the whole-file "Check my backup"). **Built by** B13.

## E11. Device state: three tables

**Rule.** `<stem>.state.db` replaces `<stem>.backup.db`. Exactly three tables, STRICT, no key-value table. `addrs` is a JSON array text column, the one exception: the pass reads it whole and nothing queries or indexes it. `application_id = 0x43425331` (`CBS1`), `user_version` is the rung count (1 for this build); a newer rung is refused; the older ledger (`CBL1`) found beside the vault is **deleted without being read** (decision 8). Rungs live as `crates/vault/src/backup/state_ladder/NNN_*.sql`, applied in one transaction each, never edited after the first release. No host clock in DDL.

```sql
CREATE TABLE gateway (
  gateway_id     TEXT PRIMARY KEY CHECK (length(gateway_id) = 32 AND gateway_id NOT GLOB '*[^0-9a-f]*'),
  addrs          TEXT NOT NULL,                       -- JSON array of "host:port", read by the pass, never queried
  cert_der       BLOB NOT NULL,
  label          TEXT NOT NULL,
  epoch          INTEGER NOT NULL CHECK (epoch >= 1), -- the writer epoch this phone's token there was minted at
  head           TEXT CHECK (head IS NULL OR (length(head) = 64 AND head NOT GLOB '*[^0-9a-f]*')),
  generation     INTEGER NOT NULL DEFAULT 0 CHECK (generation >= 0),
  writes         INTEGER NOT NULL DEFAULT 0 CHECK (writes >= 0),   -- of the head this phone last set
  cursor         INTEGER NOT NULL DEFAULT 0 CHECK (cursor >= 0),   -- last blob.seq handed to the outbox
  reach          TEXT NOT NULL DEFAULT 'ok' CHECK (reach IN
                   ('ok','unreachable','pair_again','refused_disk','refused_large','refused_other',
                    'moved','frozen','gateway_old','busy')),
  moved_epoch    INTEGER CHECK ((reach = 'moved') = (moved_epoch IS NOT NULL)),
  reach_ms       INTEGER,
  paired_ms      INTEGER NOT NULL,
  seen_ms        INTEGER,
  ack_ms         INTEGER,
  sample_counter INTEGER NOT NULL DEFAULT 0 CHECK (sample_counter >= 0),
  directory_dirty INTEGER NOT NULL DEFAULT 1 CHECK (directory_dirty IN (0, 1))
) STRICT;

CREATE TABLE outbox (
  gateway_id TEXT NOT NULL REFERENCES gateway (gateway_id) ON DELETE CASCADE,
  name       TEXT NOT NULL CHECK (length(name) = 64 AND name NOT GLOB '*[^0-9a-f]*'),
  kind       TEXT NOT NULL CHECK (kind IN ('range','leaf','manifest','directory','blob')),
  hash       TEXT CHECK ((kind = 'blob') = (hash IS NOT NULL)),    -- plaintext hash of a blob part's file
  part_path  TEXT,                                                -- the sealed file; NULL = owed but not yet sealed
  waiting    TEXT CHECK (waiting IS NULL OR (waiting IN ('lapsed','bytes') AND part_path IS NULL)), -- why an unsealed row waits: no renter, or bytes not yet on this phone
  size       INTEGER CHECK (part_path IS NULL OR size >= 0),
  digest     TEXT CHECK ((part_path IS NULL) = (digest IS NULL)), -- BLAKE3 of the sealed file as spooled
  media_type TEXT CHECK ((kind = 'blob') = (media_type IS NOT NULL)),
  created_ms INTEGER NOT NULL,
  handed_ms  INTEGER,
  attempts   INTEGER NOT NULL DEFAULT 0 CHECK (attempts >= 0),
  last_error TEXT,
  PRIMARY KEY (gateway_id, name)
) STRICT, WITHOUT ROWID;
CREATE INDEX outbox_in_order ON outbox (gateway_id, kind = 'manifest', created_ms, name);
CREATE INDEX outbox_waiting ON outbox (gateway_id, waiting, name) WHERE waiting IS NOT NULL;

CREATE TABLE local_bytes (          -- unchanged from the ledger's, minus verified_ms (E10 replaces it)
  hash   TEXT PRIMARY KEY CHECK (length(hash) = 64 AND hash NOT GLOB '*[^0-9a-f]*'),
  source TEXT NOT NULL CHECK (source IN ('os','store')),
  ref    TEXT CHECK ((source = 'os') = (ref IS NOT NULL AND ref <> '')),
  edited INTEGER NOT NULL DEFAULT 0 CHECK (edited IN (0, 1) AND (edited = 0 OR source = 'os'))
) STRICT;
```

The token is **not** a column (E12). The `snapshot` table and the `meta` table are gone: the one fact `meta` held that matters (a snapshot is owed) is derived, not stored: a snapshot is owed when `directory_dirty` is 1 for any gateway, when a blob part was confirmed whose digest no head records, or when the vault's `writes`/`user_version` differ from the newest head's. The previous head's manifest is kept in the spool under its name; it is fetched from a gateway only when that spool file is absent.

**The per-gateway cursor and what the outbox covers.** Lane V adds `blob.seq` (V12): assigned at insert only, from a counter that never reuses a value (a blob row deleted by collection and inserted again gets a new value naturally); lane V is not asked to re-stamp on revival. A pass asks, per gateway, `SELECT hash, byte_size, seq FROM blob WHERE seq > :cursor ORDER BY seq LIMIT 500`; for each row it computes the part names, asks `exists`, writes an outbox row for each missing name, then sets `cursor` to the last `seq`, in one transaction. An unchanged library returns no rows: one statement and one gateway call. The outbox holds everything the cursor has already passed but that is not done:

- **Lapsed blobs.** A blob row with no renter left (lapsed, awaiting the vault's own collection) is skipped as the cursor passes it, but the pass leaves an outbox row for each of its part names with `waiting = 'lapsed'` and `part_path` NULL. Each pass re-examines only `waiting = 'lapsed'` rows (`outbox_waiting`, a partial index): a blob rented again becomes owed (`waiting` NULL, `exists` asked), a blob row gone has its rows deleted. The cost is bounded by the number of lapsed blobs, not the library. A blob that is collected and inserted again gets a new `seq`, so the cursor meets it as new.
- **Renter changes.** A renter added to an existing rented blob changes nothing on the gateway; no outbox row.
- **Bytes that arrive later.** An original only the OS library holds gets an outbox row with `part_path` NULL and `waiting = 'bytes'`; `need_bytes` names it; sealing fills `part_path`, `size`, `digest`. A part whose gateway refused, lost it (read-back, E10) or answered missing in `exists` returns to the outbox.

**Reset rules.** *Restore in place* (a claim at each gateway; the vault is replaced): for each gateway row `epoch = claim epoch`, `head = the head claimed against`, `generation = 0`, `writes = 0`, `cursor = 0`, `reach = 'ok'`, `moved_epoch = NULL`, `sample_counter = 0`, `directory_dirty = 1`; the outbox is emptied and its spool files removed; `local_bytes` is kept (it is about this device, not the vault's history). *Forget a gateway*: delete the row (cascade drops its outbox rows; unreferenced spool files are swept); no confirmation, as today; `local_bytes` untouched. *The state file is lost*: the phone has no gateway rows and re-pairs; each pairing is a claim (the vault key is the seed's), which also revokes the lost token at the gateway (E5).

**Replaces.** All of `vault/src/backup/ledger.rs` (`Ledger`, `Destination`, `Queued`, `PartKind`, `SNAPSHOT_OWED_KEY` and every `meta` key, `set_moved`, `confirmed` and its queries), `mover.rs`'s confirmed bookkeeping, `phone/mod.rs`'s ledger references, the four ledger defects the issue lists as not done on purpose. **Built by** B14 (tables, reset), B12 (cursor, outbox rows).

## E12. Credential storage

**Rule.** The gateway token is stored by the shell, in the **device secret store the shells already have** (`SecretBatch`, `plumbing_screens.proto`; `SecretStores.swift`, `SecretStores.kt`), under key `gateway-token.<vault_id hex>.<gateway_id hex>`.

- **iOS.** `kSecClassGenericPassword`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, no `kSecAttrSynchronizable`: this device only, never in iCloud Keychain nor an encrypted backup. `AfterFirstUnlock` (not `WhenUnlocked`) is what lets a background pass, which runs with the phone locked, read it after the first unlock since boot.
- **Android.** The existing device store: the value AES-GCM sealed under a non-exportable Android Keystore key (`KeyGenParameterSpec`, purposes encrypt and decrypt, no user-authentication requirement, so a background worker can read it), stored in app-private preferences that are excluded from backup.

**What crosses the core boundary.** The core still writes no key to disk. `pair` (and a claim) returns the token to the core in memory; the core asks the shell to store it with a `SecretBatch` put and writes the `gateway` row **only after** the put answers ok. The core opens with the tokens of its gateway rows supplied by the shell in the open configuration, like the seed (`CONTRACT.md` §4b), and keeps them in memory. A pass for a gateway whose token is absent does not guess: `reach = 'pair_again'`.

**A lost wrapping key means pair again.** If the Keystore key is gone (a factory-reset keystore, a restored device) or the item is missing, the read fails or is empty and the gateway row goes `pair_again`; the member pairs again, which is a claim at epoch + 1 and so revokes the lost token at the gateway (E5). The stale token is not a hole.

**Why.** Gap 5: the token is a plaintext column in `<stem>.backup.db` today. **Rejected.** Encrypting the token with a key derived from the seed and keeping it in the database (the seed is in the same Keychain, so no isolation is gained, and the core would hold a key at rest).

**Replaces.** `Destination.token`, `put_destination` writing it, `Ledger`'s `token` column, `link.rs` reading it from the ledger. **Built by** B15.

## E13. Protocol 3 and schema versioning

**Gateway `state.db`.** `application_id = 0x43475733` (`CGW3`), `user_version = 1` for this build. The schema is a ladder, `crates/gateway/src/server/sql/ladder/NNN_*.sql`, one transaction per rung; the always-run idempotent `schema.sql` is deleted. Opening a `state.db`:

| Found | Does |
| --- | --- |
| no file | founds rung 1, sets `application_id` and `user_version` |
| `application_id` 0 and tables present (a v2 gateway), or any other id | refuses; changes nothing; sentence below |
| `user_version` above this build's | refuses; changes nothing; "This gateway's data was written by a newer version of the gateway (rung {n}); this one reads rung {m}. Update the gateway; nothing was changed." |
| `user_version` below this build's | applies the missing rungs |

The sentence for the dev data directory (decision 8), printed by `serve` and `pairings` and exit code 2: **"This data folder was made by an earlier version of the gateway, and this version cannot open it. Nothing was changed. Move the folder aside and start again; every phone will need to pair again."**

**The client.** A phone first contacts `GET /v3/info`. A gateway that answers `/v3/info` with `protocol < REQUIRED_PROTOCOL` (3), or answers `NOT_FOUND`/405 to `/v3/info` and answers `/v2/info` (an older gateway), is refused with a typed `GatewayTooOld { found, required }` and the member reads: "This gateway runs an older version. Update it, then pair again." Every pass handshakes `info` per gateway and sets `reach = 'gateway_old'` on a downgrade. There is no fallback to v2.

**Why.** B1. **Rejected.** Serving v2 and v3 side by side (decision 8: dev state is not migrated). **Replaces.** `PROTOCOL`, every `/v2/` route string in `server/http.rs` and `client/mod.rs`, `schema.sql`. **Built by** B1.

## E14. Gateway housekeeping numbers and rules (B7)

- **Seek paging.** Every listing is keyset-paged by its table's primary key, passed as the last row's key, never `OFFSET`: `objects` and `held` by `(vault, name)`; `snapshots` by `(vault, name)` with `after=<name>&limit` (the phone sorts by `taken_at_ms`); the purge sweep by `(purge_after_ms, vault, name)` over `object_by_purge ON object (purge_after_ms, vault, name) WHERE purge_after_ms IS NOT NULL`; the scrub by `(vault, name)`; `pairings` by vault. Page size `LIST_LIMIT` (1000). The gateway's plan test asserts each statement walks an index.
- **A bundle commits in one transaction.** Frames are staged and renamed first; then one `BEGIN IMMEDIATE` inserts every row and commits. A crash between leaves unlisted files, which the orphan sweep (below) removes; it never leaves a row with no bytes.
- **Ranged read.** Exists (single `Range`, 206). No new route.
- **Pairing secrets.** A used secret is pruned `7 days` after `used_at_ms`; an unused one `7 days` after `expires_at_ms`, in the hourly sweep; at most `MAX_LIVE_SECRETS = 64` unused unexpired secrets exist (minting a 65th drops the oldest live one).
- **Delete a vault.** `centraid-gateway vault <id8> delete-vault --yes`, only on a frozen vault (E6): removes the tokens, revoked tokens, head, snapshots, claim and object rows and unlinks the files, in `LIST_LIMIT` pages by `(vault, name)`, logging counts only. Not held: it is the operator's explicit act on a frozen vault.
- **Orphan sweep.** Once per sweep, list `objects/` once and delete a file that has no `object` row **and** whose mtime is more than 1 hour old (a bundle in flight is younger). `incoming/` is emptied at `serve`, as today.
- **Token kind is tied to epoch.** `CHECK ((kind = 'read') = (epoch = 0) AND (kind <> 'secret' OR epoch = 1) AND (kind <> 'claim' OR epoch >= 2))`, and the rules refuse to mint otherwise.
- **The test harness is not in the production build.** `server::harness` sits behind a cargo feature `test-harness`, off by default; crates that spawn it (`centraid`, `centraid-core` tests, the gateway's own) enable it in `dev-dependencies`. `cargo xtask rules` fails if the release gateway binary links it.
- **`taken_at_ms` clock bound.** A head whose `taken_at_ms` is more than `MAX_CLOCK_AHEAD_MS = 300_000` ahead of the gateway's `now_ms` is refused with new closed code `CLOCK_AHEAD` (400, companion `skew_ms`). The phone re-signs with `taken_at_ms = min(manifest, gateway time_ms)`; it never retries unchanged. No bound in the past (an old snapshot stays honest).
- **Purge gap.** The watched-time rule of E6 (decision 26).

**Replaces.** the always-run `schema.sql`, `server/harness` unconditional compile, `rules/limits.rs` additions (the new constants above, shared by both ends and generated into the phone's `NAMES_PER_CALL`-style mirrors at L1). **Built by** B7.
