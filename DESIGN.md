# DESIGN.md — Centraid

This is the normative product constitution and the machine-readable design brief in the official [design.md](https://github.com/google-labs-code/design.md) format. The phone is its base: SwiftUI and Compose over a Kotlin Multiplatform kit and a Rust core, with no desktop shell, no web shell and no blueprint plane ([#1029](https://github.com/srikanth235/centraid/issues/1029), [#1020](https://github.com/srikanth235/centraid/issues/1020)). Values in this file are pinned to [packages/design/src](packages/design/src) by the design-md tests; the official linter runs through `bun run lint:design-md`. The rulings of the web era that no longer govern a surface live in [docs/decisions.md](docs/decisions.md#designmds-web-era-rulings-superseded-2026-10-15), each with its supersession marker.

## Overview

Centraid is a personal, local-first superapp: one shell wrapping many first-party apps whose content characters could not be more different — a photo grid wants to disappear behind imagery, a document wants reading comfort, an agenda wants dense scannable structure. They have to feel like rooms in one house, not separate products, while each app's content leads.

The answer is a **binding layer of five invariants**. Everything not named as an invariant is explicitly the app's own choice, and the freedom table below is as binding as the invariants are. That division is the system.

The product grammar is one semantic contract, lowered once for the phone: `toNativeTheme(scheme)` writes concrete values as data, and the SwiftUI and Compose kits read them. A role is a name, a meaning, and a contrast obligation together. `packages/design` still emits CSS (`toCss()`) and the pointer values beside the phone's, solely for the public site centraid.dev ([design machinery](docs/design-machinery.md)); no phone surface reads them.

### The five invariants

1. **Navigation is the band.** Two bands sit at the foot: the **shell band** — Home, Chat and Backup on iOS; Home and Backup on Android, which has no Chat tab yet — and each app's own band, two to four places and then More ([R-CHROME-5](docs/decisions.md#app-chrome-one-grammar-for-every-app-root)). The shell band lists the frame's places and never an installed app: every app is a tile on Home. A band is never themed by an app and never scrolls away. A band is capped at 5 apps plus More; a tab below 44px stops being a tap target, so the cap is a constraint and not a preference.
2. **One ramp, one face.** The touch sizes are the type table the phone draws: one bundled face, two weights. Instrument Sans sets the whole product; hierarchy comes from named roles, not an app-level family. The platform code stack is allowed only for code, inline literals, and file paths. Nothing falls below 11px, navigation labels never fall below `--text-soft`, and numerics are proportional, tabular Sans in every app without exception. Native consumes each role's typed `nativeDelta`, and both shells follow the system text size within a cap ([Dynamic Type](#typography)).
3. **One control vocabulary, and the shell owns no colour.** Every control is ink on paper; commit is the Ink button, never a hue, and there is at most one filled ink element per view. Destructive is an **outlined** button in `--net`, never a fill. The `--link` hue is the platform chrome's tint and the ink of a text verb (`KitLink`, a status line's action), and it never appears on a kit button. Pressed is the one interaction state: `--bg-press` under the finger (iOS [`KitRowPress`](mobile/iosApp/Sources/Kit/Rows.swift), Android [`bandPress`](mobile/androidApp/src/main/kotlin/dev/centraid/android/kit/Band.kt)). State is never expressed with container `opacity` — a recessive state takes its own token on the leaf element.
4. **One spatial rhythm.** 4px base, scale 4 / 8 / 12 / 16 / 24 / 32. Targets and rows are 44, the page margin is 18. A 34 target exists only inside a dense row, and only through the named constant (`targetMinFine`). Text in a fixed-height container is line-clamped, never clipped — a clipped baseline reads as a rendering bug.
5. **One motion and feedback grammar.** Entry and settle at 280ms, a state change at 140ms, reduced motion honoured. State is reported on one status line, docked at the foot of the place directly above its band — or at the foot of a pushed page, a sheet or an editor, which draw no band — and the shell's import line takes that same seat. Never a toast, a badge count, a red dot, a bounce, a parallax or a scale. A screen's load is a skeleton (`ReadStateView`); a spinner (`KitSpinner`, `StageSpinner`) exists only for work with no shape to draw — a save in flight, a transfer starting — and work whose count is known gets a determinate bar.

### What an app may set for itself

This list is as important as the invariants. An app that stays inside it needs no permission from the system, and an app that steps outside it is changing the product, not its own screen.

| Property | Freedom | Token |
| --- | --- | --- |
| Layout | Free. Full-bleed grid, reading measure, 7-column table, message stack. No constraint. | — |
| Colour | One identity hue, in the icon chip and as a content marker. **Never on a control.** | `--app-hue`, `--app-identity`, `--c-*` |
| Surface | **FIXED — the one row here that is not a freedom.** The phone is one surface, touch; the pointer values belong to the site. Width is a canvas, not a surface; a narrower or wider screen carries no rules of its own, so there is no second set of values for an app to declare and no second word for the middle one. | `targetMinCoarse`, `pageMargin` |

The table lost two rows with v4s. **Primary register** is gone: the face follows the role, not the app, so there is no reading-or-scanning choice to declare and no `register` field on a manifest. **Surface tone** is gone: there is one ground per theme, `#FDFDFC` light and `#0E0E0E` dark, and the seam between two apps is a route change rather than a colour change. Neither is a setting an app may reach for by another name. The table lost a third row with the phone as the base: **Density tier** — `comfortable`, `compact` or `dense`, set by `data-density` — was a pointer-surface freedom, and no phone surface reads it ([R-DESIGN-5](docs/decisions.md#designmds-web-era-rulings-superseded-2026-10-15)).

Everything else — control shape, ink ramp, hairlines, motion, the bands, the status line — belongs to the system.

### The app identity hues

`oklch(0.50 0.09 h)` in light and `oklch(0.72 0.09 h)` in dark, resolved to sRGB hex at build time by `oklchToHex` in [packages/design/src/oklab.ts](packages/design/src/oklab.ts). One lightness and one chroma per theme, only the hue moves — which is what makes the hues equally loud and stops one app out-shouting another. A third-party hue is clamped to the same chroma and lightness before it is admitted.

| App    | Hue | Key      | App    | Hue | Key      |
| ------ | --- | -------- | ------ | --- | -------- |
| locker | 0   | `rose`   | docs   | 210 | `teal`   |
| photos | 28  | `amber`  | notes  | 255 | `slate`  |
| tasks  | 70  | `ochre`  | money  | 290 | `indigo` |
| agenda | 150 | `forest` | people | 320 | `violet` |

Home takes no hue: it renders in `--text-soft`. Colour is never the only channel — every app mark is distinguishable by silhouette alone at 14px, which is what makes the hue system safe for colour-blind readers.

## Colors

**The shell spends no colour.** `--accent` is ink in both themes, and so are `--accent-fill`, `--accent-deep`, `--accent-text` and `--accent-light`. `--accent-soft` is an 8% ink wash, never a fill. If a hue ever reappears in this family, every app identity colour silently stops meaning "this belongs to that app". The hover rungs — `--accent-deep-hover`, `--accent-hover`, `--net-hover` and `--bg-hover` — are the site's: the phone has no hover and presses on `--bg-press`.

Three hues are reserved and named. `--link` is the platform chrome's tint, the ink of a text verb, and text selection, and is never permitted on a kit button; `--bg-sel` and `--line-sel` are washes of it. `--focus-ring-color` is the ring, the site's — the phone's focus is the platform's. `--net` is "this leaves the device" — type, a border or a 2px rule (a refusal, a destructive label), never a fill, because nothing alarming should be a large filled surface. `--danger` is solved from the same base as `--net` so a destructive action and a network egress read as one consequence.

System signals use exactly three tones: `quiet` (tertiary ink only), `attention` (`#8A6520` / `#D8A64E`), and `urgent` (`--net`). `--attention` is deliberately distinct from the general-purpose `--warning` semantic role: it is the one amber rung members learn on the ambient ribbon and its escalation path. Like `--net`, it may appear as type, a border, or a 2px rule, never as a fill.

`--net` carries a rung of its own for the site's pointer, `--net-hover` (`#7F3026` / `#EC9C8D`), which steps AWAY from the paper because a warning that gets quieter under the pointer is the wrong answer. `--net-wash` (`rgba(154,59,46,.07)` / `rgba(224,136,120,.11)`) is the ONE tint of `--net` the system permits, and it is the exception that states the rule rather than breaking it: it is faint enough that `--net` and the whole ink ramp still clear AA painted on top of it, which is precisely what keeps it from becoming the large alarming surface `--net` forbids. It is built from `--net` rather than typed beside it, and it is the one wash whose alpha differs per theme — a tint on near-black has to work harder to be seen — so it lowers as a concrete `rgba()` instead of the shared `color-mix(… N%, transparent)` that `--accent-soft` and `--bg-sel` use.

`--seam` (`#B4441F` / `#E0864F`) is the state the system otherwise had no word for: **not yet, and not wrong** — pending, expiring, invited. `--warning` says a reading is degraded and `--net` says bytes leave the device, and neither is true of an invitation nobody has accepted. It is a border, a status chip, and status text, on the same terms as `--net`: never a large filled surface.

`--stage` and `--on-stage` are the opaque media ground and its ink for a viewer, a slideshow, and an editor (the Photos v4 handoff, §2.2/§B) — `#0B0B0B` / `#EDEDEC`, **the same literal in both themes**, because the media ground does not follow the theme: a viewer that lightened under "light mode" would blow out the photograph it is framing. `--stage-line` (`#2A2A29`) is the hairline between chrome and media ON the stage, because `--line` is invisible against near-black. `--stage-sunken` (`#1A1A19`) is the recess cut INTO the stage — the media transport's unplayed track and any other trough whose fill is `--on-stage` — because `--bg-sunken` follows the PAGE and would punch a near-white hole in the media ground, while `--stage-line` is tuned to be seen as an edge where a trough is tuned to recede. `--skel` (`#E4E3E0` / `#1E1E1D`) is the ground a tile paints before its bytes arrive; `--bg-elev` reads as a card, and an absence is not a card, so a loading tile gets its own rung rather than borrowing one that implies content already landed. None of the three moves a token that existed before it, and none is a new hue.

The surface roles are `--bg`, `--bg-app`, `--bg-elev`, `--bg-sunken`, `--bg-wall`, `--bg-chrome`, `--bg-hud`, `--bg-hover`, `--bg-press`, and `--bg-sel`; of the two interaction grounds, `--bg-press` is the phone's and `--bg-hover` the site's. **There is one page, and an app does not retune it.** A per-app surface-tone axis (`data-tone` → `--bg-tone-*`, five tones) shipped and was retired for two reasons, both measured: retuning `--bg` alone while `--bg-elev`/`--bg-sunken`/`--skel` stayed pinned inverted the paper metaphor — Photos drew cards LIGHTER than its page in light mode, where the system's rule is that raised paper is darker-in-light and lighter-in-dark — and, on device, four of the five tones sat within 0.7 L* of neutral while dark mode's whole spread was 2.4 L*, an axis nobody could perceive. If a page tone ever returns, it must carry its whole surface SET — page, elev, sunken, and skel together — never `--bg` alone. Surfaces are PAPER, not elevation: in light the raised surface is darker than the page, in dark it is lighter — a tile is a sheet laid on the page, not a plane floating above it.

The ink roles are `--text`, `--text-soft`, `--text-faint`, `--text-ghost`, `--text-inv`, `--on-accent`, and `--text-disabled`. **`--text-faint` is validated against the deepest surface in the system, not against `--bg`** — in dark every raised surface is lighter than the page, and in light `--bg-wall` is deeper than both, so measuring on the page alone guarantees a failure the moment text lands on a card. The ladder is four levels — `#141414` / `#5A5A58` / `#6C6C69` / `#888885` in light and `#EDEDEC` / `#9A9A98` / `#878785` / `#656563` in dark — and its obligations are not all the same: `--text`, `--text-soft`, and `--text-faint` owe AA on every surface (measured against `--bg-app`, the worst of them: 6.02:1 and 4.58:1 for the two secondary rungs), while `--text-ghost` owes 3:1, because its own role forbids it from carrying body copy at all. Deepening the secondary rungs past their floors is not free — the ramp is only a ramp while its rungs are tellable apart, which is why the floors are paired with an ordering assertion rather than trusted alone. Lines are `--line` (hairline separators, tile borders), `--line-strong` (control borders, section rules), and `--line-sel`. Focus is the platform's on the phone; `--focus-ring` plus `--focus-ring-color` is the site's.

The semantic states are `--success`, `--warning`, and `--danger`. Each is solved per theme against the hardest surface it lands on AND against a 12% wash of itself; hue separation is measured in Oklab, so a merely legible grey is not a status colour. Disabled text uses `--text-disabled`; non-text disabled affordances use `--o-disabled: 0.45` once, on the LEAF, never on a container — opacity composites every descendant and silently invalidates token-level contrast.

The role registry marks values as `literal`, `scalar`, `solved`, or `wash`; only adapters such as `--target-min` carry environment-dependent values. Both ramps are literal: the `--bg-l` anchor retired because the Binding Layer's dark surfaces are warm-tinted paper, which a one-knob greyscale calc cannot express. There is no alias layer. `--r-*`, `--sp-*`, and `--font-*` are the same names and values in the site's CSS as in the registry the phone's table is lowered from.

## Typography

There is **one** bundled face, shipped from the repo with no network fetch: `Instrument Sans` at 400 and 600. Source Serif 4 is withdrawn with v8, so display, reading, UI, and numerics all draw from the same stack with mandatory CJK fallbacks. `--font-code` names the platform code stack (`ui-monospace, SFMono-Regular, Menlo, …`) and ships no bytes; it is reached only by fenced code, inline literals, file paths, keyboard chips, and secrets — never by a timestamp, count, duration, or file size.

The weights are **two**, here and everywhere, and the table below is the whole ramp. One thing is true of the phone that is not true of the site, and it is a lowering rather than a rung: the 400 register is DRAWN by a derived 470 instance of the same family on native, because the native delta's +2px step scales the glyph without scaling the stroke and CoreText's grayscale antialiasing takes the rest. Nothing in this ramp names a 470 and nothing may; only the file behind the 400 register changes, and only on a touch surface. See [decisions.md](docs/decisions.md) and [packages/design/fonts](packages/design/fonts/README.md).

The Phone column is what the shells draw — the registry's size plus the native delta. The Site column is the registry's own pointer value, which `toCss()` emits for centraid.dev.

A **held pair** is a label that bolds when it becomes active: the `-on` half changes the weight and keeps the size and the leading, so a row of chips or a band of tabs cannot re-flow the moment one of them is chosen. A pair only holds if both halves resolve the same way on BOTH surfaces. There are three, and only four of the six halves are new roles: `--t-body`/`--t-label-on` at the body rung, `--t-annot-label`/`--t-annot-label-on` at the annotation rung, and `--t-band`/`--t-control` in the compact band. `--t-body-strong` is not a held half — it holds at 13 / 19 on touch while `--t-body` steps to 15 / 22 — and `--t-mono` is not the annotation label, because the numeric register binds tabular figures and its own `ltr`/`isolate` direction, which is exactly wrong for a word.

`--t-band` is the one role in the ramp that does not step up on touch, and the exception is arithmetic rather than editorial: invariant 1 caps a band at five destinations plus More, and at 390px those six labels come to 338px inside a 358px band at 11 / 15 — 386px at the annotation rung, which does not fit at any padding. Its active half is `--t-control`, which already holds on the same rung, so the pair stays held on both surfaces.

The legacy `mono` role name survives for consumer compatibility, but its meaning is numeric annotation in Instrument Sans. Fixed advance belongs to `--font-code`, not to that role.

Link is not a size role: it inherits and takes `--link`. It is underlined only inside running prose; a standalone text verb (`KitLink`) is not.

**Dynamic Type.** Both shells follow the system text size, so a member's setting reaches every role: iOS Dynamic Type, capped at `DynamicTypeSize.xxxLarge`, and Android's font scale, capped at 1.3. The `band` role holds its size at every setting — invariant 1's arithmetic above is why.

In the registry's CSS, every `--t-*` is a `font` shorthand, and the properties that shorthand cannot carry travel beside it as their own tokens rather than as decoration a stylesheet has to remember: `--t-display-tracking` −0.02em, `--t-title-tracking` −0.01em, `--t-eyebrow-tracking` 0.06em, `--t-eyebrow-transform` uppercase, and `--t-mono-numeric` tabular-nums. "Numerics are tabular in every app, without exception" is only true while that last one exists and is used.

The numeric role also declares its own reading direction: `--t-mono-direction` `ltr` and `--t-mono-bidi` `isolate`, set once on the role, never per span. A number is not a word — under RTL the bidi algorithm reorders a mixed digit-and-word run unless the role pins its direction and isolates it; a layout container must never carry the numeric face. Every role publishes a composable size token: `--t-display-size` 32px, `--t-title-size` 20px, `--t-reading-size` 17px, `--t-body-size` 13px, `--t-body-strong-size` 13px, `--t-small-size` 13px, `--t-small-strong-size` 13px, `--t-control-size` 11px, `--t-eyebrow-size` 11px, `--t-mono-size` 11px, `--t-label-on-size` 13px, `--t-annot-label-size` 11px, `--t-annot-label-on-size` 11px, and `--t-band-size` 11px. Duplicate values keep semantic names because pointer/touch moves roles onto different rungs; deduplicating by value would make a token change meaning across the surface boundary. There are no line-height rungs.

The phone draws the touch column; the pointer column is the site's. On touch, display steps down to 27 / 31; title and reading hold; body and section roles step up; annotation becomes 13 / 18; micro and the compact band hold at 11 / 15. The site's sheet defaults to touch and overrides once under `(pointer: fine)`; native consumes the pre-lowered touch values without parsing CSS. Width changes measure and column count, never type.

## Layout

`--sp-1` 4px, `--sp-2` 8px, `--sp-3` 12px, `--sp-4` 16px, `--sp-5` 24px, and `--sp-6` 32px are the one spacing scale; the 48px rung retired because 32px is the largest rhythm step the system has. The page margin is its own value beside the gaps — 18px — because a page margin is the distance from the paper's edge to the text block, not a gap between two things; it deliberately does not sit on the 4px ladder, and native lowers it as `pageMargin`.

The phone's metrics are tokens, not conventions: `--h-row` 44px is the row and the target (`targetMinCoarse`), and `metrics.bandCapsule` 52px is the band's frame capsule. A control is 44, never 34. The one 34 is the dense-row target, `targetMinFine`, named so that it can only be reached on purpose.

The registry still lowers the pointer values — `--h-control` 34px (44 on touch), `--h-segmented` 28px, `--w-stem` 240px, `--w-key-col` — the fact-list key column, 150px under a pointer and 110px on touch, `--w-app-rail` 232px with its row `--h-app-rail-row`, and a compact law at 720px — and `toCss()` emits them for centraid.dev alone; no phone surface reads them. They stay named here so the registry and this rulebook cannot drift apart, and the rulings they came from are superseded ([decisions.md](docs/decisions.md#designmds-web-era-rulings-superseded-2026-10-15)).

Radii are `--r-xs` 0px (content), `--r-sm` 4px (the one sub-control rung), `--r-md` 7px (controls), `--r-lg` 12px (containers), and `--r-pill` 999px. An app icon container is 26% of its own size, which no static token can carry — `iconChipRadius()` in [packages/design/src/radii.ts](packages/design/src/radii.ts) is the one source for it.

The target-min adapter is 44px on touch and 34px under a fine pointer; the phone is always touch, and `targetMinFine` is the one place it reads the 34px. Safe-area insets belong to the native renderer.

## Elevation & Depth

There is very little of it. `--bg-elev` is raised paper and `--bg-sunken` a recessed track. The `--shadow-sm`/`--shadow-md`/`--shadow-lg` rungs belong to the site's dialog and popover; a phone sheet is the platform's presentation over `--bg-elev`. Platform chrome is glass on iOS — the navigation bar, a sheet's grabber and detents — and the kit draws none: `--glass-sheen` is `none` in both themes, because the metaphor is a tinted paper label, not a button under a lens. `--device-wall` is a wall composite, not a content surface. An app icon container has no gradient, no gloss and no drop shadow.

Motion has two cases and two curves. Entry and settle is `--dur-2: 280ms` on `--ease-entry: cubic-bezier(0.2, 0.7, 0.2, 1)`; a state change is `--dur-1: 140ms` on `--ease: cubic-bezier(0.3, 0, 0.4, 1)`. Reduced motion is honoured everywhere: on the phone an animation takes the system setting (`accessibilityReduceMotion` on iOS) and the slide or entry becomes the change, and the site's `prefers-reduced-motion` is honoured in ONE global rule emitted by `toCss()` — duration to zero, opacity only — and never per component.

Feedback is one persistent status line, seated at the foot of the place directly above its band — or at the foot of a pushed page, a sheet or an editor, which draw no band. It is a sentence in the `small` style in `--text-soft` (`--net` when refused), with no dot. A long local operation gets a determinate bar and exact counts: a spinner says "wait" without saying how long, which is the one thing a local-first product always knows.

## Shapes

Geometry is an instrument, not a pillow: content is square, a control is 7px, a container is 12px, an identity mark is 26% of its size, and only an avatar or a switch track is a pill. A shape does not decide semantics, and a renderer does not silently pick a radius because a component happens to be a card.

## Components

The recipe inventory is the contract: Button, IconButton, TextField, Search, Surface, ListRow, Chip, Badge, Segmented, Dialog, Sheet, StatusLine, Banner, Empty, Loading, Error, AppTile, AppHeader, Nav, Switch, Checkbox, Select, DateTimeField, Tooltip, Progress, and Avatar; the registry's list also names a recipe or two only the site draws, Tooltip among them. Each recipe declares rest plus its supported states and its accessibility obligations. On the phone a component has one interaction state, pressed, beside the disabled, selected and focus states the platform draws; a recipe's hover state and its per-surface capability matrix are the site's ([R-DESIGN-10](docs/decisions.md#designmds-web-era-rulings-superseded-2026-10-15)). Segmented absorbs tabs; ListRow absorbs grip/reorder.

The phone has three kit controls, with the same names on both shells: the **Ink button** (`KitInkButton` · `InkButton`), the **Outline button** (`KitOutlineButton` · `OutlineButton`) and the **Link** (`KitLink` · `KitLink`). The recipe's Button variants map onto them: `primary` is the Ink button, `secondary` the Outline button, `destructive` the Outline button in `--net`, and `quiet` the Link. `primary` is the ink fill with `--text-inv` on it, and there is at most one per view. `destructive` is OUTLINED in `--net` — a filled destructive button is not part of this grammar, and the `destructiveFilled` variant is retired with its last renderer. Controls are 44 and move at the recipe's duration. DateTimeField uses the native picker on mobile.

**Pressed is the one interaction state**: `--bg-press` under the finger, on the control's own rung — never a ripple, a scale or an opacity. **Haptics** are a moment channel, not a visual state, and the phone has one: a selection tick when the lit tab of an app's band changes (iOS `.sensoryFeedback(.selection)` in [Band.swift](mobile/iosApp/Sources/Band.swift), Android `SegmentTick` in [Band.kt](mobile/androidApp/src/main/kotlin/dev/centraid/android/kit/Band.kt)). It fires on a change and not on every touch or on appearing, and nothing else buzzes.

`StatusLine` is the one feedback channel: a single persistent line docked to the bottom of the frame, updated in place — no stacking, no floating overlay, no auto-dismiss animation, and at most one inline text action. It is a sentence in the `small` style in `--text-soft` (`--net` when the answer is a refusal): no dot, and not the numeric register. Its seat is the foot of the place, directly above its band. A pushed page, a sheet or an editor draws no band and carries the line at its own foot, and the shell's import line takes that same seat on Home and on every app — progress, then outcome, one action, and a close key once the work is done. The toast container it replaces is retired outright, not aliased. `Loading` is a static skeleton (`ReadStateView`) for a screen's load and a determinate bar where the count is known; the spinners (`KitSpinner`, `StageSpinner`) are for work with no shape to draw — a save in flight, a transfer starting. A shimmer is attention-seeking about work the product can simply describe.

The phone's renderer is the typed kit: `toNativeTheme` writes the values and the SwiftUI and Compose kits draw the controls from them. The site's recipe CSS is emitted by `toCss()`; there is no blueprint renderer and no blueprint scope ([R-DESIGN-2](docs/decisions.md#designmds-web-era-rulings-superseded-2026-10-15)). The emitter drift gate and the native specs keep the emitted table and its consumers aligned ([design machinery](docs/design-machinery.md)).

One icon registry owns iconKey resolution for manifest, index, and app metadata. Components use semantic concepts (`back`, `close`, `ask`, `settings`, `add`, `trash`, `leave`, `up`) before concrete glyphs. Every icon shares one contract regardless of which app claims it: single-tone stroke on a 24 grid, `fill: none`, round caps and joins, and `aria-hidden` on the `<svg>` — an app-specific mark (Photos' `heart`, `album`, `place`, `person`, `dupe`, `restore`, `removeFrom`, `info`, `more`, and its shared `trash`/`add`/`share`/`download`) draws new artwork inside that same contract rather than a one-off. Identity uses one initials formatter and one identity-colour resolver. Relative time and bytes use one formatter module. `aria-label` on a container is a REPLACEMENT, not an addition: use it only on controls whose visible content is an icon, and mark decorative SVG `aria-hidden`.

### The seven rooms (mobile)

A mobile screen is one of seven rooms, and nothing else. The recipes above say what a control looks like; the rooms say what a SCREEN is, which is the half the audit of #1015 found missing — nine surfaces sharing no header, back affordance, search field, confirm, empty state or date format, because the kit was optional and nothing noticed a screen ignoring it.

| Room | Anatomy | Examples |
| --- | --- | --- |
| `HomeRoom` | the vault lockup with a framed search key at its trailing edge (every app but Locker, [R-CHROME-6](docs/decisions.md#app-chrome-one-grammar-for-every-app-root)) and, right of it, the appearance key ([R-CHROME-7](docs/decisions.md#app-chrome-one-grammar-for-every-app-root)), cover grid of app marks, one status line, no floating key, one trailing verb (Settings) | Home |
| `AppPlace` | the platform navigation bar (back to Home, the app's name, ≤1 trailing action: the app's create verb as `Plus` — glass on iOS, so every app's header is Photos' and Agenda's), the search bar under it, one chip row of filters then sort, app band (places, then More) as a render prop | Photos grid, Tasks list |
| `PushedPage` | `PlaceHeader`, back to the **named parent** (a computed `PlaceRef`, never a string), ≤1 trailing action | album, contact, document, settings sub-page |
| `EditorRoom` | full screen, autosave, close = done, band hidden, status line hosted inside | note, document, expense, event |
| `SheetRoom` | grabber, title carrying the noun, ≤1 ink button, status line hosted inside | confirm delete, pick date, add to album |
| `SystemPlace` | `PlaceHeader` + `SectionBlock` / `RowsBlock` only; a place root draws the Home band at its foot and no `HomeKey`, a sub-page keeps `HomeKey` or its back key in the header's leading slot | Settings, Vault, Copies, Backup health |
| `StageRoom` | full-bleed `--stage` ground under the safe area, no header and no band, the caller's own floating chrome, one close act reached by a control and by a swipe down | photo lightbox, its slideshow, a video |

The room owns the header, the back control, search, the empty/loading/error states, the status host, selection and the gutter; the app supplies content and copy. A screen that hand-rolls any of those is a finding, not a variant.

**Every app root arranges its verbs the same way** ([decisions.md, App chrome](docs/decisions.md#app-chrome-one-grammar-for-every-app-root)), top to bottom:

| Slot | Holds | Never |
| --- | --- | --- |
| Header, trailing | the app's create verb as one `Plus` glyph; Select where the app makes nothing | a word, a second item, search, a menu |
| Under the title | the search bar; tapped, the field in place (or the app's search page) | a More row, a bar glyph, a band tab |
| Chip row | filters, then the sort chip last — the current order and a chevron | a toggle in More, a private pill |
| Band | two to four places, then More | Search, a filter |
| More | Trash, Import, Export, alternate views, "What X may read" — machine rows | Search, Sort, a filter |

**Search says what it searched for, and offers the assistant when it found nothing** ([#1097](https://github.com/srikanth235/centraid/issues/1097)):

| Moment | Draws | Never |
| --- | --- | --- |
| The core corrected a typo (the exact answer was empty and a vocabulary word one slip away found rows) | one line directly under the open field, in the secondary text style — "Showing results for “sunscreen”" (`SEARCH_CORRECTED`, id `search-corrected`). It lives in the field component every search slot and Home's search page share, so it is drawn once per platform; the machine puts `SearchField.corrected` in state and the view draws it | a banner, a toast, a second row of results, the line over an exact answer, the line over rows for a term since changed |
| Home's search found nothing | the no-match sentence and its one action, "Ask about “zzqx”" (`SEARCH_ASK_ABOUT`, id `search-ask-about`): the shell's router switches to the Chat tab and sends "Find zzqx" (`SEARCH_ASK_QUESTION`, finished by the machine in `HomeSearchData.ask_question`). The action is drawn only where the shell has a Chat tab — iOS today | a second sentence, a button inside a row |
| An app's own search found nothing (Notes, People, Tasks, Docs, Agenda, Photos) | the same kit empty state with the same one action, id `search-ask-about`, whenever the machine put a question in `SearchField.ask` (`AgendaHomeState.search_ask`; Photos' no-match state is `SearchHits.empty`): the answer is current, not denied, and wholly empty (rows and containers). One `SearchEmptyView` per shell draws it, the tap goes to the shell's `askChat`, and Android, with no Chat tab, draws the sentence without it. **Locker's search never offers it** — its term can itself be a secret — | a second presentation, a hand-drawn empty column, an action the view decides to add, Ask in Locker, the action over rows or over a term since changed |
| A search matched the NAME of a notebook, album, project or Docs folder | one container row per match, above that app's result rows — its kit glyph (`Book`, `Image`, `List`, `Folder`), the title on one line and the kind in a soft word ("Notebook", "Album", "Project", "Folder"; `SEARCH_KIND_*`), id `search-container-<entity>-<id>`. It is ONE component per platform (`SearchContainerRow`) drawn by Home's search page (inside the app's group, before its rows, counted with them) and by Notes', Tasks' and Docs' own search results; the machine finished the words, the glyph and the reference (`SearchContainer`, in `SearchField.containers` for an app and `HomeSearchGroup.containers` on Home) and a tap opens the reference through the shell's one row router, so a chat card for a notebook opens too. A container that matched is an answer: the no-match sentence is not drawn over it. A new term, a close and a stale answer clear or never set it, as for `corrected` | a second router, a row of the view's own, the container among the rows, a count that leaves it out, "nothing found" over a notebook that was found |

`StageRoom` is the one room that takes none of those, and that is the point rather than an omission: one piece of media edge to edge has nothing to be empty of, nothing to search, and no list to select from, and a strip across the top of a photograph is a second ground. What it owes a member instead is a way out, so the room owns the swipe-down dismiss and hands the caller's chrome the same close act — a stage that brings no chrome gets the room's own close key, because a stage with no visible way out is a black screen.

Six product rulings sit behind the rooms and are not re-decided per screen — trash, casing, editors, push-versus-sheet, the band under a selection, and where Settings is reachable from: [docs/decisions.md § Mobile UX consistency (#1015)](docs/decisions.md#mobile-ux-consistency-1015), D1–D6.

### The shell's places (mobile)

The shell band's places are not apps. `ShellModel.Tab` is `home`, `chat` and `backup`; Chat and Backup have no tile, no route and no catalogue row, and Home draws each in place of its springboard with the shell band at the foot.

**Chat** is the on-device assistant: a thread, suggestions, and one composer card — attach, the chat's scope, send. It is not an eighth room. It follows `HomeRoom`'s frame, the place Home draws, so it keeps that frame's laws: the shell band at its foot, hidden only while the composer has focus (as an editor hides its band), and one filled ink element, which is Send (Stop while a turn runs). It owns its header, in place of the vault lockup: the drawer's control, the open chat's title with the vault beneath it, and a menu ([R-CHAT-2](docs/decisions.md#the-on-device-chat-keeps-its-history-in-the-vault)). Its status line ("Looking in Tasks…") sits just above the composer while a turn runs, and a card in an answer pushes the real row's route over the shell, so back returns to the chat. Chat is iOS only until Android ships it; the search table's "Ask about" action follows the same rule.

### The controls (mobile)

**Chrome is the platform's; content is the kit's.** The navigation bar — its back, its title, its trailing verb — and a sheet's grabber and detents are drawn by the platform (glass on iOS), never by a screen. Everything under the bar is drawn from the kit, never hand-rolled. The root carries the `link` ink as its tint, so a platform control is on-palette rather than system blue.

| Outline button | `KitOutlineButton` · `OutlineButton` | a secondary verb: hugs its label and aligns with the leading edge of the text above it; 44, `md`, `lineStrong` hairline, `smallStrong`; tone `net` when it destroys. |

| Choice stack | `KitChoiceStack` · `ChoiceStack` | alternatives stacked vertically — an Ink button with Cancel or Not now, or a set of choices like a Money transaction's offers — in one column that shares one full width. |
| Icon key | `KitIconKey` · `IconKey` | 44 target, 18 glyph in `text`; framed (in content) is a 36 plate, `md`, `lineStrong`. |
| Toolbar verb | `ToolbarVerb` / `ToolbarIcon` · `RoomAction` | a word or an 18 glyph; the bar draws it. |
| Chip | `KitChip` · `KitChip` | a filter or a choice among several: capsule, 32 visible in a 44 target; selected is `bgSunken` + `lineStrong` + `text`, never `accent` — accent is the ink button's alone. |
| Segmented | `KitSegmented` · `KitSegmented` | one of two to four views: the band plate's grammar. |
| Stepper | `KitStepper` · `KitStepper` | previous / next: two framed icon keys, each carrying its own id. |
| Check · Switch | `KitCheckBox`, `.kitToggle()` · `KitCheckBox`, `kitSwitchColors()` | `accent` when on; a check has four states — off, on, mixed (a dash: won't do) and partial (half filled: started). |

**Width belongs to the control, not to the call.** An Ink button is full width. An Outline button hugs its label and aligns with the leading edge of the text above it. When a view offers alternatives stacked vertically — an Ink button and Cancel or Not now, or a set of choices like a Money transaction's offers — they sit in one `KitChoiceStack` · `ChoiceStack` and share one full width. There is no per-call width switch.

Rulings that hold for every control:

- **Destructive** confirms through `ConfirmSheet` (D1) — never an alert, never a confirmation dialog — and its ink is `net`, never `danger`.
- **Disabled** is the `textDisabled` ink on the leaf, never a faded container — and a disabled verb is still drawn, never hidden, so the member sees what becomes possible.
- **Targets** are 44. A 34 target exists only inside a dense row, and only through the named constant (`targetMinFine`).
- **Strokes**: `lineStrong` outlines a control, `line` divides content. **Radii** come from the token scale; a literal radius is a finding.
- **Rows** press with `KitRowPress` (iOS) and a band tab with `bandPress` (Android): `bgPress` under the finger, the one interaction state. A tappable row is a `Button`, never a tap gesture.
- **Loading, empty and failure** go through `ReadStateView`; a bare spinner outside the kit is a finding, the kit's `KitSpinner` and `StageSpinner` are for work with no shape to draw, and an empty state with something to do carries its action.
- **More and Reads** sheets are `OptionSheet`s; a `NavigationStack` inside a sheet is for a sheet that pushes.

## Copy

**Copy is signage, not conversation.** The voice is calm, concrete, and specific — the same voice the rest of this document is written in — and it is read at a glance, on the way to something else. One glance is the unit: a label a member has to parse twice has already failed, and a second sentence explaining the first one is the label admitting it did not work. Crisp is not curt. "Photo deleted" is the register; "Deleted" throws away the noun that made it legible, and "Your photo has been successfully deleted." pads a fact into an announcement.

The house tic this rulebook exists to stop is **defensive reassurance**: a string states a fact and then adds a sentence about what was _not_ lost, not deleted, not sent, not generated. Repeated everywhere, it stops reading as care and starts reading as a product apologising for itself. Reassurance is **positional** — it belongs where the risk decision is actually made, and nowhere else.

Every string has a budget, and the budget is the contract. Copy lives in `copy/<app>.json`, and only there: the Kotlin table both shells read, `dev.centraid.design.copy.<App>Copy`, is generated from it at build time (`:shared:generateCopy`).

| Surface | Budget |
| --- | --- |
| Button, action, menu row | 1–2 words, verb first. Never "Click here to…" |
| Status line, outcome | A fragment — "Photo deleted". Never "successfully". |
| Status line, state | One clause |
| Empty state | One sentence and at most one action. No feature explanation, no healthy-state essay. An app's day-one empty may also carry the shell's "See an example" link — a quiet text link, never a second button ([R-ONBOARD-3](docs/decisions.md#onboarding-without-sample-data)) — and where the phone holds the data its import is the one action ([R-ONBOARD-4](docs/decisions.md#onboarding-without-sample-data)). |
| Banner (offline, degraded) | One sentence: the state, plus one action or one consequence |
| Error | What happened and what to do, ≤ ~12 words. No apology, no "Please try again." |
| Settings label + description | The label carries the meaning; the description is one sentence or absent |
| Placeholder | A short noun phrase, not an instruction manual |
| Consent, destructive confirm, security or privacy disclosure | Full sentences. The one home for reassurance. |

**Banned everywhere**: "please", "successfully", "simply", "in order to", "you can", "we're sorry". Each of them is a word the sentence works without, and every one of them is a tell that the string is talking rather than labelling.

**Vocabulary.** One noun per thing in member-facing copy; the left column is the word, the right column is every synonym it retires. A vault is never the actor ("People can't read this vault", not "The vault did not let People read").

| Say | Never |
| --- | --- |
| backup device | gateway, laptop, machine, NAS, server |
| recovery key | 24 words, your words, seed, phrase, passphrase |
| QR code (button: "Scan QR code"), pairing code (the text form) | square, payload |
| this phone | this device |
| photo | photograph |
| backed up | synced, sealed, drained, copied to the gateway |
| Try again | Retry |

A literal command the member types stays as written (`centraid-gateway pair`), and where the member types the key, "the 24 words of your recovery key" is fine. Internals are not copy either: never seal/unseal, receipt, ledger, drain, "derived", "in memory", "at rest", "by design" or `core.*` — say what the member can do or what happened. Do not hard-code counts that rot ("Eight apps").

**Hard caps.** The surface budgets above are the target; these are the ceiling, by key suffix, in words (a `{placeholder}` is one word): `_LABEL`, `_ACTION`, `_PRIMARY`, `_SECONDARY`, `_BUTTON` 4; `_NOTE`, `_DETAIL`, `_LEDE`, `_STATUS`, `_HINT` 12; `_BODY`, `_LEAD`, `_NOTICE` and errors (`_FAILED`, `_ERROR`, `_REFUSED`, `_DENIED`) 25; `_TITLE` 6. A `·` never joins two thoughts in one string — split it or cut one; it survives only between short metadata facts ("Edited · 3 days ago", six words or fewer).

`bun run lint:copy` ([scripts/lint-copy.mjs](scripts/lint-copy.mjs)) enforces the banned words, the vocabulary's retired terms, the `·` rule and the caps over every `copy/*.json` string. It is a shrink-only ratchet like the controls gate: a per-file budget that only goes down, so fix the string rather than raise it.

The reassurance rule cuts both ways, and the second half is as binding as the first. A disclosure keeps its full sentence at exactly the place a member decides whether to let the product do something with their things. A status line, an empty state, or a shelf header making the same promise a fourth time is not more trustworthy; it is noise the disclosure has to compete with.

Voice survives compression. The evocative half of a line is usually the short half — cut the defence, keep the image.

**Worked pairs**, from the [#805](https://github.com/srikanth235/centraid/issues/805) copy pass:

| Where | Before | After |
| --- | --- | --- |
| Needs-you screen empty state | "Staged writes, lapsed connections and requests for wider access appear here. This page is empty most of the time, and that is the healthy state." | "Anything that needs your OK — a message waiting to send, an account to reconnect, an app asking for access — shows up here." |
| Docs offline banner (v0; the key and the gateway it spoke of were removed in [#1029](https://github.com/srikanth235/centraid/issues/1029) and [#1047](https://github.com/srikanth235/centraid/issues/1047)) | "The gateway is unreachable. Titles, folders, filing, tags and stars are read from this device, so the drive still lists everything — but most documents cannot be opened, and search is not available on this surface. Anything you write stays here, in order, until the gateway is back." | "Gateway unreachable — filing works from this device, opening and search do not." |
| Photos Memories empty state | "Memories appear here on their own: a day that has an earlier year behind it, a run of days away from home, or a burst of near-identical photographs. Nothing is generated — they are your own photographs, noticed." | "Your own photos, noticed — a year behind a day, a trip, a burst." |
| Write failure outcome | "&lt;title&gt;: Please try again." | "&lt;title&gt;. Try again." |

The first two lose a whole sentence of reassurance about what still works; the third keeps the image and drops the defence in front of it; the fourth deletes an apology that told a member nothing they could act on. Audit everything, churn nothing — a string already inside its budget is left alone.

**One noun per thing, and the same noun on every seat.** A place and its rows share a vocabulary: a place named Rules whose rows are called automations makes a member learn two words for one thing, and hear a third from VoiceOver. A short form may DROP words from the full name, never swap one in. Identifiers are exempt and are not copy — a wire flag, a route key, a deep-link path, a module name, a file name and a concept id (`DESTINATION_MARKS`' keys) keep whatever they were called; no member reads them. When two seats share a copy module, the noun is fixed AT THE SOURCE: renaming half a shared pool is worse than the divergence it was meant to close. [docs/decisions.md § Mobile UX consistency (#1015)](docs/decisions.md#mobile-ux-consistency-1015) R-SH-8/R-SH-11/R-SH-12 carries the reasoning.

## Responsive Behavior

The phone is one surface, touch, and its responsiveness is the system's: safe-area-aware sheets, 44pt/48dp target floors, and the system text size within the [Dynamic Type](#typography) cap. A band is capped at 5 apps plus More and no tab falls below 44px. Layout may adapt, but role names, colour meaning, type hierarchy, radii, spacing, icon keys, and action scarcity do not. Components must survive the largest permitted text size, reduced motion, light and dark themes, VoiceOver and TalkBack, and RTL — the shells mirror through leading and trailing edges, and the site's CSS through logical properties, which is only true while every rule uses them.

## Agent Prompt Guide

When authoring an app, start with a room and the kit's controls, then choose only roles from [packages/design/src/roles.ts](packages/design/src/roles.ts). Do not declare a type register or retune the page. Use the Ink button once per view, the Outline button for ordinary actions and a Link for a verb that reads as words. Use `--accent-text` for the action colour on type, `--text-inv` for published fills, `--link` for a text verb and never on a kit button, `--net` for anything that leaves the device, and a status role only for status. Put every number in `--t-mono`; use `--font-code` only for code, inline literals, and paths. Write every string to its budget in [Copy](#copy) before you write the component: a verb-first label, a fragment for a status line's outcome, one sentence for an empty state or a banner, ≤ ~12 actionable words for an error. Never add a second sentence reassuring a member about what was not lost — reassurance belongs only to a consent screen, a destructive confirm, or a security disclosure. Never ship "please", "successfully", "simply", "in order to", "you can", or "we're sorry". Pick an iconKey from the shared registry. Use `formatRelativeTime`, `formatBytes`, `identityInitials`, and `identityColor`; do not write local copies. Run `bun run check:pr` and the affected contract tests before presenting work, and `cargo xtask gate --profile mobile-jvm` for a change to the shared kit.

## Do's and Don'ts

Do use shared roles, recipes, icon keys, formatters, safe-area adapters, and generated lowerings. Do keep app identity separate from the shell, which spends none. Do line-clamp text in a fixed-height container. Do give a recessive state its own token on the leaf element. Do add a receipt when a system fact changes. Do let the label carry the meaning, and keep a string inside its [Copy](#copy) budget.

Do not add a second sentence reassuring a member about what was not lost, deleted, sent, or generated — outside a consent screen, a destructive confirm, or a security disclosure, that sentence is deleted rather than shortened. Do not explain a feature in an empty state, apologise in an error, or write "please", "successfully", "simply", "in order to", "you can", or "we're sorry" anywhere. Do not weaken a budget to make a string fit; cut the words.

Do not hardcode colours, font stacks, type sizes, spacing, radii, icon dictionaries, or foreground choices. Type uses a named `--t-*` role or its emitted `--t-*-size` geometry adapter; radius uses a shared `--r-*` rung, the registry-emitted tile shape, or the 26%-of-box app-mark rule. A literal fallback or arithmetic such as `calc(var(--r-md) * .7)` is a second scale and fails the zero-debt gate. Do not add a new token in a screen or in the kit. Do not put a hue on a control, ship a second filled element in one view, fill a destructive button, or use a toast as a notification. Do not express state with container `opacity`, clip text in a fixed-height container, use a spinner for a screen's load, a badge count or a red dot, or write left and right where leading and trailing exist. Do not restore `--bg-l`, `--t-hero`, `--t-greeting`, `--sp-7`, `ACCENT_PALETTE`, `--t-tiny`, `--lib-*`, `--font-title`, `--mono`, `--bezel*`, or `--accent-midnight` as compatibility aliases.
