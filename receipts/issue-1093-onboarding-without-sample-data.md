# Issue #1093 — onboarding without sample data (2026-10-09)

[#1093](https://github.com/srikanth235/centraid/issues/1093) supersedes the sample-vault rulings that [#1078](https://github.com/srikanth235/centraid/issues/1078) made ([its receipt](issue-1078-onboarding-sample-chat.md)).

The owner's direction of 2026-10-09 ("ignore prior R-SAMPLE rulings; sample data exists only to help onboarding"), ruled in detail as [R-ONBOARD-1…7](../docs/decisions.md#onboarding-without-sample-data), superseding R-SAMPLE-1…8 ([pointer table](../docs/decisions.md#the-sample-vault)).

- [x] **The sample vault is retired** — no second vault on a first launch; `SampleMark`, `Vault::found_sample`/`finish_sample`, `CoreError::SampleVault`, `crates/core/src/sample/locker.rs`, `Shelf.foundSample`/`hasSample`/`Holding.sample`, the half-seeded-sample cleanup, `HomeData.sample_notice`, `HomeState.founded_today`, `HomeEvent.FoundingDayKnown`, `VaultLockup.sample`/`founded_at` (reserved), `FoundingDay`, "Add sample"/"Remove sample", `SampleVaultSpec`, `crates/core/tests/sample_vault.rs` and `maestro/flows/sample-vault.yaml` are gone
- [x] **"See an example"** — `CoreConfig::example` / `"example": true`, `FOUND_CONTENT_EXAMPLE` (2 reserved), `CoreError::Example` over an exhaustive arm match, `crates/core/src/example.rs` (the scenario, no Locker), `ExamplePreview`, `Shelf.openExample`/`closeExample`/`core()`/`memberCore()`, `HomeSession.seeExample`/`leaveExample`, `EmptyState.offers_example`, the banner on both shells
- [x] **One-tap imports** — `EmptyState.import_source` / `AgendaHomeData.import_source`, `kit/PhoneImport.kt`: Contacts → People (`ContactsImport`; iOS `CNContactStore`, Android `ContactsContract`), Calendar → Agenda (`CalendarImport`; iOS EventKit, Android `CalendarContract.Instances`; writable calendars only; `schedule.propose_event` gains optional `busy`), Reminders → Tasks (`RemindersImport`; iOS EventKit only). Files → Docs is Docs' existing "Add a document" → Upload
- [x] **Teaching starter rows** — `crates/core/src/starters.rs`, due on the member's today through `FoundRequest.tz`
- [x] **The banner** sits above each app's own header on iOS (an inset per destination, not on the stack); Android's shell line is a banner that stays until Done, never a timed toast
- [x] **A repeating calendar series stays one series** — its rule and its own first occurrence; the vault's expansion over the window is held against the phone's occurrences, so a cancelled one becomes a skip and a moved one an override (`schedule.edit_event_occurrence`); an occurrence the vault does not expand is imported on its own; a rule the vault refuses falls back to the occurrences in the window
- [ ] **Open** — Android not run on an emulator (no system image on this host), so its series reader (`Instances` grouped by `ORIGINAL_ID`, the master's `DURATION`) is compiled and linted but never read a real calendar; an occurrence moved from inside the import window to outside it reads as cancelled and is skipped (the phone's answer holds neither); on iOS, an all-day series' `UNTIL` east of UTC and a series whose first occurrence was itself moved are unexercised; `DeviceClock.Reading.utcOffsetMinutes` has no reader left and its three platform actuals still fill it
