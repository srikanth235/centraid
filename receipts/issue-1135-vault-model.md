# Issue #1135 — The vault's data model, rebuilt from first principles

Worked as an umbrella by orchestration. One root agent holds the plan and the model spec; lanes run serially on one branch (`claude/amazing-fermat-9nt6tr`, R-1135-0-1) so the root checkout and its warm `target/` are each lane's. The spec every lane builds from is the vault model specification (an `entity` for everything with a title and a trash, a kind row for what it is, typed `edge`s, `blob`s and `derivative`s, an `origin` and a `source` for what is followed); `docs/vault-ontology.md` is its published state. A lane that needs a table to differ from the spec records a `R-1135-<lane>-<n>` ruling here and changes the baseline; it never adds a second mechanism beside one the spec describes.

## What changed

### Lane 1 — kernel

- **One baseline, hand-written.** `contracts/migrations/001_baseline.sql` is the whole schema (every kind, the kernel, the blob plane, follow, journal, the one search index, Locker) and its seeds: the three flags, the money categories and groups as the old baseline seeded them, the eight workout kinds, the four activity kinds People logs, one relation label, one calendar and the `edge_shape` rows. Rungs two to five are deleted, so the ladder holds one rung. `contracts/schema/vault-ddl.sql` is regenerated by `export-ladder-ddl`. `contracts/schema/v0-registries.json`, `crates/ontology/src/registries.rs` and its readers, the golden corpora under `contracts/golden/`, the version window, `export-baseline` and the squash renderer are deleted.
- **`crates/ontology`** keeps the doctor, the DDL renderer and a `scratch` module (`scratch_dir`, `repo_root`, moved from the deleted `golden`). `Vault::open` no longer has a version window.
- **The gate** (`crates/vault/src/commands/mod.rs`) writes one `journal` row for every command, in the command's own transaction (`refused` for authority, schema and precondition refusals; `failed` in a transaction of its own after a rollback). `command_definition`, the check rows, explanations and the hash-chained access receipts are gone; `Registry::install` and the ontology-version gate with them. `journal.rs` replaces `audit.rs` and keeps the sealed-input tokenising and scrub.
- **`ctx.touch(id)`** (`CommitTx::touch`) stamps `updated_at`, bumps `version` once per commit and marks the entity for re-indexing at commit; `ctx.insert_entity` is the shared first half of every create. The re-index (`crates/vault/src/index.rs`) runs inside the commit, over the touched ids plus the targets of any touched note's `about` edges, into the one `search` FTS table keyed by `entity.n`. A kind's search text is one function (`text_of`) over its own row and children plus the bodies of live notes about it. Locker is not indexed.
- **`crates/search`** is rebuilt over that index: kind filter, the trash join on `entity`, keyset over `(rank, id)`, a title-over-body bm25 weight carried by the query, the fuzzy correction over the one `search_vocab`, and a snippet excerpted in Rust (the index is contentless).
- **Shared verbs** (`crates/vault/src/commands/{entity,tag,flag,edge,container,blob,person,follow}.rs`): `entity.retitle|trash|restore|purge|empty_trash`, `tag.add|remove`, `flag.set|clear`, `edge.add|remove|move`, `container.create|move`, `blob.stage|collect`, `derivative.write|drop`, `person.merge`, `follow.contacts|calendar|files|health|statement`.
- **Bytes.** `crates/vault/src/blob.rs` replaces `content.rs`: staging, derivative writes, `locate`, and garbage collection as one question asked of `PRAGMA foreign_key_list`. The backup plane's enumeration (`backup/naming.rs::content_hashes`, `backup/files.rs::content_files`) reads `blob` (which includes every `derivative.out`); the restore drill writes documents over blobs.
- **The follow engine** (`commands/follow.rs`): origin and source bookkeeping, per-field three-way merge against `source.stated`, match-then-add, R-FP-3 on absence, with a system's map as data (`SYSTEMS`).
- **Locker** is ported off every old core table: `locker_item` gains `starred` and `memo`, a `locker_tag` table replaces `core_tag`, and a `receipt` table of its own (`seq`, `at`, `item_id` as a value, `act`, `journal_seq`) replaces `access_receipt`.
- **Deleted from `crates/vault`**: every per-kind command module (`chat`, `core`, `core_links`, `event_time`, `health`, `knowledge`, `media`, `money`, `people`, `phone`, `schedule`, `social`, `wikilinks`), `chat.rs`, `originals.rs`, `operations/`, and the tests whose subject was a table or file the spec deletes. `crates/vault/src/time` and the backup plane stay.
- **The commitment tests and the shared-verb tests** are new: `crates/vault/tests/commitments.rs` (the spec's eight, each asking the founded file, with a seeded red for the index comparison) and `crates/vault/tests/shared_verbs.rs` (24 tests over every shared verb and the follow merge).
- **`docs/vault-ontology.md`** is rewritten as the model's current state with the eight commitments tabled against their tests; `crates/vault/README.md`, `crates/search/README.md` and the Locker README are brought to the same state.
- **The backup plane's history and the doctor** follow the journal: `backup::snapshot::history` counts `journal` (`RECEIPT_TABLE` is `journal`), and the dangling-receipt check of `restore_check` and its two `centraid doctor` fields are gone (a journal or Locker receipt names a row by value, so evidence outliving its row is not a finding).
- **Estate**, in a commit of its own (`3f9c4870`): six `year3` app-read rows leave `tests/journeys.json` with the tests that were their consumers; no row is added anywhere.

### Rulings

Ids R-1135-1-1 to R-1135-1-10 are in [docs/decisions.md](../docs/decisions.md#the-vault-model-from-first-principles-1135), each with its finding, choice and reason. In one line each: **1** one relation label seeded; **2** `receipt.act` is a verb grammar; **3** a journal `seq` is reserved before the handler; **4** a trashed entity leaves the search index; **5** a purge purges companions and moves the rest to the top level; **6** the blob plane is entered by a command and by the core's stage door; **7** the page door's computed columns follow the blob; **8** Locker's item keeps its own trash pair (commitment 2 names it); **9** commitment 4 follows the spec's DDL (revisions and a category's budgets and rules cascade too); **10** the index comparison reads an `fts5vocab` of type `instance`.

### Falsification

The two claims the rest of the lane leans on, each with a throwaway check.

1. **"The incremental search index is the rebuilt one, so a command that forgets to touch is red."** Check: removed `ctx.touch(id)` from `entity.retitle` (line marked `FALSIFY`, restored after). First result: the test stayed green, because a later `person.merge` in the script re-indexed the retitled person and hid the omission. The script was the weak part, not the claim: the last command of the script is now a retitle of a note nothing re-indexes afterwards. Second result: red (`a command changed searchable text and did not touch`); restored, green. A second, permanent check (`an_edit_that_forgets_to_touch_is_caught_by_the_same_comparison`) writes a body without touching and asserts the incremental and rebuilt dumps differ.
2. **"Garbage collection finds every reference from `PRAGMA foreign_key_list` alone."** Check (a throwaway test file, deleted): `CREATE TABLE zz (h TEXT REFERENCES blob(hash))` inside a commit, with no change to `blob.rs`; `collect_blobs` kept the blob while a row pointed at it and collected it once the row was deleted. The permanent commitment 3 populates every hash column of the model and requires each populated column to be a declared foreign key, and requires `blob::references` to equal the declared set.

### Lane 2 — Notes

- **Commands** (`crates/vault/src/commands/note.rs`): `note.create`, `note.edit` (title, body, format), `note.move`, `note.restore_version`. An edit that changes the body writes the replaced body as a `revision`; a restore swaps one in and keeps what it replaced; an edit or a restore onto the words already there writes nothing. A body's `[[title]]` links compile to `links` edges in the same commit, owned by the compile alone (anchor `{"wikilink": title}`). `note::found` is the one birth of a note, public so People's journal entry founds it the same way and adds its `about` edge. `note::LINKABLE` is the one list of kinds a title resolves to, shared with the powerbox. A pin, a trash, a notebook, a tag and a hand link are the shared verbs, not wrapped.
- **Reads** (`crates/apps/notes`): the six queries rewritten one table at a time over `entity` / `note` / `container` / `edge` / `revision` (a window, then the ids it returned).
