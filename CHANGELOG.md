# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) with the release rules in [docs/release.md](docs/release.md) (issue #468 **D3** / **D4** / **I12**):

- **Patch** — every entry under _Fixed_ only.
- **Minor** — anything _Added_, _Changed_, or _Removed_.
- **Major** — not used before 1.0; agents never propose one.
- GitHub Release bodies are generated from the matching section here (D3).
- In-app "what's new" is re-wired from this feed as an explicit D3 checklist item (I12); no permanent placeholder UI.

## [Unreleased]

### Added

- Self-contained recognition automations ([#724](https://github.com/srikanth235/centraid/issues/724), [#731](https://github.com/srikanth235/centraid/issues/731)): photo/PDF OCR, image/text embeddings, faces, and audio/video transcription run directly inside ordinary automation handlers. Handlers obtain bounded bytes through `ctx.vault.content`, execute their bundled PP-OCRv4, CLIP, YuNet/SFace, or Whisper implementation with optional local assets from `packages/model-runtime`, and persist typed results through `ctx.vault.invoke`; there is no enrichment process, HTTP seam, `ctx.enrich`, or `ctx.infer`. Model-versioned `enrich_derivation` stamps make upgrades bounded backfills, faces remain explicitly consent-gated with forget cascades, and every execution uses the normal automation ledger.
- Circle-backed commons co-owned sharing ([#731](https://github.com/srikanth235/centraid/issues/731)): domain rows and blobs reside in every joined member's vault with seat-local derivatives; a steward serializes member-signed commands; departure recompiles audience projections cleanly.
- Verifiable commons history ([#731](https://github.com/srikanth235/centraid/issues/731)): op-hash chain with signed checkpoint digests and deterministic divergence detection; the reference simulation harness seeds members from an identical seeded RNG to prove order-determinism across replicas.
- Steward-absence recovery and commons sync instrumentation ([#731](https://github.com/srikanth235/centraid/issues/731)): a member whose steward has gone silent sees a named presence rather than nothing, and can re-found the group from its own verified replica; local-only metrics record steward reachability, pull outcomes, parked-intent dwell, and op-log/member-lag distributions. Intents record the sequence they were composed against, and a parked intent expires or can be cancelled instead of waiting forever.
- Photos toward its north star, structural core ([#721](https://github.com/srikanth235/centraid/issues/721)): Takeout photo import on the staged import spine (sidecar-first capture time with honest absence, album reconstruction, Live Photo pairing, byte-level dedupe, structural resumability); the derived-intelligence foundation (E1/E2/E3) — model-versioned embedding ledger, a gateway indexing sweep with an opt-in external embedder (`CENTRAID_EMBEDDER_PATH`), sqlite-vec loaded per-connection with the extension gate re-closed immediately, and semantic search (`POST /centraid/_vault/enrich/semantic-search`) that answers honestly `unavailable` when unconfigured; a semantic hit group in mobile search; member-chosen album key photos honored on the Collections rails plus a viewer "Make key photo" action; a Videos shelf (Screenshots/Panoramas/Selfies deferred for want of an honest bulk signal); adversarial photo fixtures (date-line, wrong camera clock, 10k-in-one-day, all-undated, corrupt EXIF) with a registered 50k scale rig; the op-sqlite `sqliteVec` build flag pinned in both package manifests; and the D2 dogfood ritual, D3 switcher walkthrough, and derived-ledger docs.
- Notifications on desktop, web, and mobile ([#647](https://github.com/srikanth235/centraid/issues/647)): one vault-scoped stream keeps canonical owner decisions pinned above durable automation and outbox notices; repeat notices collapse, only decisions badge, SSE and content-free wakes refresh clients, and notification text is composed locally after an authenticated fetch. Gateway **health** is deliberately not in this stream ([#665](https://github.com/srikanth235/centraid/issues/665)) — it is status, not something the owner can resolve from Notifications, so it stays on the Gateway page (status card, Components, and the durable Alerts history) and in the desktop's threshold-gated OS notification.
- Fresh-install web closure ([#608](https://github.com/srikanth235/centraid/issues/608)): the sidebar can switch every reachable space and always exposes Add gateway; paired devices get distinguishable defaults and can be renamed from Household; Gateway now owns local Storage; Agents exposes the supported five-runner roster with explicit failover eligibility and recovery semantics.
- Unified ACP routing across Assistant, in-app Ask, Builder, and Automations ([#567](https://github.com/srikanth235/centraid/issues/567)): per-surface model and effort controls, capability-driven context/folder/artifact support, canonical-ledger hydration across providers, turn-boundary failover with persistent circuit breakers, explicit per-conversation provider egress consent, editable automation ladders, and the same native status/consent experience on mobile.
- Zero-ceremony first run ([#603](https://github.com/srikanth235/centraid/issues/603)): a gateway started on a **fresh** data directory creates one marked **Personal** vault for you, silently, before anything can talk to it. It is renamed to your display name once you fill in your profile; shared vaults are created later by an explicit owner action. An existing data directory is never touched. There is now exactly one kind of ticket, the **pair ticket**, and it always means _join a gateway that already exists_. On a VPS this is the whole story: `centraid-gateway serve` on a clean directory, then `centraid-gateway pair` to bring your phone in
- Desktop first run is a two-option chooser ([#603](https://github.com/srikanth235/centraid/issues/603)): **Start fresh on this Mac** or **Connect with a ticket**. Both paths then ask for the same thing — a display name and an avatar colour — so every device, on every path, gets one journey. The local gateway (and the first write to your system keychain) does not start until you pick "Start fresh"
- Where an OS keychain prompt can actually appear (development and unsigned macOS builds, some Linux keyrings), a one-line note now precedes the first secret write, so the system dialog is expected rather than alarming ([#603](https://github.com/srikanth235/centraid/issues/603))
- `vault list` (CLI `--json` and HTTP), `status`, and the gateway's vault health component report vaults that **failed to mount** distinctly from an empty registry ([#603](https://github.com/srikanth235/centraid/issues/603)) — a schema-drift or custody failure can no longer look like "you have nothing"
- `GET /_gateway/info` reports `authenticated: boolean` ([#603](https://github.com/srikanth235/centraid/issues/603)), so a client can tell a rejected credential from an endpoint that has not come up yet
- Vault erase and single-database gateway state ([#555](https://github.com/srikanth235/centraid/issues/555)): Settings gains an **erase** ceremony (owner device, exact typed vault name, verified recovery kit) that crypto-erases the vault's key. All gateway state — preferences, enrollments, tickets, web sessions, backup fencing — now lives in a single `gateway.db` that is also the exclusive single-writer process lock ([#568](https://github.com/srikanth235/centraid/issues/568))
- Storage page with local footprint accounting and two owner-set limits ([#544](https://github.com/srikanth235/centraid/issues/544)): the former Operations-sidebar surface now lives under **Gateway → Storage** ([#608](https://github.com/srikanth235/centraid/issues/608)) and shows how much of the machine's disk Centraid is using, split by component (attachments, ledger, vault database, app code, app data, backup staging, runner cache, logs, templates, gateway state) and per vault, against the volume it sits on. A **disk budget** warns as it fills — degrading a new `storage-limit` health component at 80% and again at the limit — and never blocks a write. A **ledger limit** makes conversation and audit archival run early, narrowing its window 90 → 30 → 14 → 7 days until `journal.db` is back under; the 7-day floor means archival never reaches inside the window you are working in. Both limits are off by default. New gateway routes `GET /_gateway/storage/local` and `GET|PUT /_gateway/storage/limits`.
- First-class Connectors platform ([#524](https://github.com/srikanth235/centraid/issues/524)): top-level navigation, durable connection-bound automations, provider sync/action capabilities, and 11 additional pull templates with recoverable incremental cursors.
- Centraid Assist for Google connectors ([#526](https://github.com/srikanth235/centraid/issues/526)): a stateless OAuth code courier, gateway-owned PKCE and token custody, desktop/PWA return handling, fail-closed restricted scopes, recovery guidance, and production verification gates.
- Three-number versioning and multi-surface release synthesis ([#512](https://github.com/srikanth235/centraid/issues/512)): product / build / protocol separation; handshake connects on protocol only; release surface matrix (`bun run release:matrix`); prepare/publish ship set
- Agent self-serve documentation set for solo-maintainer leverage ([#468](https://github.com/srikanth235/centraid/issues/468)): decisions, glossary, coding standards, protocol, release, recovery, traps, enrollment, identifiers, and related root docs.

### Changed

- Workspace packages consolidate 16 → 10 ([#801](https://github.com/srikanth235/centraid/issues/801)): `@centraid/core` absorbs protocol, blob-format, and time-engine behind `./protocol`, `./blob`, and `./time` subpaths; `@centraid/server` absorbs gateway, app-engine, automation, and the ACP turn driver (formerly agent-runtime) as `engine/`, `automation/`, and `acp/`. The daemon bin stays `centraid-gateway`; the harness ACP bin is `centraid-acp`; only `@centraid/cli` declares `centraid`. Previously published absorbed npm names, if any, are deprecated toward the successor.
- The binding layer standardizes and simplifies ([#747](https://github.com/srikanth235/centraid/issues/747)): one Instrument Sans ramp (400/600) now drives desktop, PWA, blueprints, and Expo; pointer/touch is the only surface axis and width changes only measure/columns. App font knobs, Source Serif 4, the 500 cut, retired font/register variables, and the complete legacy CSS/native size/radius ledgers are gone. Desktop/PWA and Expo consumer lint now share zero-debt rigor: semantic type, radius, and color roles only, with no allowance maps. The visual gallery validates computed web type triples against the same typed contract Expo lowers.
- The TypeScript toolchain now has one explicit command/config contract: exact-pinned Node, Turbo, TypeScript, Ultracite, Oxlint/tsgolint, Oxfmt, Knip, and Vitest; `check:fast`, `check:pr`, and `check:full` replace overlapping ad hoc gates; and type-aware lint covers shipped blueprints, scripts, tests, workers, and e2e programs with live fixtures ([#639](https://github.com/srikanth235/centraid/issues/639)).
- Fresh gateways checkpoint bootstrap WAL once before steady-state shipping, repeated agent availability probes use a keyed 24-hour cache, bare `pair` tickets enroll the existing owner, the connector catalog offers only OAuth providers with an Assist path, and the fresh-install automation gallery is curated to eight runnable templates ([#608](https://github.com/srikanth235/centraid/issues/608)).
- Settings → **Appearance** is now Light / Dark / **Match system** as one three-position control ([#608](https://github.com/srikanth235/centraid/issues/608)), and Match system is a standing mode that keeps following the OS rather than a button that snapped once. The page is now that control and nothing else
- The whole sidebar identity row is the space/gateway switcher ([#608](https://github.com/srikanth235/centraid/issues/608)) — click the space name, the avatar, anywhere. The ⇅ glyph is now the affordance saying "this opens something" rather than the only 26 px that responded to a click. Household keeps its own sidebar nav entry, so the row no longer spends its hit area on a duplicate link to it
- A theme's own values now render ([#608](https://github.com/srikanth235/centraid/issues/608)). Appearance prefs are applied as inline styles on `<html>`, which outrank every theme stylesheet block, so writing them unconditionally meant two of a theme's defining values could never take effect: the dark ramp's lightness came from the preference layer whatever the theme declared, and the accent picker's teal overwrote whatever accent the active theme declared. Accent and lightness are overrides now — applied when you have chosen one, cleared when you have not, so a theme's own values reach the screen. Centraid Dark's appearance is unchanged by this: its declaration was corrected to the `5%` near-black it has always rendered, rather than the `18%` that sat in the theme file unread
- **Centraid Dark is neutral grey, not blue-grey** ([#608](https://github.com/srikanth235/centraid/issues/608)). The dark ramp carried hue 222 at 11% saturation; it is now true greyscale (`hsl(0 0% …)` at every surface). Its shape is unchanged — same elevation steps, same sidebar gradient and alpha, same `--bg-l` response
- The gateway's loopback control bearer is derived from its KeyStore-custodied endpoint key rather than minted per boot ([#555](https://github.com/srikanth235/centraid/issues/555), documented accurately in [#568](https://github.com/srikanth235/centraid/issues/568)): a local process that can open custody derives the same bearer, which is how the CLI and the desktop reach a gateway they did not spawn. It is stable for the life of the endpoint identity and is not rotated
- Settings → **Storage** was renamed **Storage provider** in #544; the legacy configuration page and its orphaned Backups-card link are hidden by the fresh-install navigation cut, while backup and recovery status remain on **Gateway → Overview** ([#544](https://github.com/srikanth235/centraid/issues/544), [#608](https://github.com/srikanth235/centraid/issues/608)).
- Gateway info handshake no longer refuses clients solely because product version strings differ; capability flags still gate features ([#512](https://github.com/srikanth235/centraid/issues/512))
- Resource sizing is now cgroup- and steal-aware: the hardware baseline sizes the share you granted of the host rather than the raw machine, and resource modes are budget presets over that share. On container-limited or high-CPU-steal hosts the resolved worker and memory knobs may decrease to match the actually-granted share; plain hosts resolve to the same numbers as before ([#528](https://github.com/srikanth235/centraid/issues/528))

### Removed

- The remaining secondary face and intermediate weight ([#747](https://github.com/srikanth235/centraid/issues/747)): Source Serif 4 and Instrument Sans 500 no longer ship. Web/desktop now carry four Instrument Sans `.woff2` subset files and Expo loads only 400/600. The platform code stack remains reserved for code, inline literals, and file paths and downloads nothing.
- The spawned embedder, Tesseract, desktop ASR, and short-lived loopback enrichment-service processes and their URL/path configuration ([#724](https://github.com/srikanth235/centraid/issues/724), [#731](https://github.com/srikanth235/centraid/issues/731)); ordinary self-contained recognition automations now own the model execution directly.
- The gateway enrichment capability-sweep engine and the lease-based lend/borrow sharing plane ([#731](https://github.com/srikanth235/centraid/issues/731)): capability sweeps are now automation templates; live lending, borrowed stores, lease refresh, byte budgets, and the Lending UI are deleted; give (receiver-owned snapshot) and commons (co-owned co-resident) are the two sharing planes.
- Inline Ask-panel consent cards ([#647](https://github.com/srikanth235/centraid/issues/647)); parked writes now have one decision surface in Notifications while per-automation pending strips continue to project their canonical rows.
- Routine ACP session-continuity ledger notices and default-install navigation to the Workspace, Storage provider, and Import settings pages ([#608](https://github.com/srikanth235/centraid/issues/608)); the working hidden pipelines and exceptional agent notices remain intact.
- Settings → **Layout** as a separate page ([#608](https://github.com/srikanth235/centraid/issues/608)). Density and card surface moved onto **Appearance**, which is now the one page answering "how does Centraid look". The gateway-wide default cron timezone came along for want of a better home and is flagged in the code as belonging on the Automations surface instead
- The **Show sidebar** switch in Settings ([#608](https://github.com/srikanth235/centraid/issues/608)). The chrome already carries a sidebar toggle, so this was a second control for the same state — one of the two always looking stale. The pref and the chrome toggle are unchanged
- The **Builder** routing lane from Settings → Agents ([#608](https://github.com/srikanth235/centraid/issues/608)). Every builder entry point is hidden by default (#434), so the lane configured a surface you cannot open. A stored builder pin still resolves and still shows up as a "used by" chip on the agent that carries it — the control is hidden, the routing is not
- **Failover configuration on attended lanes** ([#608](https://github.com/srikanth235/centraid/issues/608)). Assistant and In-app Ask recover at the next turn with you watching and free to pick differently, so a pre-authorized ladder mainly served to pass the conversation to another provider without asking. Only **Automations** — which fires with nobody watching — still offers one. Existing ladders on attended lanes stay stored and honoured
- The dark ramp's **surface temperature** control ([#608](https://github.com/srikanth235/centraid/issues/608)) — the three-position cool / neutral / warm knob that briefly replaced the "Cool blue cast" switch, and the switch itself. Centraid Dark has exactly one ramp: neutral greyscale. The reason is parity — the light theme has no temperature, so a dark-only knob made one half of the same setting behave unlike the other for no reason a member could name. A stored `surfaceTemp` is ignored rather than migrated, and nothing writes `data-surface-temp` any more
- The accent swatches and the app-tile treatment picker are gone from Settings → Appearance ([#608](https://github.com/srikanth235/centraid/issues/608)). The page is the theme and nothing else. Both prefs still exist and still apply — a previously chosen accent keeps painting, and app tiles keep their treatment — there is simply no longer a control for choosing them, so a fresh install wears the accent its theme declares
- The ten emulation theme presets — Notion, Airtable, GitHub, Solarized (light and dark each), Nord, and Monokai ([#608](https://github.com/srikanth235/centraid/issues/608)). No stylesheet in the repo ever accounted for them: three live shell rules (the dark toast treatment, the connection brand marks) key literally on the `dark` preset, so picking any of the six _dark_ emulations took the dark tokens and left that chrome in its light-mode treatment, painted over a dark surface. The registry is Centraid Light and Centraid Dark. A stored preference naming a removed preset opens on Centraid Dark with no error and no migration step — accent swatches and app-tile treatment are unaffected, because they were never themes
- The founding ceremony, in every form ([#603](https://github.com/srikanth235/centraid/issues/603)): founding tickets (`centraid-gw-found`), the `init-ticket` CLI command, the `vaults:initialize` / `vaults:initialize/verify` / `vaults:restore` routes, the `uninitialized` gate that walled off a fresh gateway, the first-run Create/Restore screen, and the recovery-kit ceremony that first run used to force on you. Recovery kits survive where they belong — as a deliberate **backup** export (`backup kit`, the Backup screen) consumed by `centraid-gateway recover`. The erase ceremony survives unchanged
- The `--init-vault` flag on `centraid-gateway serve`, and the matching `initVaultName` library option ([#603](https://github.com/srikanth235/centraid/issues/603)) — auto-founding replaced the explicit bootstrap they existed for
- SSH-routed gateway connect, deleted rather than hidden ([#603](https://github.com/srikanth235/centraid/issues/603)): the desktop SSH host, the client `sshConnectGateway` API, and the ConnectFlow SSH branch. The headless story is `serve` on the box and `pair` from the phone
- The direct-HTTP transport tier and its per-device bearer tokens ([#555](https://github.com/srikanth235/centraid/issues/555)): remote access is iroh-only, and every remote request carries an EndpointId the QUIC handshake proved. The shared `token.bin` bearer plane and the wildcard admin/recovery HTTP mounts are gone with it
- Unwrapped recovery kits are no longer accepted ([#568](https://github.com/srikanth235/centraid/issues/568)): a kit is always password-wrapped. The unwrapped acceptance path also ignored the supplied password, leaving a password-free branch on restore, kit verification, and kit confirmation

### Fixed

- `main` CI after the served-app retirement: spent `replacesMinimumTestsFlow` markers no longer fail `test:ratchet` against itself, and the web offline-reconnect journey writes through the already-open Tasks session instead of remounting into a not-bootstrapped replica ([#802](https://github.com/srikanth235/centraid/issues/802)).
- Text embeddings refresh when OCR or transcript text is rewritten under the same embedding model, so semantic search cannot retain a vector for superseded text ([#736](https://github.com/srikanth235/centraid/issues/736)).
- `centraid-gateway pair` reports a **bearer mismatch** when the daemon was started with a pinned `CENTRAID_GATEWAY_TOKEN` the CLI cannot derive ([#603](https://github.com/srikanth235/centraid/issues/603)) — it used to blame the iroh endpoint for not being ready, which was a lie you could not act on. [docs/dev-environment.md](docs/dev-environment.md) corrected to match
- A gateway that cannot be reached during onboarding now says **unreachable** instead of quietly reporting no spaces and offering to create one ([#603](https://github.com/srikanth235/centraid/issues/603)); the dead-end "Create vaults on the gateway host." banner is gone, because the flow only offers creation on a confirmed-empty registry
- No "You're offline" banner while you are still onboarding and not yet paired ([#603](https://github.com/srikanth235/centraid/issues/603))
- Web and mobile onboarding no longer show options that cannot work there ([#603](https://github.com/srikanth235/centraid/issues/603)): no "This Mac", no SSH, no founding UI — a browser or phone can only ever join an existing gateway, so the ticket flow opens directly
- Loopback is not treated as an identity ([#568](https://github.com/srikanth235/centraid/issues/568)): the desktop's phone tunnel and the embedded gateway now refuse host-only capabilities for any request a forwarder delivered to 127.0.0.1, and `GET /_gateway/info` serves the gateway's iroh dial ticket only to an authenticated caller rather than to any local web page
- The admin CLIs open key custody the way the daemon does ([#568](https://github.com/srikanth235/centraid/issues/568)): against a real daemon data directory, `vault list` printed nothing, `status` reported zero vaults, `devices add --vault` failed to resolve a vault, and `devices revoke` silently skipped its vault-local data erasure
- `centraid-gateway service install` on macOS validates that it can decrypt existing keys **before** writing the Keychain credential, and keys that credential per data directory ([#568](https://github.com/srikanth235/centraid/issues/568)) — a failed install used to leave a poisoned entry that made every key in the directory undecryptable
- Opting into the OS gateway service no longer leaves the desktop permanently refusing to adopt it on the next launch ([#568](https://github.com/srikanth235/centraid/issues/568))
- Read-only CLI verbs (`devices list`, `backup status`, `backup list`) report that the running daemon owns the database instead of a raw `database is locked` stack trace ([#568](https://github.com/srikanth235/centraid/issues/568))
- macOS network-filesystem detection reads the mount table's filesystem type; the previous probe could never match and also suppressed its own fallback ([#568](https://github.com/srikanth235/centraid/issues/568))
- Re-opening the founding QR while a restore is downloading no longer destroys that restore ([#568](https://github.com/srikanth235/centraid/issues/568))
