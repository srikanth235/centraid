### agent-session-identity

- **Directive**: Every commit made from a recognized agent runtime records the runtime and session identifier that produced it in the issue receipt (`receipts/issue-<N>.md`), under `## Session` → `### Identifiers`. The table has one row per runtime/session pair per receipt and contains exactly `date | harness | session`.
- **Rationale**: A durable session identifier connects a receipt to the agent run that authored it without retaining conversation contents, token counts, costs, or human-steering data. The identifier is provenance, not surveillance: the kit records only the harness signal it was explicitly given and never discovers or opens a harness-owned transcript.
- **Enforced by**: `.governance/packs/governance-kit/audit/directives/agent-session-identity/hooks/pre-commit.sh` stamps the current runtime/session into the receipt before Git snapshots the tree. `.governance/packs/governance-kit/audit/directives/agent-session-identity/check.sh` validates every identifiers table and, in the commit-message lane, requires a row matching the active runtime/session. Both paths use only Bash, POSIX awk, Git, and kit-owned receipt files.
- **Exceptions**: Human commits and commits with no recognized runtime are a no-op. A recognized runtime whose session is unnamed records `-` as the session identifier. A legitimate out-of-hook agent commit may use `governance: allow-agent-session-identity <reason>` in the commit body; the reason is required and remains searchable in `git log`.
