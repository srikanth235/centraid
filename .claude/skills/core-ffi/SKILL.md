# Changing the Rust/shell C ABI

The ABI is five symbols and a contract. Nearly every feature should change a protobuf message, not a symbol. When a task seems to need a sixth symbol, it needs a new request kind on `centraid_call` instead.

## 1. What this change touches

1. **The contract**: `crates/core-ffi/CONTRACT.md` is normative (ten clauses plus sub-clauses for request kinds). Read it and `crates/core-ffi/README.md` in full before changing anything. Every clause has a test in `crates/core-ffi/tests/contract.rs` named after it.
2. **The boundary code**: `crates/core-ffi/src/lib.rs` (the five `extern "C"` entry points, `catch_unwind`, status codes, the open-config JSON) and `crates/core-ffi/src/marshal.rs` (ALL the `unsafe`: slice reconstruction, out-pointer writes, the `Vec` to raw to `Vec` round trip behind `centraid_free`). Keep unsafe confined there; miri covers only that module.
3. **The header**: `crates/core-ffi/include/centraid.h`, committed, generated by cbindgen.
4. **The messages**: `crates/api-proto/proto/centraid/core/v1/` (`envelope.proto` holds `Envelope`, `Request`, `Response`, `Event`; per-feature files hold the arms). Every payload across the ABI is a protobuf `Envelope`; only the open config is JSON.
5. **The dispatch**: `crates/core/src/handle.rs` (`Handle::call` matches each request kind; `request_kind` classifies it bounded or unbounded).
6. **Kotlin**: `mobile/core/src/commonMain/.../CentraidCore.kt` (open, handshake, call, reader, lifecycle), `CentraidAbi.kt` (the seam), `CoreFailure.kt`, `CoreStatus.kt`, `ArtifactIdentity.kt`; the JNA implementation in `jnaMain/.../JnaCentraidAbi.kt`; screens runtime `jnaMain/.../Screens.kt`. iOS Kotlin/Native uses `nativeInterop/cinterop/centraid.def`.
7. **Swift**: `mobile/iosApp/Sources/Core.swift` (`actor Core`), over the header mapped to module `CentraidCoreC` by `iosApp/CoreBridge`.

## 2. The steps

**Adding a capability (the usual case): a new request kind.**

1. Add the arm to `Request.kind` (and `Response.kind`) with the next unused number in the proto. Never reuse a number: retired arms are `reserved` by number and name, and `buf breaking` (`WIRE_JSON`) enforces it.
2. Add the new `.proto` file, if any, to `crates/api-proto/build.rs` by name (no globbing, no `protoc`).
3. Handle the arm in `Handle::call` in `crates/core/src/handle.rs`, and classify it in `request_kind`. **Bounded** kinds finish on their own and are not cancellable (`Cancel` on one is refused `INVALID_REQUEST`); **unbounded** kinds poll a cancel flag and are cancellable. Choosing wrongly means a cancel that either cannot happen or leaves a SQLite read transaction to a dropped future.
4. A zero limit is `INVALID_REQUEST`, never "no limit". A denial the screen draws is an arm of the answer, not an `Error`. A read that hits its ceiling is `OK` with `ERROR_CODE_READ_BOUND_REACHED`, never a short answer that reads as complete.
5. Document it as a clause or sub-clause in `CONTRACT.md` (kind, number, answer, bounded or not, and WHY it is a request kind), with a `Test:` line, and write that test in `tests/contract.rs` driving it through the C entry points.
6. Call it from the shells. Kotlin builds an `Envelope(request_id = ..., request = Request(...))` and `CentraidCore.call` returns `CoreOutcome`; Swift builds a `Centraid_Core_V1_Request` and `Core.call(_:lane:)`. Wire generates the Kotlin types in Gradle; SwiftProtobuf types are generated by `mobile/scripts/generate-swift-protos.sh` in Xcode's pre-build phase (a NEW `.proto` needs `xcodegen generate`).

**Changing a symbol, a status code, or the open config (rare).**

7. A signature change in `lib.rs` means regenerating the header: `CENTRAID_WRITE_HEADER=1 cargo build -p centraid-core-ffi`, then commit it; `tests/symbols.rs` fails if regeneration is not a no-op.
8. A new status code or a new open-config key is a shell-visible change. Old shells send keys newer cores no longer read (`role`, `pairing`, `device` are ignored, never refused), so an unknown or retired key is ignored; a present-but-unreadable one (a seed that is not 128 hex characters) is `BAD_ARGUMENT`. Update `CoreStatus.kt`, the Swift status handling, and `CoreConfiguration.toJson` / `Core.Configuration` together.
9. Never add a sixth exported symbol. `abi-five-symbols` (`crates/xtask/src/rules.rs`) counts `#[unsafe(no_mangle)] pub extern "C"` declarations; `tests/symbols.rs` counts what the built `cdylib` exports. They ask different questions and both must say five.

## 3. What must stay true

- **Buffers are callee-allocated and freed only by `centraid_free(buf, len)`** with the exact length, never `free(3)` or a language cleaner. A null `buf` is a no-op. Both bindings copy the bytes into host memory and free in the same `finally`/defer on every path; Kotlin asserts `buffersHandedOver == buffersFreed`.
- **A timeout (`TIMEOUT`, -5) from `next_event` leaves the out-pointers untouched.** It is not an error: loop again. Zero the locals before the call so freeing is safe either way. Both bindings poll with 1000 ms (`READER_TIMEOUT_MS`, the Swift pump).
- **Inputs are borrowed for the call.** Null pointer with length 0 is the empty slice; null with non-zero length is `BAD_ARGUMENT`.
- **`call` is reentrant; the FFI takes no lock.** Serialisation, if any, is the core's.
- **Request ids are the caller's.** Non-zero is used as-is; 0 is the handshake's. `Cancel` names an unbounded request; an unknown id is a no-op; id 0 is refused.
- **Events are never dropped.** The core's queue is bounded (1024) and drops nothing; a full queue becomes `HealthEvent{stalled}`. Kotlin's event flow therefore uses `BufferOverflow.SUSPEND` (a `DROP_OLDEST` buffer would turn a reportable stall into a stale screen). Keep exactly ONE reader per core.
- **`close` unblocks `next_event` with `CLOSED` (-3)** after delivering accepted events. After `close` the pointer dangles: null your copy. Never race `close` with `call`.
- **A panic never crosses the boundary.** It becomes `PANICKED` (-4) with an `ERROR_CODE_INTERNAL` body and a diagnostic id and poisons the handle: every later call, `next_event` included, returns the same. The shell restarts the core deliberately. A panic in `open` returns no handle.
- **A refusal is typed.** Rust returns a negative status and an `Error` body; Kotlin surfaces `CoreOutcome.Failed(CoreFailure.Refused/Closed/Poisoned/BadArgument/Malformed/StaleArtifact...)`, Swift throws `Core.Failure`. The member-facing sentence is the core's; a shell never invents one. A binding returns an answer or a typed refusal, never `null`.
- **Threading.** Never touch the ABI on the UI thread. Kotlin `call` and `open` hop to the core dispatcher with `withContext` and then call `assertNotOnUiThread(operation, uiThreadName)`; the assertion is AFTER the hop because the realistic bug is a shell that passed `Dispatchers.Main` as the dispatcher. Rust also checks by thread name when `uiThreadName` is configured. Swift runs calls on serial `DispatchQueue`s: `calls` for screens (ordered, so a push is not overtaken) and `bulk` for the byte stage door (so a stream never holds a tap), and the event pump on its own thread.
- **One handle per vault file per process** (`SingleHandleGuard` in Kotlin). A shell opens a directory (`{"shelf": dir}`) and Rust opens each vault under it.
- **Artifact identity.** `Hello` carries `git_sha`, `digest`, `schema_version`; `centraid_open` takes `expectedIdentity`; a mismatch is refused (`StaleCore`) before a handle exists. Kotlin also runs the handshake in `CentraidCore.open` and `requireDigest`: an empty expectation is NOT a match, a `dev` build on either side is "not checked" with a warning, a different digest is `StaleArtifact`. Check how the config JSON is built before assuming a digest is sent: today's shell call sites pass none, so a development core is accepted with a warning.
- **The seed crosses the ABI once, in the open config, and is redacted from every `toString`/log.** Absent means a keyless core (sealing doors refuse with `PEER_UNREACHABLE`); present-and-malformed is `BAD_ARGUMENT`.
- **Unknown protobuf fields do not survive a round trip** (prost does not retain them); nothing across the boundary relays a decoded message.

## 4. Pitfalls

- **The shell links a stale core.** iOS links the Rust archive by path, Android loads a copied `jniLibs` `.so`; neither rebuilds on a Rust change, so a new request kind can compile on every layer and answer as the old version. Run `mobile/scripts/ios-core.sh` and `mobile/scripts/android-core.sh` first, and compare mtimes. `:core:jvmTest` builds its own cdylib, so it cannot go stale.
- **Feature set drift.** Phone builds use `--features llama`; the JVM tests and the PR gate build without it, and the two JVM commands (`cargo build -p centraid-core-ffi`, the `spike-fixture` run) must use the same features or the library rebuilds.
- **Wrong JNA package.** JNA must come in as the `@aar` on Android (the jar has no `libjnidispatch.so` for Android), and a class reached by name needs an R8 keep rule in `androidApp/proguard-rules.pro` (`CentraidLibrary`'s method names are the C symbols).
- **`defer { centraid_free }` without a status check** frees whatever was in the pointers on a timeout; zero them first.
- **Putting a new feature in the open config** or a new symbol because it looks easier. The config is read once and logged; features go in protobuf.
- **Treating `TIMEOUT` as a failure** restarts a healthy core once a second.
- **Unsafe outside `marshal.rs`** escapes miri; keep it there.
- **Generated Swift/Kotlin types** are built, not committed (Swift) or built by Gradle (Wire). Never hand-write a message type.

## 5. How to check it

```sh
cargo test -p centraid-core-ffi                                   # contract.rs (one test per clause), symbols.rs, reopen, shelf_door
cargo test -p centraid-core-ffi --features debug-fault --test contract a_real_panic_inside_call_poisons_the_handle_through_the_abi
RUSTUP_TOOLCHAIN=nightly cargo miri test -p centraid-core-ffi --test marshal_miri   # when marshal.rs changed
nm -D --defined-only target/debug/libcentraid_core_ffi.so | grep ' T centraid_' | wc -l   # 5
cargo xtask rules                                                 # abi-five-symbols and the native rules
buf lint                                                          # and buf breaking, when installed
cd mobile && ./gradlew mobileJvm                                  # :core:jvmTest, the real ABI round trip over JNA (JDK 21)
cargo xtask gate --profile mobile-jvm                             # the same, plus the generated-artifact drift check
```

The Kotlin side is tested in `mobile/core/src/jvmTest`: `AbiContractSpec` and `AbiRoundTripSpec` (open, call, next_event, free, close against the real library on a vault the Rust fixture founded, plus buffer accounting), `ScreensRoundTripSpec`, per-feature `*RoundTripSpec`s, `ConfigurationJsonSpec`, `RequireDigestMatchesRustSpec`, and `FakeCentraidAbi` for lifecycle and poison cases. Add a spec beside the one for your request kind.

The Swift binding has no unit test of its own: there is no `swift test` and no SwiftPM package (`Sources/` imports UIKit). It is exercised only by the iOS app's test bundle on a simulator, so a Swift change to `Core.swift` is unverified on Linux. A Linux session also cannot prove the JNA path on a device or cinterop on iOS, or a panic injected by the real library on a phone. Say so; do not report those as passed.

## 6. Final checklist

- [ ] `CONTRACT.md` and `README.md` were read; a changed or new clause has a `Test:` line and a test in `tests/contract.rs`.
- [ ] Still exactly five exported symbols; the header regenerated and committed if a signature changed.
- [ ] New capability is a request kind: proto arm (never a reused number), `build.rs` entry, `Handle::call` dispatch, `request_kind` classification.
- [ ] All unsafe is in `marshal.rs`; every buffer is freed through `centraid_free` on every path in both bindings, including the timeout.
- [ ] `TIMEOUT` is handled as a normal answer; `PANICKED` poisons and is surfaced as a typed failure.
- [ ] Kotlin hops dispatcher then asserts off the UI thread; Swift uses the right lane.
- [ ] Both bindings return a typed refusal, never `null`; neither invents member-facing words.
- [ ] Artifact identity and open-config changes were made on both sides together.
- [ ] `cargo test -p centraid-core-ffi`, `cargo xtask rules` and `./gradlew mobileJvm` ran; the Swift binding, iOS cinterop and on-device runs are named as not run.
- [ ] The Rust core was rebuilt for each platform before any device check.
