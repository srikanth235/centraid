# The gateway

[`crates/gateway`](../../../crates/gateway/README.md) is the protocol's rules, the gateway a member runs and the client a phone links. Its README holds the routes, refusal codes, CLI and data directory. This page is what to keep true when you change it. What a member is told about it: [product.md](./product.md). The protocol revision is [`contracts/backup/spec.md`](../../../contracts/backup/spec.md) §4; the decisions below are the ones that outlive it.

## What it stores

- One data directory of plain files. Copying it copies the gateway.
- `state.db` (SQLite, `synchronous = FULL`, `application_id` `CGW4`, a `user_version` ladder) holds vault ids (public keys), writer epochs, BLAKE3 of tokens and pairing secrets, device labels, the signed head and one signed row per snapshot, the last signed claim, revoked-token tombstones, single-use nonces, and per object a name, digest of the ciphertext, size, `(pack_id, pack_pos)` (indexed by `object_by_pack`), and times.
- `packs/<vault>/<pack_id>.pack` holds append-only packfiles of sealed objects. Each `POST bundle` streams frames into a staged packfile in `staging/<pack_id>.pack` (truncating any `DIGEST_MISMATCH` frame back to its start and any trailing partial frame on EOF or mid-stream disconnect via a detached bundle worker), `fsync`s once, atomically renames into `packs/<vault>/`, and commits all completed valid frames in one `BEGIN IMMEDIATE … COMMIT` SQLite transaction. `GET` and `POST fetch` serve byte slices directly via positioned reads (`pread` / `seek_read`).
- Identity is `tls.key`, `tls.crt` and `gateway.id`, minted together at the first `serve`. The phone trusts the certificate by pin.
- Every phone-facing decision is in `src/rules`, with no clock, file, socket or randomness. `src/server` adapts it (SQLite, files, axum, sweeps) and decides nothing. `tests/pure_rules.rs` scans the rules for any reach.

## What it must never be able to do

- Read an object, recognise a known file, or hold a key. Object names are keyed hashes it cannot invert. The crate has no sealed-format code and depends on no `centraid-media`.
- Hold a plaintext, a plaintext hash or a key in a column or file. The `state.rs` records are the whole of what it knows, and a conformance canary plants all three and scans every byte it keeps.
- Overwrite an object. Storage is write-once by name and digest.
- Delete the head's manifest, take a write from a token below the vault's writer epoch, or accept a head, delete or undo the vault key did not sign. It cannot forge one either: it holds no key.
- Take a delete computed under any head but its current one. The delete's signed preimage carries the head's root name after `generation`, and the gateway refuses (`HEAD_CONFLICT`, carrying the head it has) when that is not its head, so a gateway whose data directory was rolled back never applies a keep set computed from a head it does not have.
- Remove anything the vault key deleted before seven days of the gateway's clock have passed (a gap of more than three sweep intervals is added to every hold, so unwatched time is never counted), or at all while the operator has frozen the vault.
- Leave an older token alive after a takeover.
- Tell a stranger, another vault's token and an unknown vault apart. All answer `UNAUTHORIZED`.
- Say "backed up". It returns acknowledgements and the client passes them on.

## Decisions in force

Common encoding of every signed record (`rules::signing`, the phone calls the same builders): Ed25519 by the vault identity key, verified strictly; the preimage is a list of fields, each `u32be(length) ‖ bytes`, integers `u64be`, names and hashes 32 raw bytes, an absent optional name a zero-length field.

- **One key, one context string per record.** The vault identity key (the vault id) signs every head, delete, undo, check, claim and pairing. The context is the first preimage field (`centraid-gateway-claim-v1` for a claim and a read grant, `-head-v1`, `-delete-v1`, `-undo-v1`, `-check-v1`, `-pair-v1`), so a signature over one is never valid as another; the second and third fields are `gateway_id` (16 bytes) and `vault_id` (32), so a record for one gateway or vault is void at another. No second key is derived: the seed holds both. Vectors: `contracts/crypto/gateway-signing-vectors.json`.
- **A head binds** `epoch, generation, writes, taken_at_ms, manifest_name, prev`. The gateway stores and serves the signed record unchanged; `HeadView` carries no unsigned writer epoch, so the phone takes its epoch as the greater of the verified head's and the verified claim's and verifies signature, gateway id and vault id before it believes any field (`ClientError::Unverified`). Keys run head, then snapshot, then object: a manifest a snapshot row names cannot be tombstoned except through a held delete, and a head's cannot at all (`HEAD_IN_USE`).
- **Ordering.** One counter, `generation`, is shared by head, delete and undo. A record is accepted only when its signature verifies, the token's writer epoch is the vault's (else `MOVED`), `generation` is above the standing one by at most `MAX_GENERATION_JUMP` (256), a head's `writes` does not fall, and `prev` is the standing head. Else `OUT_OF_ORDER` (409, carrying the standing `epoch`, `generation`, `writes`): the phone re-reads, re-signs at `max(local, standing) + 1` and tries once more, and a second one stops that gateway's pass. A retry of the head that already stands answers the stored record. A claim resets the counters. `taken_at_ms` more than `MAX_CLOCK_AHEAD_MS` ahead of the gateway's clock is `CLOCK_AHEAD`; the phone re-signs with `min(manifest, gateway time)`.
- **Moved.** A `MOVED` carries the vault's last signed claim. The phone believes it only if the claim verifies by the vault key against this gateway's id and nonce and its epoch is strictly above the one the phone holds there; it then marks that gateway's row `moved` and stops that gateway's pass only. There is no vault-wide freeze: another gateway answers for its own writer epoch. A `MOVED` without a verifying, higher claim is "refused for another reason".
- **Takeover.** A claim at `writer_epoch + 1`, in one transaction: deletes every token of the vault (reads included), writes a `revoked_token` tombstone (BLAKE3, vault, epoch, time) for each, clears every held delete, stores the claim, resets the counters, sets the epoch, mints the claimant's token. A revoked token answers `MOVED` with the latest claim for `REVOKED_TOKEN_KEEP_MS` (365 days) and at most `MAX_REVOKED_PER_VAULT` (64) tombstones per vault (read-grant tombstones trimmed first, then the oldest writers), then `UNAUTHORIZED` ("pair again"). A token revoked on purpose leaves no tombstone. A takeover is never delayed.
- **Nonce.** `POST /v1/nonce` writes nothing: 40 bytes, 16 random, `issued_at_ms` and a 16-byte BLAKE3 MAC keyed by the gateway-local `nonce.key`; good for `NONCE_TTL_MS` (5 min); signed into every claim, read grant and pairing. A request is judged nonce, credential, signature, and **only a request whose signature verifies records the nonce as spent**, so a stranger cannot fill the table. An unknown, expired or spent nonce is `UNAUTHORIZED` (no oracle). At `MAX_LIVE_NONCES` (4096) a pair answers `BUSY` with `retry_after_ms`.
- **Pairing by secret proves the vault key.** The signature covers `blake3(secret) ‖ nonce`; checked after the nonce and the secret, and every failure is `UNAUTHORIZED`. It stops a stranger squatting the member's vault address; it does not stop a photographer who pairs their own vault with the one-time secret first, which spends the member's code (the member prints a new one; the console prints the safety number of every pairing, so it is visible). Used secrets are pruned after 7 days; at most `MAX_LIVE_SECRETS` (64) unused ones exist.
- **Deletes are held, signed and bound to a head.** The delete preimage is `… ‖ epoch ‖ generation ‖ head_root ‖ names_digest` (`names_digest` over the sorted, de-duplicated names). An accepted delete sets `held_at_ms` and `purge_after_ms = now + GRACE_MS` (7 days) on each object and on any snapshot row whose manifest is among them; nothing is removed before the purge sweep passes it. A held name is not held for `exists` (so the phone sends it), the live listing leaves it out, and `GET` and `fetch` still serve it. A bundle frame over a held name with the recorded digest lifts the hold (`held`); any other digest is `taken` carrying the recorded digest and the name's state (`live`, `held`, `damaged`), never an acknowledgement. A signed delete of a damaged name frees it at once, in `freed`. Undo (`POST undo`, signed, names or all) and the operator's `undo` clear holds; neither moves the head or reverses a takeover. The seven days are measured by the gateway's clock and count only watched time (a gap of more than `PURGE_GAP_INTERVALS` (3) sweep intervals is added to every hold). `FROZEN` (423, `since_ms`) is the answer to every state-changing route on a frozen vault; reads, `nonce` and read grants still answer. The phone records `frozen` for that gateway and stops only its pass.
- **Operator verbs** (`centraid-gateway vault <id8> <verb> --data-dir DIR`, local, unsigned, through the same `Engine`): `freeze`; `unfreeze` (adds the frozen time to every hold); `undo`; `purge-now --yes` (an unfrozen vault); `delete-vault --yes` (a frozen vault; removes every row and file in `LIST_LIMIT` pages, logging counts).
- **Protocol 1 and the data folder.** `state.db` is a ladder (`sql/ladder/NNN_*.sql`, `application_id` `CGW4`, one transaction per rung): no file founds rung 1; another `application_id`, or tables present with id 0, is refused; a newer `user_version` is refused with "Update the gateway; nothing was changed."; an older one gets its missing rungs. A refused folder is left byte-identical and `serve` and `pairings` print "This data folder was made by an earlier version of the gateway, and this version cannot open it. Nothing was changed. Move the folder aside and start again; every phone will need to pair again." and exit 2. A gateway that answers `/v1/info` with `protocol < REQUIRED_PROTOCOL` or `NOT_FOUND` is `GatewayTooOld` and the member reads "This gateway runs an older version. Update it, then pair again." There is no fallback protocol.
- **Housekeeping.** Every listing is keyset-paged by its table's key (`LIST_LIMIT` 1000), never `OFFSET` (`tests/plans.rs` asserts an index walk). Each bundle streams into a staged packfile, `fsync`s once, renames into `packs/<vault>/`, and commits all completed frames in one transaction; a crash between rename and commit leaves an unreferenced `.pack` file, never a row without bytes. `staging/` is swept on startup (`serve`), and the hourly sweep prunes secrets and nonces, runs `compact_packs_once` (compacting sparse packfiles with `>= 50%` dead bytes and coalescing `< 16 MiB` packs up to `256 MiB` with an atomic CAS index remap of `(pack_id, pack_pos)`), and runs `orphans_once` to remove unreferenced `.pack` and `staging/` files older than `ORPHAN_MIN_AGE_MS`. Quarterly `scrub_once` walks `object_by_pack` to verify packfiles sequentially without opening a file per object. A token's kind is tied to its epoch by a table check. `server::harness` sits behind the `test-harness` feature, and `cargo xtask rules` fails if the release gateway links it.

## What its operator sees

- Only a terminal. `serve` prints the gateway id, name (`--name <label>`, defaulting to the clean hostname and carried in `/v1/info` and `PairPayload.label`), the pin, the bound address, any repeatable `--announce <host:port>` addresses (ranked alongside discovered LAN/Tailscale addresses ahead of `172.16.0.0/12` Docker bridges), and a pairing QR, and when a phone pairs, its safety number. `--name` and repeatable `--announce` are also accepted on `pair` and `install`. A data folder an earlier gateway made is refused with a sentence and exit code 2.
- `pairings` lists each vault by the first 8 hex of its id: epoch, safety number, head, tokens by the first 12 hex of their BLAKE3, and counts of waiting, spent and expired secrets. The operator can revoke a token, run `scrub`, or `install` a unit file, and has the last word over a vault: `vault <id8> freeze | unfreeze | undo | purge-now --yes | delete-vault --yes`.
- Holds count only watched time: after a gap of more than three sweep intervals every hold shifts by the whole gap before the purge, so a sleeping gateway or a jumped clock never ends one early. The nonce route writes nothing (a MAC-keyed stateless nonce; the spent table is written only after a valid signature). A bundle frame over a held or damaged name is accepted only with the recorded digest (`taken` carries it and the name's state; a held name with the right digest is answered `held` and its hold lifted); only a signed delete frees a damaged name. Objects arrive only through `POST bundle`; a method no route takes (an upload straight to an object's path) is `NOT_FOUND`. Handlers do their rules and file work on the blocking pool, never on a tokio worker.
- The purge and scrub sweeps log counts, never names. A stolen copy yields ciphertext, names, digests, sizes, times, labels, public keys and epochs. It also holds the gateway's TLS key.
- **Check this name** (decision 34): `POST /v1/v/{vault}/check` is the phone's way to ask the gateway to hash one stored object against its recorded digest between scrubs (the scrub is quarterly, 90 days from the last finish). Signed by the vault key under its own context and ordered by the delete counter, so a token alone, a replay or a delete's signature is refused; a frozen vault refuses it; 64 names per vault per hour, then `BUSY`. A mismatch marks the name damaged (a signed delete then frees it at once); a match changes nothing.

## Changing the protocol

0. A change to what the vault key signs is a change to `rules::signing` and to `contracts/crypto/gateway-signing-vectors.json` (`CENTRAID_UPDATE_FIXTURES=1 cargo test -p centraid-gateway --test signing_vectors`, once, then without the variable), and the phone calls the same builders. A delete signs `epoch`, `generation`, the head's root name (`head_root`, empty for no head) and `names_digest`; its `DeleteRequest` carries `head_root` too.
1. Put the decision in `rules::engine`. Add request and answer shapes to `rules::wire` and every shared number to `rules::limits`, which both ends import. A new refusal is a closed code in `rules::code` with exactly one status and its companions.
2. Add the adapter side: `src/server/http.rs` renders and decides nothing. SQL lives in `src/server/sql/*.sql`; every listing is a seek by key (add it to `sql::LISTINGS` so `tests/plans.rs` sees it); and the schema is a ladder (`sql/ladder/NNN_*.sql`, one transaction per rung, `user_version` counts them); a change is a new rung once released.
3. Add the client method in `src/client/mod.rs`, and decide whether it is idempotent: only an idempotent call goes through `retrying` (at most `MAX_RETRIES` repeats after a dropped connection or a `BUSY`). The client dials every address in parallel and speaks HTTP/2 or HTTP/1.1 by ALPN; a method must work over both (`tests/transport.rs`).
4. Add a named case to `rules::conformance::CASES`, and a row in `conformance::NAMED` with a test of that name in both conformance files if `tests.md` names one. It runs over the in-memory rules and over the wire, and the two must agree. Add a case in the same change as any new rule.
5. Mirror it in the phone's `Store` trait in the vault's backup store. `centraid-vault` depends on `centraid-gateway` with `default-features = false` (pure rules only, zero I/O), so limits, refusal codes, wire enums and `MemoryStore` (`Gateway<MemoryState>`) all come straight from `centraid_gateway::rules` rather than being restated.
6. Check how the phone hears it: the client's `ClientError::reach()` and `Reach` give the typed outcome (`ok`, `unreachable`, `untrusted`, `too_old`, `pair_again`, `moved`, `frozen`, `busy`); a new refusal code must land in one of them or read as `ok` (the gateway answered). An unknown code reads as "refused for another reason".
7. Update the README tables in the same change.

## Tests

`conformance`, `conformance_wire`, `head_state`, `check_name`, `older_gateway`, `gateway_cli`, `tls`, `transport`, `frames`, `delete_rollback`, `pair_from_payload`, `store_client`, `revoke`, `lost_bytes`, `stalled`, `data_dir`, `operator`, `plans`, `bundle_commit`, `pack_compaction` and `signing_vectors` live in `crates/gateway/tests`. `server::harness::spawn` (behind the `test-harness` feature, never in the release gateway) starts a real gateway on `127.0.0.1:0` for tests in any crate, and can cut or stall its connection; `spawn_http1_only` offers `http/1.1` alone; `harness::put` sends one frame; `knobs().on_committed` says when a frame is committed. Assert on counts, never on seconds.
